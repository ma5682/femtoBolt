# 保存性能与单进程持续运行检查

本说明用于研发人员检查固定方案的保存耗时，以及同一 Python 进程反复运行后的功能与内存变化。使用当前工作区 `.venv` 和已有输入，每次运行写入新的 `outputs` 子目录。

## 内存归因与完整保存动作

持续工具支持 `--observation-mode minimal|weak|allocations`。minimal保留进程指标但不遍历模型；weak为默认，增加弱引用生命周期观察；allocations增加Python和NumPy可用分配域、追踪器元数据和有限分配差异。各短跑内部保持同一进程、相同阶段和自然GC。分配模式不是耗时对照，触及原预算时保留失败，不能提高预算后宣告正常速度。

`cycles.json` 的 `memory_observation` 包含私有/USS指标、缓存规模和系统计数；字段不可用时保留空值或错误。`weak_references.unsupported_types` 明确不能弱引用的类型。分配模式的 `survivor_details` 仅保留类型和有限分配位置，不保存引用对象。追踪快照本身也有内存开销；RSS减去已追踪字节不能直接视为Open3D占用。

实际Qt动作使用 `tools/profile_qt_save.py --project <固定工程> --output <新outputs目录>`。它以离屏参考视图调用真实保存入口和完成回调，包含快照、两种输出及登记，随后完整独立回读。它不等于持续桌面渲染性能，也不能用单独原生计时替代完整动作时间。

2026-11-11 起，`manifest.json` 另外记录 `complete_seconds`（调用保存到完成回调）和 `route_release_seconds`（调用保存到页面收到“三维路线已保存”通知）。后者在状态信号处理时记录，早于随后放开查看控件的 `refresh()`，不包含该次刷新和屏幕渲染；此时可编辑工程仍在写入，不能当作整次保存的耗时。改动前的源码归档不产生该字段。

跨多个模块的前后比较使用 `tools/compare_save_backends.py --before <生产源码ZIP> --after <生产源码ZIP> --v1 <固定基础工程> --exact <固定完整精确工程> --output <新outputs目录>`。ZIP内应保留完整 `femto/` 路径。工具串行运行两种入口，各输入执行AB、BA、AB三组，保存每轮完整资产、回读和来源证明。`*_backend.json` 记录实际加载的归档模块摘要；子运行manifest另外记录磁盘源码摘要，二者不能混用。

计时工具统一记录目标读取/重建、路线与覆盖核验、序列化、NPZ压缩和文件发布，嵌套阶段不能直接相加。`instrumentation.json` 在计时外采集系统CPU累计时间、可用内存及有限其他进程CPU/RSS，不读取命令行。前后累计计数差值用于识别同机负载背景，不能据此精确扣除负载影响。正式比较期间保持全部工具与生产源码冻结，不并行跑其他测量或回归。

当全流程分配追踪触及预算，可使用 `tools/probe_memory_components.py` 对clone、mesh、target或reconstruction分别诊断。reconstruction必须另传`--reconstruction-report`，按报告原输入和参数重建并核对网格摘要与帧数，同时弱引用观察真实TSDF卷。target组件明确只读取实际资产并做非重建校验；输入本身先正常完整打开。各组件保留固定基础模型，观察12轮临时对象自然退出，不是保存性能或全流程稳定性证据。无法弱引用的类型单独报告，不能把未观察到对象当作已释放。

## 完成后独立审计

等待持续测试进程正常结束，再执行 `tools/audit_workstation_soak.py`，将完整运行目录作为唯一参数。例如：

```powershell
.venv\Scripts\python.exe -X utf8 tools\audit_workstation_soak.py outputs\save_stability_20261020\soak_hour
```

工具重新读取每轮便携目标与路线、原生证据、重建网格，以及当前固定输入、数据集、生产代码和测量工具摘要，结果写入运行目录的 `audit.json`。未完成一小时、轮次不足、阶段缺失或文件不一致均不能通过。审计通过后仍需单独分析 `memory.json` 的同阶段趋势与跨轮存活对象；它不直接给出无泄漏结论。

这里记录检查方法，不预先宣告任何尚未完成的性能或一小时运行结果。两项工具都属于离线软件回放，不是 GUI 操作验收，也不覆盖实时相机、机械臂、底座、治疗头或临床执行。

## 准备固定输入

需要一份包含已保存路线、目标台账及相关证据的完整 `.region.zip`。持续运行如需包含重建，还需要对应的 `reconstruction_report.json`、报告指定的源数据，以及报告同目录下的参考网格。

示例使用本工作区已有输入：

- 方案：`outputs/grouped_coverage_probe_20261016/recalculated.region.zip`。
- 重建报告：`outputs/complete_demo_20261014_093026/reconstruction/reconstruction_report.json`。

从项目根目录执行命令。测量期间保持 `femto/` 和参与测量的工具源码不变，关闭其他重负载任务。输出目录必须不存在；工具不会覆盖或续跑已有目录。

## 测量固定方案的保存

使用 [profile_saved_plan.py](../../tools/profile_saved_plan.py) 打开同一份已保存方案，依次执行原生保存、便携保存，以及两种结果的完整独立回读。它不先重新生成基础规划，因此适合隔离“保存已有方案”的成本。

运行三轮常规计时：

```powershell
$runStamp = Get-Date -Format 'yyyyMMdd_HHmmss'
.venv\Scripts\python.exe -X utf8 tools\profile_saved_plan.py --project outputs\grouped_coverage_probe_20261016\recalculated.region.zip --output "outputs\fixed_plan_save_$runStamp" --repetitions 3 --profile none
```

需要分析函数耗时分布时，用新的输出目录执行：

```powershell
$runStamp = Get-Date -Format 'yyyyMMdd_HHmmss'
.venv\Scripts\python.exe -X utf8 tools\profile_saved_plan.py --project outputs\grouped_coverage_probe_20261016\recalculated.region.zip --output "outputs\fixed_plan_save_profile_$runStamp" --repetitions 1 --profile saves
```

`--profile` 支持 `none`、`saves`、`all`，默认 `none`。`saves` 只为两个保存阶段开启 `cProfile`，`all` 覆盖全部五个阶段。`cProfile` 会增加开销，可能触发正常操作的时间预算；此时保留失败结果，不能把它当作常规计时或通过调大预算来声称提速。

| 文件 | 检查内容 |
| --- | --- |
| `manifest.json` | 固定方案摘要、生产源码摘要、工具摘要、目标与路线算法、完成状态及最终检查 |
| `stages.json` | 五个阶段的每轮时间、CPU 时间、RSS 采样及采样错误 |
| `summary.json` | 已成功执行阶段的次数、耗时中位数、采样内存峰值与观察到的 GC 时间 |
| `equivalence.json` | 原生和便携回读的路线语义、便携文件内计划及全部目标/覆盖证据比较 |
| `instrumentation.json` | 各阶段是否启用性能剖析，以及自然 GC 的次数和耗时 |
| `run_*_*.prof`、`run_*_*.txt` | 开启 `cProfile` 后的函数耗时数据及前 100 项摘要 |
| `diagnostics/`、`run_*/` | 生产诊断和每轮保存、展开与回读资产 |

成功需同时满足 `manifest.json` 中的 `status=passed`、`all_checks_passed=true`、`measurement_checks_passed=true`、`source_unchanged=true` 和 `code_unchanged=true`。每轮必须完整记录 `source_open`、`native_save`、`portable_save`、`native_readback`、`portable_readback`，且 `sampling_errors` 为空。已有旧报告可能没有后加的测量门槛字段；不要回写旧报告补造通过结论，应检查其原始阶段记录或以新目录重新测量。

### 保持比较口径一致

比较两次运行时，先确认输入文件摘要、重复次数、`--profile` 模式、目标/路线算法和目标规模一致，再比较同名阶段。每次都保留完整回读和证据检查。代码可以在两次运行之间改变，但单次运行期间必须保持不变。

输出目录和展开路径每轮会变化，不能直接以整个 ZIP 的字节摘要判断语义不同。路线比较复用生产代码的 `semantic_payload`：保留几何摘要、区域标识及区域签名，忽略可迁移的其他来源字段、显示状态及 `data_layers` 声明。另行比较实际保存的目标/覆盖 JSON 和数组的类型、形状与字节，以及便携文件内计划是否等于传入计划。该口径不能替代产品已有的完整回读校验。

这项探针的固定已保存路线，可能包含后续补充规划和覆盖证据；[全流程测量](工作台固定数据性能测量.md)中的 `planning_generate` 会重新生成基础路线。不能把不同算法、不同证据规模的两个保存时间直接当作优化前后结果。

RSS 是整个进程每 50 毫秒观察到的内存，并包含前面阶段保留的对象。固定方案探针还可能在下一轮开始时保留上一轮的回读局部变量，因此其 RSS 不等于单次保存的独立分配量，也不适合替代下面的轮末释放观察。工具不强制清理系统文件缓存；需要归因时应保持相同观察方式并交替运行对照版本。

## 运行同一进程的持续检查

使用 [soak_workstation.py](../../tools/soak_workstation.py) 在一个进程中反复执行以下流程：

1. 按报告记录的参数和位姿离线重建，并核对固定参考网格；未提供重建报告时跳过该阶段。
2. 完整打开固定历史方案，核对原路线和目标台账。
3. 生成基础规划，原生保存、便携保存并重新打开便携结果。
4. 核对生成路线、保存路线、目标数组与摘要，以及各轮结果的一致性。
5. 在隔离 SQLite 历史库中检查版本搜索、隐藏及恢复。
6. 业务局部对象离开作用域后等待一秒，记录轮末 RSS、自然 GC 和弱引用存活情况。

包含重建的一小时检查命令：

```powershell
$runStamp = Get-Date -Format 'yyyyMMdd_HHmmss'
.venv\Scripts\python.exe -X utf8 tools\soak_workstation.py --project outputs\grouped_coverage_probe_20261016\recalculated.region.zip --reconstruction-report outputs\complete_demo_20261014_093026\reconstruction\reconstruction_report.json --output "outputs\workstation_soak_$runStamp" --duration-seconds 3600 --warmup-cycles 3
```

脚本默认 `--duration-seconds 3600`、`--warmup-cycles 3`，未设置 `--max-cycles`。正常结束同时要求达到请求时长和 `max(8, 暖机轮数+5)` 轮；在完整轮次之间检查条件，所以运行可能超过一小时。

只检查脚本流程时，可以使用新目录和以下短跑参数：

```powershell
$runStamp = Get-Date -Format 'yyyyMMdd_HHmmss'
.venv\Scripts\python.exe -X utf8 tools\soak_workstation.py --project outputs\grouped_coverage_probe_20261016\recalculated.region.zip --output "outputs\workstation_soak_smoke_$runStamp" --duration-seconds 0 --max-cycles 2
```

此短跑仍执行真实规划和保存，不能视为轻量单元测试。它省略了重建，也不能取得一小时资格。`--max-cycles` 是停止上限；即使返回码为零，也必须查看完整判定字段。

### 检查一小时资格

读取 `manifest.json`，一小时运行证据完整要求：

- `status=completed`，且 `stop_reason=requested_duration_and_cycles_completed`。
- `active_cycle_seconds >= 3600`、`completed_cycles >= 8`。业务循环时长不包含开始和结束的输入摘要核对；`elapsed_seconds` 是包含这些工作的会话总耗时。
- `functional_checks_passed=true`、`inputs_and_code_unchanged=true`、`sustained_hour_qualified=true`。
- 每轮严格包含声明的全部阶段，阶段执行和 RSS 采样均成功。
- `memory.json` 中 `post_warmup_cycles >= 5`。默认剔除前三轮，至少留下五轮供趋势观察。

`sustained_hour_qualified` 表示一小时检查的时长、轮次和证据完整性达标。工具未用某个 RSS 斜率或弱引用数量作为“无泄漏”阈值，不能仅凭此字段宣称内存稳定或没有泄漏。

| 文件或目录 | 用途 |
| --- | --- |
| `manifest.json` | 进程、环境、停止原因、时长、轮数及资格判定 |
| `inputs.json`、`inputs_after.json` | 输入、源数据、参考资产、生产源码与参与工具的前后摘要 |
| `stages.json` | 每阶段耗时、同进程 RSS、采样状态、GC 增量与循环时间位置 |
| `cycles.json` | 每个完整轮次的功能检查、资产大小、轮末内存和弱引用 |
| `memory.json` | 剔除暖机后，轮末及相同阶段 RSS 的趋势 |
| `checkpoint.json`、`cycle_*/state.json` | 最近阶段及该轮的运行、完成或失败状态 |
| `cycle_*/` | 每轮重建、展开、保存及回读的全部资产 |
| `isolated/outputs/` | 本次运行隔离的方案登记和 SQLite 历史元数据 |

### 判断内存变化

先比较暖机后的相同阶段，再比较 `cleanup` 的轮末 RSS。各阶段持有的数据不同，不能把“打开后”和“对象离开作用域后”的内存直接当作增长趋势。

`memory.json` 同时提供每小时斜率、首末窗口均值差，以及斜率的描述性误差带。相邻轮次受缓存和分配器影响，样本并非相互独立；误差带不是独立样本假设下的 95% 置信区间。

弱引用观察器只保存引用和计数，不保留模型或数组本身。重点看 `older_cycles` 和 `oldest_age` 是否随轮次增长，再联系相同阶段 RSS 判断。它只覆盖已观察的模型、数组与分区实例，不能统计所有 Python 对象或原生库内部内存；数组视图也可能共享底层存储，`array_bytes` 不是整个进程的准确占用量。

脚本不会调用强制 GC，不关闭自然 GC，也不在轮次之间重启进程。自然 GC 未启用或运行期间被关闭会使检查失败。一次完整运行、有限的 RSS 波动或少量弱引用存活，都不足以单独证明长期不存在泄漏。

### 处理停止或失败

脚本保留每一轮资产，不删除旧轮次来降低磁盘占用。每轮开始前，磁盘保护要求剩余空间至少为 **4 GiB 加下一轮预计资产大小的 1.25 倍**。首次以 256 MiB 为资产估计下限，随后取历史轮次的最大资产大小与该下限中的较大值。保护发生在轮次之间，不是磁盘配额或实时空间保证。

空间不足时以 `stop_reason=disk_guard` 停止，返回非零，一小时资格为假。已完成轮次可以保留有效功能结果，但不能把这次提前停止当作完整持续运行通过。

普通异常、采样失败或输入/代码变化会使检查失败，并保留已有资产和错误。强制终止进程或断电可能只留下 `running` 检查点；这表示运行未完成，不表示已恢复或通过。检查错误和空间后，使用新输出目录重新运行，不续写旧报告。

相关失败路径逻辑测试位于 [test_soak_workstation.py](../../tests/test_soak_workstation.py)；保存测量证据门槛测试位于 [test_profile_saved_plan.py](../../tests/test_profile_saved_plan.py)。这些逻辑测试不执行真实重建或规划，不能代替上述实际运行。
