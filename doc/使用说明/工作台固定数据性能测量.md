# 测量固定数据下的工作台性能

本工具用于研发对照，不连接相机，不发布新的采集历史。它在新的输出目录重建、规划、保存并回读，保留已有输入。

## 输入与环境

使用当前工作区 `.venv`，需要已安装的产品依赖及现有性能工具使用的 `psutil`。准备：

- 一份带已保存路线的完整 `.region.zip`。
- 与要测的采集数据对应的 `reconstruction_report.json`，其源数据目录仍存在。
- 当前工作区 `outputs` 下尚不存在的输出目录。

建议使用同一次采集生成的方案和重建报告。不要在测量过程中编辑 `femto/` 源码，也不要同时运行其他大工程或训练。

## 运行

从项目根目录执行。本例使用本工作区已有固定数据；另一次运行需换新的输出目录。

```powershell
.venv\Scripts\python.exe -X utf8 tools\benchmark_workstation.py --project outputs\grouped_coverage_probe_20261016\recalculated.region.zip --reconstruction-report outputs\complete_demo_20261014_093026\reconstruction\reconstruction_report.json --output outputs\workstation_baseline_20261020 --repetitions 3
```

工具拒绝覆盖已存在的输出目录。中途失败保留已完成阶段及错误，不把失败记为零耗时。

全部测量结束后执行审计，检查阶段数量、保存回读，以及三轮重建网格、路线点序列和目标数组是否相同：

```powershell
.venv\Scripts\python.exe -X utf8 tools\audit_workstation_benchmark.py outputs\workstation_baseline_20261020
```

优化完成后以相同命令和固定输入写入另一个新目录，例如 `outputs/workstation_optimized_20261020`。比较两次运行时执行：

```powershell
.venv\Scripts\python.exe -X utf8 tools\audit_workstation_benchmark.py outputs\workstation_optimized_20261020 --baseline outputs\workstation_baseline_20261020
```

结果写入优化目录的 `comparison.json`。审计重新读取每轮输出，比较原输入记录摘要、重建网格字节、路线顺序、目标数组形状/类型/字节及摘要；两次运行都必须完整。代码允许在两次运行之间改变，但单次测量期间必须不变。只有等价检查通过后，才比较同名阶段的时间。该审计本身不宣布提速。

## 读取结果

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 输入及生产源码摘要、环境、完成状态、输入/源码是否保持 |
| `stages.json` | 每轮每阶段耗时、进程 CPU 时间和内存峰值 |
| `summary.json` | 各阶段已通过次数、中位/最大耗时、采样内存峰值 |
| `equivalence.json` | 保存后路线回读是否一致，以及该轮输出 |
| `audit.json` | 阶段完整性与重复输出一致性审计 |
| `diagnostics/` | 生产诊断已有的细分阶段计时 |
| `run_*/` | 每轮独立的重建、原生/便携保存及回读工作目录 |

成功要求：`status=passed`、输入与源码保持不变、所有轮次的保存回读一致。一个阶段有成功结果不表示整轮完成；检查重复次数是否达到命令要求。

## 指标含义

- `reconstruct` 是对已有位姿数据的离线重建，包括该函数的文件读写。它不包含实时相机采集、在线跟踪、完整最终发布或实物精度验收。
- `history_open` 完整打开原方案，含保存证据回放；`saved_history_open` 打开本轮新生成的方案，两者数据与证据规模可能不同，不能直接据此宣称优化提速。
- `planning_generate` 按当前产品算法和已保存参数重新生成基础路线；不自动重做所有后续补充规划或覆盖阶段。
- `native_save` 与 `portable_save` 分别计时；不等于 UI 单次保存动作的端到端耗时。
- 内存是单进程 RSS 每50毫秒采样峰值，包含先前步骤保留的对象。它不等于单函数分配量、整机峰值或瞬时绝对峰值。
- 重复运行保留系统文件缓存，不是强制冷启动。首轮与后续轮次均保留。
- 输入文件摘要、模块导入和额外结果检查不计入各阶段计时。诊断与内存观察本身仍有少量开销。

分析时先看总阶段，再看诊断中的 `self_seconds`。不要把嵌套阶段的包含时间相加，否则会重复计算。
