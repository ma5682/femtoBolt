# 区域方案库使用说明

本功能组织研发规划历史，不验证临床精度或机械臂可执行性。入口仍是当前模型的“历史记录”，规划工作台继续复用已有窗口。

1. 打开历史后，按“来源区域 → 方案结果版本 → 工程或导出记录”展开。区域身份同时使用区域ID、来源几何指纹和原点来源，不按名称合并；证据不足的旧记录单独保留。搜索名称、筛选类型；工程可显示参考RGB缩略图，路线显示已有PNG，无图片显示“无缩略图”。缩略图仅供展示。
2. 单选叶子记录查看来源详情，包括原点、网格指纹、项目/修订ID、算法/参数/结果绑定、文件清单及位置。可多选叶子添加备注；备注属于库记录，不修改工程文件，不是保存方案。新版工程修订不会继承旧修订备注。
3. 双击区域或工程进入原有规划入口。工程ZIP用于继续编辑；路径分享包ZIP用于展示，按钮按所选类型标注。文件指纹一致不代表路径有效：有绑定的方案仍提示“待工作台重算”；旧版/无绑定显示待验证。状态区分仅点标记、无模型导出、文件丢失和损坏；缺失/损坏不能作为正常工程打开。
4. 移动前至少刷新一次，让库记录内容指纹；新版登记工程自动记录ZIP SHA256。移动后选缺失记录，点“重新定位文件”，选择原工程ZIP或原path.json/annotations.json。必须完全匹配原清单/ZIP内容；工程内部及导出清单列出的资产继续核验。同名不同内容拒绝。导出目录应完整移动；旧清单无资产指纹时只能证明清单本身，不能证明未登记模型字节。
5. Ctrl/Shift多选叶子，再“移除所选索引（不删文件）”。勾选“显示已移除索引”后选中并“恢复所选索引”即可撤销。分组行不代表批量选择所有子项。本版没有实际文件删除按钮，不改动原RGB/Depth、标定、位姿、网格、工程或导出资产，因此不会沿依赖关系误删其他方案。若需要磁盘清理，应另行审计共享依赖，本批没有实现这项破坏性操作。
6. “重建/修复索引”从原annotations、region_paths目录与工程登记记录重建。损坏的region_library.json移到唯一.corrupt.*.bak，保留原字节；正常索引的备注、隐藏、重定位继续保留。索引完全丢失时，原导出目录仍可被发现；外部工程使用“扫描目录找工程”或“导入已有区域工程”重新登记。库备注、隐藏设置、已移动文件位置不能凭原资产凭空恢复，应备份索引。
7. 读取和核验在后台显示阶段与耗时，120秒预算，支持取消；关闭窗口抛弃迟到的UI结果。索引写入采用临时文件刷新后原子替换，失败保留旧索引。一次只运行一个库任务；写入发布开始后不能撤销发布，可使用恢复索引。扫描目录最多20000项、工程解压核验最多1GiB，非工程/损坏ZIP显示跳过数量与首个原因。扫描按文件登记；途中失败/取消可能保留之前已完整登记的工程，不会产生半个工程文件，也不报告全目录成功。

限制：不会扫描整台磁盘寻找文件；扫描目录仅发现工程ZIP，不自动解包分享ZIP。外部修改尚未刷新的文件状态可能过时，打开规划时仍执行完整来源/路径校验。保存覆盖同一工程文件不会自动保留其旧文件内容，需要用另存为保留独立版本。无可靠原指纹的缺失旧文件不能按名称重新认领。工程/导出结果可关联不等于报告物理精度已验证。

验证命令（项目目录）：

```powershell
.venv\Scripts\python.exe -m unittest tests.test_region_library tests.test_export_history tests.test_local_history tests.test_region_project -v
$env:PYTHONPATH='.'
.venv\Scripts\python.exe outputs/region_library_checks/replay.py
```

回放使用现有书本实采产生的方案与导出副本，不改变原文件；它验证历史组织和内容关联，不是重新测量实物精度。证据在outputs/region_library_checks。
