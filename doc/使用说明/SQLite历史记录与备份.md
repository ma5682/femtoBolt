# SQLite 历史记录与备份

需要同时备份图像、采集、模型和方案资产时，使用[完整数据备份与恢复](完整数据备份与恢复.md)。本文后续命令仍仅针对元数据，不替代完整数据备份。

面向当前单机工作台使用者与维护者。历史列表使用 SQLite 管理检索和采集记录的移除状态；模型、采集和方案文件仍按原格式保存，打开时继续核验原文件。

## 查找和恢复记录

1. 打开工作台的“历史记录”。首次刷新建立 `outputs/history_metadata/history.sqlite3`。
2. 使用搜索框查找名称、时间、状态。区域与轨迹还支持完整项目 ID、版本 ID 和父版本 ID 搜索。
3. 在“区域与轨迹”选择“全部已保存方案版本”，查看已登记版本。展开“来源详情”可以查看完整版本与上一版本编号。
4. 在“采集记录”中选择“从列表移除”，仅隐藏该记录。当前窗口可“撤销移除”。
5. 关闭并重新打开窗口后，勾选“已移除记录”，选中记录并点击“恢复记录”。取消勾选后可在正常列表中看到它。

两个标签分别保留搜索词。在“区域与轨迹”搜索或刷新，不会改变其关联的采集记录；后台读取期间切换采集时，迟到的旧结果不会替换当前记录。

“已移除记录”只显示已隐藏且原目录仍能扫描到的采集记录。目录被外部删除或移动后，恢复列表项不会重建原始文件。

## 旧索引迁移

数据库首次写入时读取 `outputs/local_history_deleted.json`，在同一事务中导入采集隐藏状态并登记 schema v1。旧 JSON 原样保留；后续隐藏和恢复只更新 SQLite。刷新不会重新导入旧 JSON，也不会把已经恢复的记录再次隐藏。

扫描失败、取消、数据库忙或写入失败时，历史窗口保留原列表并显示原因。数据库更新使用事务，未提交的更新不会替换旧集合。当前界面仍一次展示扫描集合，尚无滚动分页；数据库查询接口支持分页。

不要通过删除数据库来刷新历史：文件索引可以重建，用户隐藏状态无法从文件恢复。需要重新扫描时使用“刷新”。

区域库原有的备注、文件重定位和导出隐藏配置仍保留在原区域库索引；本次迁移范围是采集隐藏状态和历史检索数据。

## 检查和备份元数据

在项目根目录的 PowerShell 中执行。数据库须已由历史页面建立。

```powershell
.venv\Scripts\python.exe tools\history_metadata.py --outputs outputs
```

成功输出包含 `integrity: ["ok"]`、记录数、隐藏数和各集合条数。读取检查不会扫描或修改采集与方案文件。

使用一个不存在的新目录同时备份两份数据库：

```powershell
.venv\Scripts\python.exe tools\history_metadata.py --outputs outputs --backup outputs\history_backups\metadata_20261021
```

命令使用 SQLite 在线备份 API，生成 `history.sqlite3`、首次运行后存在的 `execution.sqlite3` 和 `manifest.json`。不存在的源库记录为 absent，不创建空运行数据库；现有目标被拒绝。旧 `.sqlite3` 文件名调用仍支持，同时生成 `_execution.sqlite3` 和 `_manifest.json` 同级文件。manifest 保存摘要和每库备份时刻。

两个文件各自一致，但没有跨库原子一致点：备份开始至结束间，历史索引与事件可能相差该时间窗口内的更新。恢复时保留 manifest 作为这一缺口证据；方案按摘要回核，未结束模拟任务显示中断/待核对，不根据历史索引推断执行结果。备份不含图像、模型、方案包或旧区域库配置，完整资产应独立保留。

清单内容或时间范围无效时，模拟回看显示时间范围未知，任务与事件仍可只读查看。关闭应用会取消正在遍历的中断恢复；已经提交的恢复记录保留，其余任务继续显示中断/待核对，不自动续跑。

恢复前关闭全部工作台实例，保留现有 `history_metadata` 整个目录以便回退。将 manifest 中 present 的两份快照放入新的空 `history_metadata`，分别命名 `history.sqlite3`、`execution.sqlite3`，同时保留 manifest；不能混入任何旧 `-wal` 或 `-shm`。只有历史库的旧备份不包含后续模拟事件，不要用它覆盖完整双库备份。重新打开后核验历史隐藏/恢复列表、模拟任务与事件数，再实际打开方案按摘要确认。模拟记录只读，未结束任务不自动续跑。当前没有自动恢复命令，不支持只复制数据库迁移全部资产。

## 当前实现边界

- 数据库保存索引时观察到的核验状态；它不能替代打开时的来源、摘要和数值核验。
- 刷新、写入、隐藏和恢复在后台执行。GUI 搜索使用不等写锁的只读查询，超时则保留当前筛选。
- 版本关联保存现有项目、版本与父版本标识，不根据名称猜测血缘。
- 当前模拟事件由独立 execution 库管理，历史索引 schema v1 不改；没有真实硬件执行日志、网络 API 或离线同步。
- 模拟事件库当前写版本为 v2，新增“已放弃、未运行”。新软件可只读 v1/v2，v1 首次写在事务内升级，不改写旧事件；旧软件会拒绝 v2 事件库。需要降级时使用升级前的备份，不手改 `user_version`，历史索引 v1 不受影响。
