# 人工补采与阶段检查

状态：实施中，2026-10-13。当前用于软件研发核验。

1. 在工作台选支持部位及体位，在新鲜 RGB 画面框选扫描范围，确认范围并开始。目标保持静止。
2. 保持与上一画面的重叠，缓慢小幅移动相机，停稳后请求补采。接纳至少 3 个不同视角后点击“检查当前采集”。
3. 阶段检查在后台重建，采集会话和参考原点保持，跟踪输入继续。目标和相机尽量保持稳定，避免断流或失跟。
4. 检查完成后打开“查看上次阶段检查”。查看问题位置、原因、建议和前后变化；有深度无网格不自动等同需要补采。检查图不能说明不可见面完整。
5. 关闭阶段检查，按提示调整视角，再停稳补采一到多个有效视角，再次检查。重复视角不虚增接纳数；无新接纳视角不重算阶段。
6. 连续两次没有参考支持改善或达到阶段上限时，停止继续补采接纳。查看原因后可最终结束，或重新建立独立采集；不在同会话重置原点。
7. 最终结束后生成最终模型和质量记录。检查模型与边界，再确认进入工作区域规划。人工结束仍有待确认位置时，记录保持待确认；确认不会把它们改为采集完成。
8. 在固定参考图涂抹工作区域、擦除排除，生成现有曲面路线。阶段模型不能直接进入规划。

现场验收至少记录同一会话的两轮阶段模型、增加的接纳视角、相同粗选/标定/参考来源、改善与退化、最终确认及生成路径。失败、取消、无收益与失跟分别核验。历史录制回放、Qt offscreen、软件测试及本次实采分别记录，不能互相代替。

阶段目录为源会话的 `derived/checkpoints/<stage>/`，包含 checkpoint.json、冻结 source、诊断图、逐像素类别、scan_feedback.json 与 scan_tasks.json。最终结果保存 acquisition_completion.json、scan_check.png、scan_diagnosis.npy 和 scan_tasks.json。接口文件给未来扫描适配器作为数据基础，尚未接入机械臂。
