# 检查和恢复历史元数据发布

此流程处理历史方案索引、区域库索引及采集任务绑定的小型元数据写入中断，不修复模型、原始采集或方案 ZIP 的内容。先检查状态，再决定是否恢复。

## 发布记录在哪里

这些入口通过 `femto.asset_storage.publish_json` 写入。每次操作在目标 JSON 所在目录的 `.publications/` 下生成操作记录，使用唯一操作编号和暂存文件。例如，历史方案登记位于 `region_project_history/.publications/`。

- `*.json`：操作身份、目标文件名、旧摘要、新摘要和发布状态。
- `*.stage`：未发布或失败后保留的准备内容。
- 上一级 `.publication.lock`：协作进程使用的操作系统文件锁。文件存在不代表进程仍运行；进程退出后锁会由操作系统释放，不按文件年龄强行解锁。

正常历史列表只扫描上一级的正式索引，不把这些记录作为用户方案展示。

## 只读检查

从项目根目录执行，将 `JOURNAL_PATH` 替换为具体的操作记录路径：

```powershell
.venv\Scripts\python.exe -X utf8 tools\recover_metadata_publication.py "JOURNAL_PATH"
```

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `published` | 正式目标内容与发布摘要相同 | 无需恢复 |
| `published_unrecorded` | 正式目标已经写入，最终收据未完成 | 可补记完成状态，不改目标内容 |
| `recoverable` | 进程中断留下完整准备内容，目标仍与写入前一致 | 可显式恢复 |
| `failed_retained` | 已明确记录失败，准备文件保留 | 不自动恢复，先排查失败原因，再重新登记 |
| `conflict` | 目标已改变，不符合当时预期 | 停止恢复，核对外部修改 |
| `superseded_or_missing` | 已发布过，但目标后来更新或丢失 | 不用旧记录覆盖新目标 |
| `incomplete` | 准备内容缺失或不完整 | 不能据此恢复 |

检查不会改变源方案。不要将 `published` 当作几何或覆盖核验通过，它只证明这次元数据写入的内容与摘要相符。

## 显式恢复

仅对 `recoverable` 或 `published_unrecorded` 使用：

```powershell
.venv\Scripts\python.exe -X utf8 tools\recover_metadata_publication.py "JOURNAL_PATH" --resume
```

恢复重新获取锁并再次检查目标与暂存摘要。目标被修改时拒绝覆盖。已经完成的操作可重复调用。

出现磁盘或权限故障时保留诊断，不手动删除原始模型、方案或任意 `.stage` 文件。当前没有自动清理这些操作记录。

## 当前接入范围

- 已接入：`catalog.register_project` 的历史方案索引、`region_library.write_index` 的区域库索引、`task_context.save_task` 的采集任务绑定，以及 `catalog.local_asset` 的受控相对路径解析。
- 已提供：可配置根目录的 `LocalAssets` 描述和定位接口。
- SQLite 历史管理使用自身事务，不经 JSON 发布器写数据库。操作方法见[SQLite 历史记录与备份](SQLite历史记录与备份.md)。
- 采集 `publication.json`、原生方案和 ZIP 继续使用既有完整资产核验与发布协议。
- 协作写入通过操作系统锁串行化；外部工具不遵守该锁时，不构成跨程序事务保证。

采集任务绑定只允许首次创建。两个调用并发写入同一个结果时，后到的调用读取已经建立的绑定，不覆盖它。区域库仍保留原有接口；其调用方在锁外读取后编辑的整个过程，不因此成为跨进程原子读改写事务。

需要与任务取消边界结合时，`publish_json` 支持 `commit` 回调，只把最终替换放在提交动作内；准备和校验仍可取消。异常的 `published` 字段表示目标是否已经实际替换，不能因最终收据失败便误报“没有保存”。

备份历史管理信息时应包含正式索引和操作记录。原始证据与方案资产仍按生命周期清单保留。
