# 完整数据备份与恢复

本工具为单机工作台的数据目录制作包含资产和数据库的备份，恢复时核对文件摘要，保留现有目录。它不接续模拟任务，也不发送设备指令。

## 备份数据

1. 在工作台“历史记录”点击“数据备份与恢复”，打开独立维护窗口。
2. 关闭主工作台和其他采集、重建、规划、数据写入工具。其他工作台实例未关闭时，备份会拒绝开始；独占维护锁持有期间，新工作台也不会打开。
3. 保持“备份数据”，选择备份的上级目录。窗口生成新的备份目录名，可自行编辑。备份位置必须在源数据目录之外，不能覆盖已有备份。
4. 核对“采集数据、模型与方案、原始照片、模型资源”等实际存在的数据根。只选择数据目录，不选择整个项目或磁盘根目录。
5. 点击“检查关联资产”。存在的外部关联资产未纳入时，使用“添加外部数据目录”显式加入其数据目录。工具不会自动扩大到整个磁盘。
6. 若原记录已经指向缺失的文件，先查看详情。默认阻止备份；确认只保留现存数据时，可勾选“记录已有缺失并备份其余数据”。这些缺失会保存在清单与恢复结果中，备份无法补回原文件。
7. 点击“开始备份”，等待完整清单、资产复制、数据库快照和独立校验结束。过程中可以取消；取消晚到、结果已经发布时，界面会说明已发布结果仍保留。

“检查关联资产”覆盖当前历史索引、已发布工作台记录、采集manifest来源链和设备证据引用，不解析任意第三方文件格式。便携方案中仅作历史来源说明的旧路径不当作活跃外部依赖。每个选定数据根的文件仍全部复制，不只复制索引命中的文件。

已有失效登记不被删除或改写。当前项目曾发现指向已删除临时目录的测试登记；维护窗口将其作为“原已缺失”列出，不把它们伪装成可恢复资产。

## 查看容量与清理预览

在“备份数据”模式点击“磁盘与清理预览”，后台统计已选择的数据目录，并按文件系统显示可用空间。同一卷不会重复汇总容量；可用空间低于2 GiB或卷容量的10%时显示“空间偏低”。这只是提醒，不替代备份/恢复时的实际空间检查，也不估计下一次采集或重建需要多少容量。

详情列出逻辑文件大小、疑似Python缓存及需要核对的草稿/发布/恢复暂存。**预览不删除文件，也不授权删除这些候选。** 暂存、`.tmp`、`.stage`或`.partial`名称不能证明文件已无用，恢复事务和未保存草稿须保留。原始采集、方案和历史文件不会因“长期未使用”被推荐自动删除。

链接和Windows重解析点不会递归扫描；目录不可读或扫描中消失时，报告“统计不完整”。文件仍在写入、稀疏文件、硬链接和压缩会导致统计与磁盘实际占用不一致，容量结果是扫描时的估计。

命令行执行 `.venv\Scripts\python.exe tools\data_backup.py disk-preview`。指定数据根仍用操作名前的 `--root name=directory`；扫描不完整时输出报告并以2退出，参数错误以1退出。图形界面可取消扫描。

## 检查与恢复

1. 选择“检查备份”，选择备份目录。工具核对清单、所有文件和SQLite完整性。若源数据已有缺失，检查成功也会同时显示缺失数。
2. 选择“恢复数据”，读取备份，核对每个数据根的恢复目录。**目标目录必须尚不存在**；请先单独保留现有数据，工具不会代为移动或覆盖它。
3. 若是原设备灾后恢复，应恢复到原来的绝对路径。将文件恢复到新目录只得到经过校验的副本，不会改写方案、轨迹、来源链中的绝对路径，不能据此承诺迁移后所有历史立即可用。
4. 点击“恢复到空目录”。全部根先独立暂存并核验，再发布。选择“查看详情”确认恢复结果和缺失资产标记。
5. 打开工作台，核对隐藏状态与历史列表，实际打开需要使用的便携/原生方案，确认图像、目标、路线和覆盖证据。未结束的模拟记录只读回看，不自动重发或续跑。

恢复预览绑定已校验的清单摘要。读取后备份清单改变，恢复会拒绝开始，需重新读取核对。

## 恢复中断

恢复事务保存在工作区 `.data_restores/`，暂存目录带 `.restore.<编号>.partial`。事务保留原始已校验清单及数据根归属；所有数据根完成发布后才清理未完成标记。

若进程退出，重新打开维护窗口，选择“继续中断恢复”，读取相应事务记录。继续前会核对暂存/已发布目录归属与每个文件摘要；目录被外部修改时拒绝覆盖。全部暂存已准备好时，即使原备份后来损坏，也可以用事务保存的原清单核对并继续。

暂存未准备完整时，选择“中止中断恢复”，保留现场后新建恢复任务。中止不删除暂存数据。工作台在存在未完成或无法读取的恢复事务时拒绝启动，避免把半恢复的数据当成正常数据使用。不要直接删除事务记录来绕过检查。

## 一致性边界

源资产写入者必须停止。工作台使用OS共享租约，维护使用独占租约；复制期间对发现的SQLite数据库同时持有写保留锁，使用SQLite backup API生成不依赖旧WAL/SHM的快照。源文件首末清单及摘要、目标副本均重新核对。

这不是操作系统级文件系统快照，维护锁不控制不采用该协议的第三方进程。停止其他命令行写入工具仍是前提；清单一致不证明任意外部写入过程都具备全局原子性。文件摘要校验也不代替实际打开时的几何、来源、预算和覆盖核验。

磁盘不足、取消、源文件变化和校验失败不会发布成完整备份。失败暂存和恢复现场保留，核对后再决定如何处置，不自动清理用户数据。

## 命令行

在项目根目录PowerShell执行。图形入口也可单独启动：

```powershell
.venv\Scripts\python.exe -m femto.app.qt_data_maintenance
.venv\Scripts\python.exe tools\data_backup.py inspect
.venv\Scripts\python.exe tools\data_backup.py backup D:\工作站备份\backup_20261021
.venv\Scripts\python.exe tools\data_backup.py verify D:\工作站备份\backup_20261021
```

自定义工作区用 `--workspace`；自定义数据根用重复的 `--root name=directory`，参数放在操作名之前。外部目录必须明确指定：

```powershell
.venv\Scripts\python.exe tools\data_backup.py --root outputs=E:\测试3D人体关节坐标-ui\outputs --root datasets=E:\测试3D人体关节坐标-ui\datasets --root external_1=D:\外部采集 backup D:\工作站备份\backup_external
```

选择新目录验证恢复副本：

```powershell
.venv\Scripts\python.exe tools\data_backup.py --to outputs=D:\恢复检查\outputs --to datasets=D:\恢复检查\datasets --to models=D:\恢复检查\models restore D:\工作站备份\backup_20261021
```

恢复目标需覆盖备份中全部数据根，其父目录须存在；具体根名以“检查备份”输出为准。`recover <事务JSON>` 与 `abort <事务JSON>` 分别继续和中止恢复，同样用 `--to` 明确非默认目标。`--allow-existing-missing` 仅允许记录原已缺失的资产，不能跳过仍存在但未纳入的外部资产。

原[SQLite元数据备份](SQLite历史记录与备份.md)命令仍可用，但只含数据库，不能替代本工具的数据根备份。新流程的验证进度见[本轮实施记录](../历史开发记录/后续五项迭代实施与验证_20261021.md)。
