# 16GB 电脑工作流程与升级复验

适用当前 Qt 工作区，更新于 2026-10-12。功能与参数以 [技术路线](../../技术路线.md) 为准。内存升级前可继续使用现有采集、规划、覆盖核验、补充与保存功能；不同工程的资源需求仍需按实际数据验证。

## 当前电脑操作

1. 采集时用 [主工作台](../../start_femto_app.cmd)，先确认部位、体位和扫描范围，再建立参考位置、停稳补采、结束并检查模型。完整 RGB-D 保留，不能通过裁掉原图减少证据。
2. 只处理已有工程时用 [区域规划入口](../../start_region_planner.cmd)，或运行下列命令。此模式打开已有模型/方案，不自动连接相机。
3. 依次生成路线、核验覆盖、查看原因和后续任务，再按需要进行严格路径或变宽补充。计算期间等待完成或使用取消，避免另开多个工作台同时处理大工程。
4. 人工核对后保存。原生路线包和便携工程各有完整校验，不能将正在保存的目录当作完整交付。失败提示若说明已有原生包保留，可从历史只读核对，再按提示重试便携保存。
5. 将 3DGS 训练、多份大工程回放和批量性能测试安排在其他时段。当前规划功能不依赖训练 Gaussian 模型；训练仍需独立运行环境及合格真实多视角输入。

```powershell
.venv\Scripts\python.exe -m femto.app.qt_main --ui-preview --project "实际模型目录或方案.zip"
```

输入区域、参数或模型改变后，旧路线、覆盖证据和后续任务可能失效，应重新计算与核对。取消或失败不能把旧证据变成新结果。历史方案保持只读；操作见 [覆盖原因与后续任务](覆盖原因与后续任务.md) 和 [名义变宽模型及恢复](名义变宽模型与恢复.md)。

## 已实施的资源优化

- 保存与回读的文件摘要按当前可用内存与文件大小选择有界分块缓冲：低余量时最多 64 KiB，其他条件最多 1 MiB；块间响应现有取消/预算并保留完整内容校验。阶段专项的 Python 分配测量只描述摘要临时内存，不是工作台总内存。
- 本次计算准备缓存按可用内存和任务规模有界配置；保存资产的摘要按可用内存、资产规模和进程可用 CPU 自动选择一或两工作线程。几何与证明仍保持原遍历和预算，资源检测失败时保守处理。绑定缓存与已处理预算异常的引用保留问题已修复，详见 [接入与复验记录](../历史开发记录/资源自适应接入与真实工程复验_20261012.md)。
- 工程 JSON 清单分段写入，目标台账和覆盖计算只在本次任务内有界复用计算准备，任务结束后释放；独立打开工程仍重新验证。
- 路线字段遍历和极小批次几何计算已做等价优化，数值策略、历史版本、质量门禁及工作预算保留。

固定真实工程在明确观测条件下已通过三次完整保存和每份工程的原生/便携独立回读；后续结构检查与摘要优化也分别通过同源一次完整保存及双回读。见 [保存复验](../历史开发记录/保存监控开销核对与真实工程复验_20261011.md) 和 [分块摘要验证](../历史开发记录/文件摘要分块读取与取消完善_20261011.md)。该样例不能代表所有模型规模或后台负载。

## 升级到 32GB 或更多之后

升级内存不需要迁移原始数据、替换算法版本或修改已保存方案。先使用同一真实工程、同一输入和当前参数进行复验，再扩大实际任务规模。

软件会在新的计算准备、摘要任务开始时读取当前可用资源，升级后无需手动切换“32GB 模式”。实际可用内存充足时可保留更多准备缓存；满足 CPU、资产规模和内存余量条件时可启用两个摘要线程。更多内存可以减少内存压力和换页，实际速度仍取决于任务、CPU、磁盘和后台负载。当前只有模拟资源配置与现有 16GB 电脑验证，32GB 或更多真机性能待测。

复验至少包含：三次完整保存、每份原生和便携工程的独立打开、全部资产摘要核对，以及保存前后的原目标/确认范围一致性。记录内存容量、后台负载、源码版本、输入摘要和观测频率；进程 RSS 可保持 20 毫秒采样，系统可用内存按 1 秒采样，避免高频系统查询干扰耗时。测试命令与记录格式见 [覆盖性能重复验收](覆盖性能重复验收与失败诊断.md)。

现有局部离线建模子进程的默认资源预算为 4096 MiB / 600 秒，规划操作的现有限额也不会因增加物理内存而自动改变。这些限制不等于整机或全部 UI 进程的内存上限。若更大任务仍触及预算，应先保留诊断并定位实际瓶颈，再提出独立变更，不能仅因为内存增加就放宽几何证明条件。

跨会话目标继承、实物尺寸精度和真实移动多视角训练仍分别需要配对采集、测量真值及合格视角；升级内存不会补齐这些证据。当前结果用于研发查看与规划，执行与实物精度验证标志保持未通过。
