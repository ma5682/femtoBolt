# 研发重复测量与版本回归流程

本流程用于研发诊断和版本回归，不是临床定位或机械臂验收。已有“两点实测距离”界面、measurement_audit与scene_scale_validation保持可用。本流程补充结构化条件、失败尝试、独立采集区分、代码封存和同源配对。

## 先选测试目的

|purpose|输入及输出|基准datum|不能据此声称|
|---|---|---|---|
|optical_range|一个W0点的欧氏模长，mm|optical_origin|相机外壳到物体的尺量距离|
|axial_depth|同一点的Z分量，mm|optical_axial|斜向尺长、欧氏距离|
|housing_distance|相机外壳指定标记到参考物的人工读数，mm|housing_mark|光心位置或自动补偿；本项只存人工读数|
|two_point_length|两点W0三维欧氏距离，mm|two_physical_endpoints|绝对XYZ精度或全表面精度|
|plane_residual|至少4个非共线点拟合平面后的RMS/P95残差，mm|fitted_plane|绝对平面位置准确；RMS也不是峰谷平面度|
|mapping_reprojection|固定初始RGB像素与K·XYZ投影的距离，pixel|reference_camera_pixel|独立二维到三维定位精度|

重复采集不是另一个距离定义：在相同目的、物理目标和摆放程序下独立重采上述量。代码将同一原始RGB/Depth字节集合去重；同一数据多次运行或重复选点只报告同数据波动，不计作独立重采。原始字节不同也只能作为独立性候选，不能证明相机确实重新摆放。

W0为首次有效彩色相机RDF，XYZ单位米。相机移动或重新建立原点后，不能直接把两个W0中的XYZ相减；优先比较同一参考物的两点长度。若要比较绝对位置，必须另有已验证的跨会话坐标注册，本流程目前不代做。mapping_reprojection仅使用固定初始相机的去畸变内参及像素。

## 实物测试准备与录入

1. 用固定的哑光刚性参考物，标出可重复辨认的A/B端点及平面ROI。记录真实读数，不能按设计尺寸代填。平面建议固定至少3×3个位置，记录同一ROI与采样布局；不要每次删掉残差大的点。
2. 写明尺具/量具型号、分辨率、校验来源、读数基准、参考物尺寸和材料。reference.uncertainty_bound是用户声明的**绝对误差界**，不是默认标准差；在uncertainty_method解释视差、尺具、端点识别等如何得到这个界。没有依据时填null，不填0冒充无误差。
3. 区分外壳上的实际尺量标记、光心、轴向深度。外壳到光心的关系未独立核验时，光心/深度项目保持未验证。一次吻合或固定差值不能触发补偿；程序不生成或应用补偿值。
4. 填写实际距离、角度及角度定义、材料、相机模式/分辨率/FPS/量程/对齐配置、光照/温度/背景/振动、操作者、目标与相机摆放程序。附参考物照片、尺量记录或量具证据，作为reference_evidence资产。不能追忆的历史条件填null。
5. 先写计划次数及失败条件，保存测试计划，再采集。建议每个条件至少5次独立重采作为研发起步，不把5次当统计充分性或通过门槛。每次都重新执行同一摆放/采集/选点程序；不同距离、角度、材料或操作者分组。失败、丢失、无支持、取消都录入，不只挑成功样本。
6. 保留原始RGB/Depth、输入位姿、标定、几何和算法。assets清单只封存当前指纹，原数据仍需自行保留；不要清理原始目录。代码文件会复制进记录目录，20MB预算，填写参与处理的完整项目源文件及依赖版本。algorithm.parameters填写实际参数，不是计划参数。

所有新报告的physical_accuracy_verified=false、verification_status=unverified。条件完整时可出现within_entered_interval_only，只表示该数值与用户输入参考误差界/容差的区间关系，不升级为实物或临床通过。

## 文件和命令

在PowerShell进入项目：

```powershell
Set-Location 'E:\测试3D人体关节坐标'
.\.venv\Scripts\python.exe research_validation.py init 'outputs\my_protocol.json'
```

也可从“研发验证模板”复制对应purpose的protocol.json与observations.json。模板坐标为null，必须填实际值，不能直接作为测量结果。完整示例字段见模板；默认assets的占位路径也必须替换。路径相对protocol文件所在目录，建议使用绝对路径。

历史输入可自动列出原始会话RGB/Depth、输入位姿、标定和清单：

```powershell
.\.venv\Scripts\python.exe research_validation.py init 'outputs\replay_protocol.json' --dataset 'datasets\原始会话目录'
```

该入口默认historical_replay/same_data，不标成新实物试验。对比跟踪/融合版本时使用共同的**原始输入会话**；新版本生成的几何及位姿属于算法输出证据，不要冒充不同的输入标定。source_metadata保存清单指纹但不充当独立采集指纹，复制数据再改目录/清单时间不会增加独立采集数。

补齐test_id、target_id、operator和measurement_definition。后者写清A/B实体定义、固定RGB选点像素或平面ROI/采样位置及选择方法；更换定义必须新建协议。reference填写参考值、单位mm或pixel、误差界和基准；没有独立参考时value=null，此时偏差/RMSE为未知。algorithm填写名称、版本与参数，assets追加算法源文件、geometry及reference_evidence。证据类型只能是synthetic、historical_replay或physical_test，分别统计，不跨类型配对。

observations输入示意（坐标仅说明格式，实际录入须替换）：

```json
{"xyz_m": [[0.0, 0.0, 0.5], [0.1, 0.0, 0.5]], "selection_notes": "替换为真实A/B端点"}
```

两点可从已有measurement_validation记录的points[*].point_world_m复制；保留旧记录为source_metadata。旧记录不自动获得新条件，也不升级验证级别。平面填写固定ROI采样点；映射另填pixel和intrinsic；外壳距离填manual_distance_mm。

录入每次尝试：

```powershell
.\.venv\Scripts\python.exe research_validation.py record 'outputs\my_protocol.json' --observations 'outputs\my_observations.json' --trial 'trial-01' --elapsed 1.23 --output 'outputs\experiment_A'
.\.venv\Scripts\python.exe research_validation.py record 'outputs\my_protocol.json' --trial 'trial-02' --status failed --reason '无有效映射' --elapsed 2.10 --output 'outputs\experiment_A'
.\.venv\Scripts\python.exe research_validation.py record 'outputs\my_protocol.json' --trial 'trial-03' --status cancelled --reason '操作者取消' --output 'outputs\experiment_A'
```

elapsed是实际算法处理耗时（秒），不包括人工准备或录入封存；不知道就省略。工具自身记录recording_elapsed_s，二者不混用。记录会显示阶段，Ctrl+C取消未完成封存；如中断发生在发布边界，以能通过校验的完整记录为准，不把.pending目录当结果。每次生成独立UUID目录，原子发布，不覆盖旧记录。人工输入错误被拒绝时，应修正输入；真实算法失败则用status=failed保留尝试。

汇总与同源比较：

```powershell
$runPaths = @(Get-ChildItem 'outputs\experiment_A' -Filter record.json -Recurse | ForEach-Object { $_.FullName })
.\.venv\Scripts\python.exe research_validation.py summary @runPaths --output 'outputs\summary_A.json'
.\.venv\Scripts\python.exe research_validation.py compare --before 'outputs\experiment_A\记录ID\record.json' --after 'outputs\experiment_B\记录ID\record.json' --output 'outputs\comparison_AB.json'
.\.venv\Scripts\python.exe research_validation.py verify-assets 'outputs\experiment_A\记录ID\record.json' --output 'outputs\asset_audit.json'
```

汇总/比较输出必须用新文件名；已有文件会被拒绝覆盖。compare两侧可各列多个record.json，每侧每个trial只允许一个记录。配对要求协议定义、条件、参考、证据类型、trial、原始字节和输入标定相同；算法代码/版本/参数可以不同。未配对数量会显示，不能静默缩小样本集。不同标定单独分组；不知道标定或原数据的记录不能形成有效配对。

## 如何解释结果

- signed_bias、RMSE、P95绝对误差仅在有可比参考时计算；外壳/光心基准错配不计算偏差。显示小数位来自浮点计算，不代表精度。
- sample_stddev是全部录入成功数值的样本标准差；同数据重复也可能为0。recapture_stddev先按原始数据指纹聚合，再计算不同采集均值之间的标准差；只有一个原始数据集合或same_data范围时为null。该统计不是不确定度预算或测量精度证明。
- failure_rate分母是全部已录入尝试（含取消）；取消单列，未录入尝试不会被推断为成功。必须保存预定计划，才能检查是否漏录。
- pairs给出同试次值差和已知耗时差，前后摘要分别提供偏差/重复性/失败率。值变小或速度变快不自动视为改进；配对样本少、硬件/环境变化和预热影响要在报告中说明。
- summary/compare用封存时指纹配对，读取时验证记录、算法快照和指标重算；不逐次重读庞大原数据。真正回放前运行verify-assets检查源是否仍存在且未变。算法当前文件变更不破坏已封存代码，但原输入变化/缺失必须处理后再复测。

## 当前证据与未验证清单

自动化合成测试、历史回放位于outputs/research_validation_checks，分别报告。历史书本保存的两点在相同版本复算两次，值一致，原始集合只有1份，独立重采统计为空；没有尺量基准，偏差/精度仍未知。该演练不是算法改进对照，版本差异配对由合成回归测试验证。

以下真实条件当前全部为“未验证”：具有不确定度说明的光心距离/轴向深度基准、外壳到光心关系、多距离多角度多材料/环境矩阵、独立重复采集的尺寸偏差、已知物理平面的绝对残差、独立二维到三维真值、操作者间差异和长期漂移。未提供这些条件时，不给通过结论；本批不补做临床定位验收。
