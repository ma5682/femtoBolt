# 三维表面轨迹使用说明

本功能从已保存区域的实测 Mesh 表面生成研发用蛇形扫描轨迹。所有 XYZ 均为 W0 / RDF / 米。历史生成与命令行当前默认算法 `mesh-slice-serpentine-v4.4`：工作块按医师在固定 RGB 页涂抹的选择组件划分（一个 4 连通的选中区域 = 一个工作块），块内先按局部条带逐行蛇形访问、再转到邻近条带；每一对实际相邻扫描段都尝试沿真实网格表面连接（相邻行先走边界折返，其余沿网格边找路并在原路径的可信三角面内缩短；仍失败时，再经真实共享边内部双向搜索面内路线），成功的块是一条连续链、块内 `gap_count=0`；块之间只记录 `selection_break` 停止标记，不生成跨块点、连线或运动。Mesh 连通关系只作为块内"碎片"诊断：一个选中区域内的多个网格碎片逐个规划，碎片之间的接缝保留为 `disconnected_surface` gap，块标为"未完成"。缺面、禁止区域或无法连接的位置仍保留 `gap`，并在 `gaps.csv` 的 `link_failure_reason` / `row_turn_failure_reason` 列和报告中给出诊断原因（仅供排查，不参与任何决策）。

旧结果：v1 / v2 / v3 / v3.1 / v4 / v4.1 / v4.2 / v4.3 文件仍可查看和播放（播放只做哈希、来源和网格校验，不重算，窗口提示当前产品规则为 v4.4）。已有 v4 系列的区域直接“重新生成”即可采用 v4.4，不必重选；v4、v4.1、v4.2、v4.3 和 v4.4 都保留按保存版本重算的能力，不自动升级。旧的逐整行访问顺序不再用于新生成的默认路线，但其实现保留供历史校验，不删除历史文件。更老且没有“选择意图”的区域导出需要重新选择并导出，旧轨迹仍保留。

v4.1 只优化网格边回退连接：固定两端，合并可行的同面折线，沿相邻三角面的真实共享边调整交点，每条新边仍必须有单个实测面支持且整边不穿未选像素/禁区。不可行的候选保留原路径；不移动扫描行，不改变已成功的边界折返，不补缺面。报告列出 `surface_corridor_shortened` 数量。缩短不等于全局最短、运动平顺或可执行，急转角仍需单独检查。

v4.2 保留上述成功连接，只在旧方法失败时补充面内搜索：按共享边投影经过的像素区间取内部候选点，以透视关系还原到原始三维共边；仅连接同一实测三角面内、整条边均通过选区/禁区检查的点对。报告列出 `surface_face_portals` 数量。这可以解决“端点到三个顶点都被选区边缘挡住，但面内仍可绕行”的断开，不填洞、不跨碎片、不把待补采位置自动接通。有限候选搜索不保证找到所有可行路线，失败仍为待处理。详见 [v4.2 交付记录](../历史开发记录/三维路线面内补充连接与显示修正_v4.2_交付记录_20260923.md)。

v4.4 在用户确认后调整块内扫描段访问顺序：相邻物理切片中，沿 e1 区间互为唯一重叠邻居的段组成局部条带；分叉、合并、缺行处结束条带。先保留原首段及其方向，在条带内蛇形扫完，再按确定性的 XYZ 入口距离选择下一条带。全部扫描段和采样原值保留，不改工作块或碎片，入口距离只用于排序，不能代替实际贴面连接验证。原物理行号、扫描方向无关的行距测量顺序保留；连接失败仍待处理，不保证全局最短或全部连续。

v4.4 行距测量仍使用原始规范扫描顺序、全部既定测量点和同一最短路数值规则，但在全部待查询顶点距离确定后提前结束当前层搜索，不再遍历不影响报告的远处顶点；测量上限不变。播放定位按真实行号与精确 XYZ 映射到重排后的点，不使用最近邻猜测；没有唯一对应时说明无法定位，保留原测量报告。

## 选择意图与三种"断开"

v4.3 保持候选点与几何约束，仅改变补充搜索顺序：两端共享原搜索预算，尽早发现终点被约束隔开的情况；对已经严格证明全选中、远离禁区边界的节点包围框批量判断可见，其他位置照常逐条检查，最终采样仍完整验真。报告记为 `surface_face_portals_bidirectional`。旧 v4.2 的同成本路线选择可能不同，所以保留独立版本，不能把新结果重解释为旧结果。详见 [v4.3 交付记录](../历史开发记录/三维路线大区域搜索优化_v4.3_交付记录_20260923.md)。

- 固定 RGB 页保存区域时，最终涂抹掩膜（工作区 − 禁区，或有效范围 − 禁区）作为权威记录写入 `region.selection_intent`：选中组件、内部明确未选的孔洞、涂抹禁区都逐个枚举；三角面只是由掩膜派生的几何绑定。同时写入 `region.selection_support`，把每个选中像素分为：有实测 Mesh 支持、参考帧有深度但 Mesh 缺面（派生表面候选，待用户确认方法后才会使用）、无 Mesh 且无深度、超出深度范围、深度冲突、无源像素。后五类统称"几何待确认 / 需要补采"，它们保留覆盖需求，不会被当成未选。
- 多个分离的选中区域 → 多个工作块，块内各自连续，块间暂停。
- 一个区域内部明确未选（未涂抹或涂为禁区）→ 保存为选择孔洞；面心落在孔内的三角面不进入区域 PLY；扫描采样、连接采样以及任意两个相邻采样之间的整条边，其投影经过的每一个参考像素都必须属于本块的选中像素（像素级严格），落在未选像素上的采样被丢弃并切段；涂抹禁区另按多边形整边避让。无法绕行时该块标"未完成"并报告原因（如 `explicit_unselected_blocked`），不强行跨孔连接。
- 选中但 Mesh 有孔洞 / 缺面 / 碎片 → 覆盖需求保留：碎片逐个规划、接缝不桥接；完全没有支持的区域记为"无法规划：需要补采"；不会生成任何伪实测 XYZ。

## 状态与发布策略

- 每块状态：`planned`（单链完成）/ `incomplete`（有链但块内仍有 gap，原因逐条列出）/ `unplannable`（没有任何链）。整体 `continuity_status` 只有全部块单链时才是 complete。
- 覆盖与连续分开检查：`coverage_status` 在存在无法规划块、未覆盖网格碎片或几何待确认像素时为 partial；报告列出每块的未覆盖碎片、面数、面积和几何待确认像素。没有治疗头有效覆盖宽度依据，不宣称完整治疗覆盖。
- 连接段若落在其他已扫描行的名义半行距内会标为"重复经过"（洋红显示、报告与 CSV 记录）；该判定按名义行距，不是治疗头宽度，不得据此推定治疗能量持续开启。
- 存在未完成或无法规划的块、未覆盖网格碎片或几何待确认像素时（"结果完成"只有一个判定：所有块单链、连续完整、覆盖完整、几何待确认像素为 0、未覆盖碎片为 0），新结果仍完整生成、校验并可预览，但**不替换、不删除**旧的有效轨迹：历史列表同时显示最新完整结果和更新的未完成结果，后者标注"未完成结果，旧轨迹保留"。只有结果完成并校验通过后，才删除同一区域的旧轨迹目录。

2026-09-23 新生成默认已更新为 v4.4；重启应用后，在原历史区域点击“重新生成”即可，无需重选。此前 10:46:41 大区域已完成规划并发布研发预览文件（单次规划约 58 秒、含发布约 67 秒，128016 点）；仍有实测碎片分离、约束阻断与几何待确认，因此明确为未完成结果，保留旧轨迹。120 秒、20 万采样/各类面内搜索以及行距计算上限与完整验证仍保留；更复杂输入仍可能被拒绝，不发布截断或未经验证的路线。实际时间随网格、禁区与机器负载变化；自动分批未实现，不能自动删点或放大步长。详见 [v4.4 交付记录](../历史开发记录/三维路线块内条带访问优化_v4.4_交付记录_20260923.md)。

1. 在固定 RGB 页面完成工作区域/禁止区域并点击"保存并导出当前结果 GLB / PLY"。状态栏会显示选择组件数、内部孔洞数和几何待确认像素数。当前页面只负责选区和导出。
2. 打开"历史区域导出记录"，选中一个已保存区域，点击"生成三维扫描轨迹"。已有轨迹时按钮变为"重新生成三维扫描轨迹"。任务在后台执行，可取消。
3. 新结果生成并通过完整性校验后，若结果完成（见上节判定），删除同一历史区域的旧轨迹目录（不进入回收站）；生成失败、取消或结果未完成时保留旧结果。包含额外用户文件的旧目录不会自动删除，界面会报告原因。
4. 选中轨迹可预览 GLB、打开轨迹文件夹、查看路线图或播放。播放使用保存时的区域和来源；块间停止时提示"块间停止（选择分离）"，继续只定位下一块起点；块内 gap（未完成块）停止时提示链接失败原因。播放窗口"块"下拉可切换单块显示并标出状态（单链完成 / 未完成 / 未规划），未完成块分别显示“N 段路线 / M 处断开”，不再把链数称为断点数。路线图与播放画面叠加青色选择组件轮廓、红色明确未选区域、紫色"有深度缺面"、橙色"无可靠几何"；选择组件模式不画旧多边形编码带来的紫色跨块桥线，也不拿旧多边形填充覆盖。源模型、参考图像或标定不匹配时拒绝播放。
5. 历史列表和生成完成提示会显示工作块数、单链完成数、未完成数、无法规划数与覆盖状态。
6. 选中轨迹点击“查看规划检查”：先核验文件及来源，再查看逐块待处理原因、完整行距样本分类、采样步长、离散转角及最大转角位置、扫描/连接长度比例。旧轨迹也可直接检查，不重新生成、不改写原文件。新生成的 `trajectory_report.txt` 自动包含该内容。单链连续不等于平滑；缺失 XYZ、行距不确定和丢弃的切片片段分别列出，保留医师覆盖需求。检查不改变当前自动发布/旧文件清理规则，也不新增平滑或补面门限。论文依据与后续顺序见 [路线规划论文借鉴与完善方案](../技术资料/路线规划论文借鉴与完善方案_20260923.md)。

## 命令行与拖放

把包含 `region_N.json` 的区域导出目录拖到根目录 `生成三维蛇形扫描轨迹.cmd`，或从仓库根目录运行：

```powershell
.venv\Scripts\python.exe -m femto.planning.mesh_slice_planner <区域导出目录或region_N.json>
```

可选参数包括 `--output DIR`、`--row-mm 5`、`--step-mm 1`、`--direction auto|w0_x|w0_y|<角度>`、`--start-corner top_left|top_right|bottom_left|bottom_right`；`--selection-v4` 显式使用冻结旧 v4，`--selection-v4-1` 使用冻结 v4.1，`--selection-v4-2` 使用保留的单端面内搜索，`--selection-v4-3` 使用保留的逐整行访问 + 双向搜索，`--mesh-blocks-v3` 显式回到 v3.1 的网格连通分块规则（不需要选择意图），五开关互斥。无选择意图的导出在 v4/v4.1/v4.2/v4.3/v4.4 下写出 `trajectory_blocked.json` 并返回 2。v1 冻结默认值及阈值不得为追求结果而放宽。Python API 为兼容仍默认 v4；使用 v4.4 时显式传 `selection_algorithm='mesh-slice-serpentine-v4.4'`，该选项通过已有 `planner.algorithm_version` 保存，不新增参数键。

## 输出

- `trajectory.json`：统一 `femto-surface-trajectory-v1` 模型，扫描段与 gap 严格交替；v4 每段带 `block_index`，`blocks`（`femto-surface-trajectory-blocks-v2`）记录每块的选择组件、面清单哈希、状态 / 原因、网格碎片、连续 / 覆盖 / 选区 / 重复经过统计、链接规则和选择绑定；`statistics` 含块数、单链完成数、未完成数、块间 gap 数、`continuity_status`、`coverage_status`、几何待确认像素数和重复经过统计；`gap_report` 含链接失败计数、未完成块清单和几何待确认分类。
- `trajectory.csv`（v4 含 `block_index` / `role` / `revisit` 列）、`gaps.csv`（含 `block_from` / `block_to` / `row_turn_failure_reason` / `link_failure_reason`）、`blocks.csv`（含连续 / 覆盖 / 像素 / 重复经过列）。 v4.4 的 `row_index` 列为每个点的真实物理扫描行，访问顺序可以回到较早行；JSON 链头行号仍标识首点所在行，不代表整个合并链只有一行。
- `region_with_trajectory.glb`：区域网格、每个有链的块一个管线节点（洋红为重复经过的连接段）、gap 端点标记（青色为 `selection_break`），块间没有管线。
- `route_diagram.png`：参考 RGB 可找到且哈希一致时生成；叠加选择组件轮廓、明确未选区域和几何待确认区域，标注块编号与状态，块间不画线。
- `depth_diagram.png`、`trajectory_report.txt`：扫描面深度图与中文摘要（逐块逐碎片列出状态、原因、覆盖缺口和重复经过）。
- `trajectory_files.json`：上述已生成文件的 SHA-256 清单，不包含自身。

区域方案库和 `load_trajectory` 会核对文件清单、来源清单、区域 PLY 和逐点三角面支持；v4/v4.1/v4.2/v4.3/v4.4 还按导出的选择意图重算工作块与面归属、碎片连通性、面清单哈希、像素计数，核对意图 / 支持哈希，检查每个 `planned` 块单链无 gap、块间 gap 恰为 `selection_break`、连接边不穿越禁区且不离开参考图像，所有块与全局统计均能从 `ordered_items` 重算，任一不符即拒绝。v4/v4.1/v4.2/v4.3/v4.4 按保存版本精确重算；旧 v3 只校验回放，仍需重新生成才能使用较新算法，不会被重解释。

## 投影式旧方案适配

研发代码可调用 `from_projection_plan(plan, region, store, region_manifest=None)`。显式传 `region_manifest` 时绑定并校验导出 PLY；不传时只从当前 `store.mesh` 重建区域网格，不扫描目录猜测。旧全局 `triangle_index` 会转换为区域 PLY 的局部索引并做 1e-6 m 几何验证；无法映射的点会拒绝整次转换，旧 `path.json`、`plan_binding` 和 CSV 不会被修改。

## 阶段 C 诊断：派生表面候选（不进入规划）

把带选择意图的区域导出目录拖到根目录 `生成派生表面候选诊断.cmd`，或运行：

```powershell
.venv\Scripts\python.exe -m femto.planning.derived_surface_candidates <区域导出目录或region_N.json> [--output DIR]
```

它绑定该导出所引用数据集的逐视角原始深度、标定与位姿（哈希与单位参考位姿全部核对，导出记录的深度范围必须等于该数据集的重建深度范围，不符即拒绝），对参考帧原始深度按既有像素邻接规则建面，只保留三个顶点、三条边和内部像素都属于同一个医师选择组件、不触碰深度冲突像素、且至少一个顶点是"有深度缺面"像素的三角面，然后在导出目录下写 `derived_surface_candidates_<12位>/`：`derived_surface_candidates.json`（逐组件候选 / 已覆盖 / 未覆盖 / 深度冲突像素数、被拒面原因计数、接缝距离分位数、其他视角 10 mm 诊断计数）、`candidate_surface_m.ply`（W0 / RDF / 米）、`candidate_faces.csv`、`candidate_pixels.csv`、`derived_surface_diagram.png`（绿 = 候选已覆盖、橙 = 未覆盖、红 = 深度冲突、青 = 选择组件轮廓）和哈希清单。旧导出无选择意图时写 `derived_surface_blocked.json` 并返回 2。回读诊断目录时会重新绑定并核对全部原始证据（每个视角的 RGB / Depth / Pose 字节、`frames.jsonl`、数据集 manifest、标定、参考位姿），任何一项与生成时不同都拒绝读取。

这一步只是研发诊断：`status=candidate_not_admitted`，候选面不进入区域导出、`selection_support`、v4 规划、轨迹、播放或历史清理；无深度和深度冲突像素不会被插值；原网格、原始数据和旧轨迹不变。任一候选像素未覆盖或存在深度冲突像素时报告即标"未完成"。是否以及以何种门限（他视角一致性、接缝深度 / 法线差、孔洞尺寸、密度、拟合误差）把候选面纳入规划，仍待用户确认。

## 安全边界

轨迹固定 `execution_ready=false`、`physical_accuracy_verified=false`。点法线不是工具姿态；当前没有速度规划、离面抬升、碰撞检测、底座/机械臂运动学、手眼标定、接触力、治疗能量或设备接口。行距是平行切片间距，不等于处处相同的曲面测地间距。派生工作表面（阶段 C）只实现到候选诊断，方法门限与纳入规则待用户确认，候选不参与轨迹。该结果只能用于研发查看和软件一致性验证，不能直接驱动设备或作为临床/实物精度结论。
