# 三维表面轨迹使用说明

本功能从已保存区域的实测 Mesh 表面生成研发用蛇形扫描轨迹。所有 XYZ 均为 W0 / RDF / 米。当前算法 `mesh-slice-serpentine-v3.1`：先按网格面连通关系把区域分成块，每块内部按块自身的扫描坐标排行（行按切片位置、段按行方向投影、奇偶行反向），沿真实网格边界逐行折返形成连续扫描链，一块扫完才进入下一块；块之间只记录 `disconnected_surface` gap，不生成跨块点、连线或运动。缺面、禁止区域或无法验证的换行仍保留 `gap`；未连接的换行会在 `gaps.csv` 的 `row_turn_failure_reason` 列和报告中给出诊断原因（仅供排查，不参与任何决策）。已有旧轨迹需点击“重新生成三维扫描轨迹”才会采用当前算法；旧 v3 文件仍可查看和播放，但重算校验会提示重新生成。

## 分块规则

- 块 = 共享边相连的三角面集合，只看网格拓扑，不按 RGB 外观、投影接近或空间距离合并；相距很近或投影重叠但拓扑分离的表面仍是不同块。
- 块编号按访问顺序从 1 起。访问顺序按参考图像阅读顺序：从 `start_corner` 一侧开始，先比行方向的像素边界，再比列方向；无法投影的块排最后；同值按连通分量编号。同一输入重复生成顺序相同。
- 每块单独计算扫描方向（`auto` 为该块 PCA 主轴，模糊时回退 W0 X；`w0_x` / `w0_y` / 角度对每块含义相同）。行的先后按该块扫描面的切片位置排序，不按参考图像行列；`start_corner` 只决定从哪一端开始和首行方向。冻结阈值、行距、步长和 200,000 点总预算对整份结果生效，不因分块放宽或倍增。
- 报告中的“实际网格间距分布”是原始测量；“有效行距”排除了大于 2 倍名义行距的样本，这些样本是跨孔洞或缺失表面的图最短路上界，不代表真实排行间距，其数量与占比单独列出。
- 太小或无法切片的块（例如 1–2 面碎片、窄于一个行距）不会被静默丢弃：报告和 JSON 记录其编号、面数和原因，覆盖状态标为“部分覆盖”。全部块都无法规划时拒绝生成，旧轨迹保留。

## 从历史区域生成和预览

1. 在固定 RGB 页面完成工作区域/禁止区域并点击“保存并导出当前结果 GLB / PLY”。当前页面只负责选区和导出。
2. 打开“历史区域导出记录”，选中一个已保存区域，点击“生成三维扫描轨迹”。已有轨迹时按钮变为“重新生成三维扫描轨迹”。任务在后台执行，可取消。
3. 每个区域下面只显示一条当前轨迹。新结果生成并通过完整性校验后，删除同一历史区域的旧轨迹目录（不进入回收站）；生成失败或取消保留旧结果。包含额外用户文件的旧目录不会自动删除，界面会报告原因。
4. 选中轨迹可预览 GLB、打开轨迹文件夹、查看路线图或播放。播放使用保存时的区域和来源，不需要恢复当前选区；gap 处停止，继续仅定位下一段起点；块间停止时提示“块间停止”，继续只定位下一块起点，不播放跨块运动。播放窗口的“块”下拉可在“全部块”和单块之间切换，单块只是显示过滤并定位到该块首链，未规划块会提示原因；切换不修改保存的轨迹。源模型、参考图像或标定不匹配时拒绝播放。
5. 历史列表和生成完成提示会显示块数、可规划块数和覆盖状态；“部分覆盖”表示有块未规划，轨迹不覆盖这些块。

## 命令行与拖放

把包含 `region_N.json` 的区域导出目录拖到根目录 `生成三维蛇形扫描轨迹.cmd`，或从仓库根目录运行：

```powershell
.venv\Scripts\python.exe -m femto.planning.mesh_slice_planner <区域导出目录或region_N.json>
```

可选参数包括 `--output DIR`、`--row-mm 5`、`--step-mm 1`、`--direction auto|w0_x|w0_y|<角度>` 和 `--start-corner top_left|top_right|bottom_left|bottom_right`。v1 冻结默认值及阈值不得为追求结果而放宽。

## 输出

- `trajectory.json`：统一 `femto-surface-trajectory-v1` 模型，扫描段与 gap 严格交替；v3 每段带 `block_index`，`blocks` 记录每块的连通分量、面索引范围与哈希、状态 / 原因、段 / 点 / 行区间和长度统计，`statistics` 含块数、可规划块数、块间 gap 数和 `coverage_status`。
- `trajectory.csv`、`gaps.csv`、`blocks.csv`：逐点（v3 含 `block_index` 列）、逐 gap（v3 含 `block_from` / `block_to`）和逐块表格。
- `region_with_trajectory.glb`：区域网格、扫描段和 gap 端点；v3 每个已规划块一个管线节点，块间没有管线。
- `route_diagram.png`：参考 RGB 可找到且哈希一致时生成；标注块编号与覆盖状态，块间不画线；不可用不会阻断核心轨迹。
- `depth_diagram.png`、`trajectory_report.txt`：扫描面深度图与中文摘要。
- `trajectory_files.json`：上述已生成文件的 SHA-256 清单，不包含自身。

区域方案库和 `load_trajectory` 会核对文件清单、来源清单、区域 PLY 和逐点三角面支持；Mesh 自动规划结果还会按原参数重算比对，v3 还核对块与网格连通分量的映射。旧 v1 / v2 文件按原算法版本读取和重算，不会被重新解释为分块结果。文件缺失、被篡改或来源不一致时拒绝使用。

## 投影式旧方案适配

研发代码可调用 `from_projection_plan(plan, region, store, region_manifest=None)`。显式传 `region_manifest` 时绑定并校验导出 PLY；不传时只从当前 `store.mesh` 重建区域网格，不扫描目录猜测。旧全局 `triangle_index` 会转换为区域 PLY 的局部索引并做 1e-6 m 几何验证；无法映射的点会拒绝整次转换，旧 `path.json`、`plan_binding` 和 CSV 不会被修改。

## 安全边界

轨迹固定 `execution_ready=false`、`physical_accuracy_verified=false`。点法线不是工具姿态；当前没有速度规划、离面抬升、碰撞检测、底座/机械臂运动学、手眼标定或设备接口。行距是平行切片间距，不等于处处相同的曲面测地间距。该结果只能用于研发查看和软件一致性验证，不能直接驱动设备或作为临床/实物精度结论。
