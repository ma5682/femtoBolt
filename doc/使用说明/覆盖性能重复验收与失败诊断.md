# 覆盖性能重复验收与失败诊断

固定作用模型的“补充规划”现在先重新证明原确认范围，再尝试新扫描范围。原确认集合必须完整保留，新增扫描点见证至少增加 0.1 mm² 才接纳。若无法重新证明原确认集合或新增见证不足，保留该轮之前的路线和覆盖。达到预算时可以保留已经证明且达到接纳门槛的部分结果，其余位置仍显示未确认，并记录停止原因。变宽 P5 路线暂不直接使用此补线入口。

当前补线使用 v5 交替调度：先重验原确认范围，新扫描位置轮流获得搜索机会，再交替处理新扫描和遗留区域。较大未确认面积优先分类；原确认范围内的小块缺口也继续检查。可能相交但尚无完整证明的位置仍显示未确认。历史版本按原算法回放，升级默认版本不会自动改写原文件。

固定模型在相同输入下“重新核验模型覆盖”时，先重新证明原确认集合，再搜索剩余范围。它利用上一份结果安排复算顺序，所有新确认仍从当前几何重新证明。如果预算不足而遗漏任何原确认范围，界面提示本次未接纳并保留原覆盖；可以重试或继续查看、保存原版本。新增确认总面积更大也不能抵消局部丢失。连续复算只保存一层提示，不逐次累积旧提示链；P5 变宽核验仍按原规则处理。

原目标建账与当前 P2／P3 已减少重复计算：建账复用单次任务中相同源面之间的分离计算，覆盖复算复用本次搜索的只读候选坐标。操作入口和参数保持，升级后正常生成、重新核验或补充规划即可使用；历史文件仍按保存的算法和停止边界完整回放。具体实测与验收范围见 [原目标建账与覆盖计算提速](../历史开发记录/原目标建账与覆盖计算提速_20261010.md)。

## 工作台操作

打开原方案，恢复到未补充的常规 v3 或严格 P4 路线，依次执行“核验模型覆盖”“补充规划”“核对保存”。历史记录可回看补充前与各轮结果；恢复补充前路线会同时恢复其同源覆盖。不要用图中线条变多代替覆盖报告，也不要把计算结束当作整个目标已覆盖。

验收应同时记录完整按钮操作耗时、预算遗留叶数／整数权重／原目标加权面积、新增确认面积与新增扫描见证面积、原确认集合损失权重。叶数会受细分影响，不能单独用于判断改善；原集合损失必须为 0。所有面积仍为名义模型面积，未定位像素及未知物理面积分别保留。

## 重复基准工具

从本工作区根目录运行，使用当前 `.venv`。输出目录必须是当前 `outputs` 内尚不存在的新目录；每次运行使用不同目录。

```powershell
.venv\Scripts\python.exe tools\benchmark_surface_coverage.py --output outputs\coverage_repeat_01 --project "E:\已有方案\planning.region.zip" --repetitions 3 --refine --replay --compare-legacy --require-p2-acceptance --require-gain
```

将 `--project` 替换为实际固定模型方案。工具完整打开并验证输入；输入若是已补充的 v3／P4，会使用已验证报告中的补充前路线。P5 变宽方案需先在工作台恢复原 P4 后另存。工具不启动相机、不改原方案，不发布新产品方案。

- 不指定 `--project`：只运行 128 和 2,048 面的首次覆盖、新 P2 复算与 v5 新球实验；新增种子是数值覆盖输入，不是 RGB-D 路线准入验证。
- `--refine`：对真实固定目标重复当前 P3，固定使用第一次当前 P2 接纳后的覆盖；若未接纳则使用原已验证覆盖。每次 P2 都独立从同一原证据起步。
- `--replay`：从保存资产逐次完整回放数值结果、每个 P2 原始候选和 P3 历史；包括未接纳及后续重复的 P2 候选。
- `--compare-legacy`：加入旧 P2／P3 v4，对相同固定起点交替执行新旧策略，分别保留全部结果。
- `--refinement-guide-assets`：可选指定一份覆盖资产目录，经完整回放及原集合保留检查后，作为所有 P3 重复的固定起点。
- `--require-p2-acceptance`：某次当前 P2 未接纳时明确记录失败；旧 P2 对照的拒绝仍按实际状态记录。
- `--require-gain`：某次真实 P3 没有接纳时，将该次明确记录为验收失败；仍保留数值结果与失败原因，并继续记录后续运行。

`result.json` 汇总全部运行、最小／中位／最大耗时、逐状态数量与面积、原集合比较以及输入／源码摘要。每次计算还有单独 JSON 和证据数组目录。`seconds` 是输入验证后的对应计算操作，`total_observed_seconds` 还包括统计和证据写入；两者均不能代替工作台整个按钮操作的计时。CPU 时间有助于区分运算量与调度等待。RSS 每 20 ms 采样一次，报告的是采样峰值。

真实 P2 的 `values`、`comparison` 和 `budget_change` 记录本次原始候选，`recalculation` 单列是否接纳、实际选定的证据摘要、各状态指标和原集合比较。`retained_previous` 表示候选没有安装；原始候选的损失照实记录，选定结果的损失必须为 0。固定引导单独保存在 `fixed_refinement_guide_assets`，不能把未接纳的第一次候选直接用于 P3 对照。

有前后证据时，`budget_change` 同时列出预算遗留叶数、整数权重及名义面积的前值、后值和差值，负值表示该指标减少。若新增确认增加而预算遗留也增加，应如实保留这两个结果；不能据单个指标宣称全目标已完成或所有性能均改善。

比较计算实现的优化效果时，优化前后必须使用相同原方案、作用模型和固定引导证书。报告分别说明“相对输入证书的变化”和“相对优化前实现的变化”。P3 增加扫描种子后，原来的球外结论需要重新分类；因此同预算下比旧实现减少遗留，也可能仍比补线前的遗留更多。P2 没有新增扫描点，其新增扫描见证面积为 0，新增确认来自原扫描证据的进一步计算。

P2 核心 30 秒、P3 每轮 4 秒、整个产品操作 120 秒及原累计几何预算保持不变。墙钟停止可能使重复运行取得不同确认集合，报告必须列出全部结果；不能只选最快或增益最大的一次，也不能按不同作用模型的面积相减。

## 查找耗时与失败记录

工作台默认将新记录追加到本工作区 `outputs/diagnostics/`，基准工具将它们隔离在本次输出的 `diagnostics/`。可用进程环境变量 `FEMTO_DIAGNOSTICS_DIR` 指定单次验收的其他目录。

`operations/<新目录>/operation.json` 包含状态、总耗时和分阶段汇总；`events.jsonl` 最多保存 512 个阶段事件，超过后明确记录省略数，汇总继续累计。Qt 中记录的是后台工作耗时；覆盖准备、原集合重验、范围外排除、新扫描搜索、保存与回读分别统计。`complete` 只表示操作结束，预算不足仍由覆盖报告明确标记。

原目标的实际几何构造记在 `target.construct`，外层 `generate.target_build` 或 `target.prepare` 还可能包含质量准备、摘要和资产工作。蛇形生成性能、覆盖计算性能、完整 Qt 按钮耗时分别记录，不能用其中一项代替另一项的前后对照。保存失败时查看 `native.save` 与 `portable.save`，确认是路线包还是便携工程未完成，并保留失败目录及原方案；新验收使用新的输出目录。

便携保存和回读新增三个细分阶段：`portable.manifest` 为工程清单编码与落盘，`portable.validation_manifest` 为回读时临时路线清单的写入，`portable.archive` 为 ZIP 压缩与落盘。清单写入使用小缓冲区，期间检查原取消、时间及工程大小上限；不需要设置新参数。取消或写入失败后原方案和核对状态保留，可直接重试；已经成功保存的原生路线包按错误提示中的路径保留，不能把它当作便携工程也已保存成功。

如果不同计算阶段同时出现明显耗时波动，记录当时可用内存、系统提交量与换页情况，再比较同源重复结果。清单临时内存、整个进程 RSS、完整按钮时间分别报告；内存测量工具本身会增加耗时，不能把带追踪的编码时间当作实际按钮性能。分段检查仍受操作系统调用的合作式边界限制，不是硬实时保证。

子叶分类的时间单独记在 `coverage.residual_recheck`。相关检查数、球外分类数、可能相交而提前停止的数量，以及组筛选节省的比较数，可用于区分几何未确认和计算尚未完成；这些诊断字段不提供覆盖资格。

新 P2 的已复证边索引记在 `coverage.retained_frontier`。P3 v5 将交替工作记在 `coverage.interleaved_search`，并记录新扫描批次、遗留分类批次和跳过的已变化单元；停止阶段可区分原集合复证、前置分类和交替搜索。若尚未进入交替搜索，不能据此判断某个交替频率优劣。

异常时同目录保留 `error.log`。局部重建子进程失败或取消后，`subprocess_failures/<新目录>/worker.log` 与 `failure.json` 保留退出码、耗时和内存观测，临时输入目录删除后仍可查看。超过 16 MiB 的日志只保留末尾 16 MiB，明确标记截断，不能当作完整日志；异常 traceback 上限 512 KiB。

诊断不记录函数参数、命令行、环境变量或原始帧，不参与覆盖资格和发布凭据。日志写入故障不改变原计算结果或掩盖原异常。当前不会自动重试，也不表示过去尚未定位的重建异常已经修复。

详见 [复算与诊断契约](../技术资料/覆盖复算调度与持久诊断契约.md)。这些检查属于软件与历史数据回放，原生 GPU、设备和物理精度仍需分别验收。
