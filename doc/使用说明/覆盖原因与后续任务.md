# 覆盖原因与后续任务

在规划工作台核验模型覆盖后，覆盖面板显示待处理原因种类。选择一种原因，可查看原目标中的面积、叶单元数量、涉及的参考像素和建议下一步。点击“定位”查看范围；点击建议操作进入现有核验、补充规划或恢复流程。

| 原因 | 建议处理 |
| --- | --- |
| 模型内已确认 | 保留；后续结果仍须重新证明原集合，无“手动确认完成”入口 |
| 质量排除或待检查 | 定位并检查参考深度与质量证据；存在真实缺失时补采 |
| 种子内球未触及 | 固定宽度常规或严格路线可尝试补充规划，仍须通过逐边检查、原集合保留和新增扫描见证 |
| 球内连通未确认 | 重新核验连通，不直接判为行距不足 |
| 细分到限 | 当前预算内重新核验；反复到限仍保持未知 |
| 目标构造未确认 | 检查原目标构造、映射与数值边界，不直接补线 |
| 预算内未处理 | 在原限额内重新核验；固定模型优先重新证明原集合，原结果通过保留检查后才替换 |
| 目标含未定位范围 | 在参考图定位，查看缺失、部分定位、数值或预算原因；三维面积未知 |

“重新核验”执行现有同输入计算，不从旧报告继承已确认状态，不提高预算，也不保证重复一次就增加覆盖。补充版本先显式恢复补充前路线和覆盖，再处理计算或补线任务。未补充的变宽版本在完成覆盖核验后，“未触及范围”进入独立的变宽补充规划；它会重绑整条链的宽度并重新证明覆盖，仅接纳原确认范围无损的实际新扫描见证。具体操作见[名义变宽模型与恢复](名义变宽模型与恢复.md)。

达到计算限额的全局停止信息也保留为核验任务，即使没有标为“未处理”的叶单元；零未处理面积不能替代原目标完成状态。

未定位任务按原台账列出具体像素原因。深度缺失/冲突和无网格范围进入参考图复核；目标建账预算范围检查计算进度，数值或部分定位范围检查几何对应。当前参考图定位功能可查看这些待处理范围，任务提示不会把全部未定位范围作为补采缺失。

选择“目标含未定位范围”，再从下方选择“无网格表面”“参考深度缺失”“深度冲突”或其他原因，点击“定位”。参考图只显示当前原因的像素；选“全部未定位原因”恢复总览。检查补采位置时分别查看观测问题，避免把预算范围混作实测缺失。历史页面可同样只读定位。

输入修改、记录切换或处理期间，操作入口禁用。原因查看和定位保留当前路线；软件计算失败、取消或旧结果迟到沿用现有保留机制。检查/补采任务只定位并提示，不直接启动相机、修改数据、删除模型或生成机器人运动。

## 导出和历史回读

规划页的“导出后续任务”保存 JSON 报告，包含原目标标识、原目标/计算修订/覆盖证书/数值路线摘要、稳定任务标识和原因定位选择器。导出在后台进行，写完临时文件并完成检查后原子替换；发布前检测到取消或写入失败时，保留目标路径中的旧文件。

任务采用 `femto-coverage-next-step-tasks-v1`，只是经验证证据的派生建议。它不是覆盖证书或后续规划输入，没有导入覆盖结论的入口；`execution_ready=false`、`physical_accuracy_verified=false`。未定位面积为 `null`，不以零代替未知。每类面积来自原目标根单元面积和精确四叉树深度权重；不同原因涉及的像素可重叠，不能把各类像素数量相加当成选区像素数量。

原生与便携工程继续保存既有目标和覆盖证据，不新增每叶任务列表或重复大数组。打开工程、独立回读验证成功后，重建同一任务视图；旧版本无覆盖证据时不补造任务。历史页显示任务建议与范围，只读，不提供执行或导出入口。任务没有“勾选完成”状态，只有重新计算后的证据才能改变原因和覆盖结论。

## 当前验证范围

定向验证包含原因分流、分区/面积/像素统计、未定位面积语义、任务绑定失效、分区篡改拒绝、取消与失败写入保留、后台导出、只读历史和便携回读任务一致性。测试日志保存在 `outputs/functional_iteration_20261011/`。Qt 自动化使用 offscreen，不能证明真实相机采集或原生 GPU 视窗效果。
