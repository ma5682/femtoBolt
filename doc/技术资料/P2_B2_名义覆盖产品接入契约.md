# P2 / B2 名义覆盖产品接入契约

本契约描述当前工作台的可选覆盖核验。沿用 [B1 几何与证明规则](P2_B1_名义覆盖验证契约.md)，优化计算顺序并接入显示、保存与历史回读。P2 核验不会增加、移动或删除路线点；显式补线由独立 P3 工作流处理。

## 版本与输入

| 对象 | 当前版本及职责 |
| --- | --- |
| 路线生成器 | `quality-constrained-surface-v3`，既有整边、质量、宽度和连接准入不变 |
| P1 台账 | 原 `planning_context` 的 `schema / revision / target` 三字段契约不变 |
| 覆盖证据 | `femto-model-surface-coverage-prototype-v1`，JSON 清单与 NPZ 数组分开保存 |
| B1 算法 | `exact-anchor-ball-subedge-coverage-v1`，保留旧调度用于复算 |
| B2 算法 | `layered-anchor-ball-subedge-coverage-v2`，首次覆盖及 P5 沿用 |
| 同输入固定模型复算 | `retained-first-anchor-ball-coverage-v1`，先重验原集合再搜索剩余范围 |
| 产品路线绑定 | `femto-accepted-v3-coverage-source-v2` |
| 方案扩展 | 可选 `coverage_evidence`，不把覆盖元数据塞入 P1 台账或 v3 路线 |

`coverage_certificate.evaluate()` 默认仍为 v1；工作台显式选择相应算法。证据回读按保存版本分派，不能仅替换算法标签。产品只接纳完整关联的覆盖资产；独立 B1 归档仍用原入口读取。固定模型复算核对完整 domain、route、扫描种子及模型绑定，使用上一份输出作为不可信提示，重新证明原集合、重新分类，再通过本轮复证边索引搜索未知区域。任何原确认整数权重丢失都拒绝安装。完整调度见 [复算与诊断契约](覆盖复算调度与持久诊断契约.md)。

覆盖种子仅来自已接纳的非零扫描边端点。连接段不自动赋予作用效果。名义球有效宽度仍为 `(0, 1000] mm`，半径为宽度的一半；数值锚点位移从内球半径扣除。源几何保持 W0 / RDF / 米，规范顶点、半像素裁剪、正长度共享子边与同球父链判定沿用 B1。面积采用 P1 原单元的名义面积乘细分权重，不能声称为物理面积误差界。

物理中心偏移、配准及标定不确定性仍为 `null`。`execution_ready=false`、`physical_accuracy_verified=false`；原始完整场景 RGB-D、源 Mesh 与旧路线都是只读输入。

## 计算调度与预算

先处理原目标单元，再按广度优先顺序细分边界。已满足同球包含的单元在线建立精确公共子边邻接，立即传播证明，不必等待全域细分结束。每个单元最多尝试按近似距离排序的 8 个候选球；排序只决定尝试顺序，确认仍须通过原包含与连通判定。省略候选只产生未确认，不证明不存在其他覆盖。

包围盒到内球的距离筛选逐次向外舍入，仅用于安全排除。每 128 个原单元触发连通处理，每批最多处理 1,024 个证明队列项；阶段末在总预算内排空。策略完整绑定在 `inputs.search_policy`，证据元数据使用副本，不得修改进程共享策略。

| 项目 | 预算 |
| --- | --- |
| 原目标输入单元 | 200,000 |
| 新增叶单元 | 200,000，按相对原目标的新增量计数 |
| 最大细分深度 | 默认 4，显式最高 8 |
| 已绑定种子 / 输入种子记录 | 20,000 / 400,000 |
| 包含与距离比较 | 1,000,000 |
| 邻接比较 / 证明节点 | 各 1,000,000 |
| 覆盖计算时间 | 内核 / CLI 默认 45 秒；工作台核验显式使用 30 秒，合作式检查，之后仍有资产整理成本 |
| 覆盖清单 / 数组 | 1 MiB / 256 MiB |

空间候选、包围盒比较另记指标，不冒充上述包含比较；新增 `original_cells_visited`、`cell_candidates_deferred`、`aabb_ball_comparisons`。数组限制不是 Python 进程内存硬限，工程峰值独立记录。P1、区域工程及原 v3 的预算继续生效。

工作台原生与便携包合并保存仍共用原有 120 秒任务期限。界面核验用 30 秒覆盖预算，为输入核对及两次保存复算留出时间；没有提高保存或几何准入期限。较短预算产生的剩余目标继续显示未完成，保存步骤与回读仍严格一致。

保存停止步骤和阶段，回读按同一步骤边界复算，不以第二次运行的墙钟时间截断。预算耗尽或深度到限保留原分区，返回 `calculation_incomplete`。每个原单元的叶权重之和仍须精确等于 1，多球确认的叶面积只累计一次。

## 结果与显示

主界面并列显示路径、原目标几何、模型覆盖三个摘要。路径连续、原目标已定位与覆盖已确认分别陈述。无证书显示“未进行此项核验”；计算未完成、原目标未定位或质量待核验都不会显示为完整覆盖。

| 状态 | 色层及解释 |
| --- | --- |
| 模型内已确认 | 绿色，同球整面包含与连通证据成立 |
| 质量排除、待检查、目标构造未确认 | 紫色，保留原目标需求 |
| 内球未触及、球内连通未确认、细分到限 | 橙色，不能解读为已证明未覆盖 |
| 预算内未处理 | 灰色，保留分母与原单元身份 |
| 目标含未定位范围 | 紫色，仅在参考图定位；不补造三维位置或面积 |

三维显示是已验证叶单元的浮点近似，并保留原面编号。源 Mesh 与拾取索引不替换，三维色层不参与计算。参考图采用像素汇总：一个像素的所有关联叶均确认且没有未定位剩余时才能显示绿色；像素包含多个原因时保留全部原因位，由优先级决定总览颜色。因此部分叶确认不保证对应像素整块变绿。

覆盖色层与区域、几何检查、路线叠层互斥。可按原因筛选和定位；未知位置切回参考图。覆盖显示期间停止播放。历史页只显示已经完整核验的证据，不提供重新计算按钮；再次安装同一模型也同步重置图层控件，避免勾选状态与画面不一致。

## 输入变化、取消与安装

覆盖计算在后台使用冻结输入。结果返回时除既有请求代次、模型及 P1 修订外，还比较发起时的完整方案摘要，防止相同输入下另一条路线被旧任务覆盖。

纯导航和名称备注不改变计算身份。参数变化禁用原证据的使用与显示；恢复完全相同的输入后可恢复原证据，保存前仍须重新人工核对。选区或源数据变化遵循既有失效链。成功核验生成新的待保存方案，清除旧“已保存”与人工核对状态；核验本身不发布文件。

取消、失败或迟到结果不替换原路线和证书。安装时先准备全部显示数据，再更新模型缓存，避免显示准备失败后只替换部分缓存。自动草稿只恢复标记与参数，不承诺恢复未正式保存的路线或覆盖。

## 保存、回读与迁移

产品路线绑定覆盖数值路线内容、各类报告、算法参数、原点、P1 上下文及源几何/区域身份；可迁移文件路径、`route_diagram_status`、`data_layers` 不进入该覆盖绑定。来源文件仍通过方案或轨迹的文件清单和哈希独立核验，不能靠修改路径绕过几何校验。

原生保存包包含独立 `coverage_certificate.json`、`coverage_certificate.npz`、`model_coverage_report.txt`，`trajectory_files.json` 可选记录 `coverage_evidence`。便携 region ZIP 同时绑定方案中的元数据与这两份覆盖资产。元数据缺失、文件缺失、孤立资产、缓存不匹配或重新计算外层哈希的伪证据均拒绝接受。

同输入优先复算额外保存一层 `recalculation_hint_coverage_certificate.json`／`.npz`，提示与输出数组合计不超过原 256 MiB。连续复算只带上一份输出，不递归保存旧提示。提示仅决定分区和待重验路径，独立回读仍从当前几何重现新证据；缺件、孤立或递归提示拒绝。未使用此算法的旧包不要求新增提示文件。

staging 写入后完整回读复算，成功才原子发布。回读先验证文件集合、大小、数组头和类型，再用受信任的原目标、种子、作用模型和路线关联重算证明。不能只核对 SHA 就把缓存当作已验证结果。保存或读取的取消沿用既有事务与版本保护。

便携工程迁移后再次导出，新的来源快照和 `data_layers` 来源说明同步更新；原路线与证书保持原值。v3 路线回读仍执行完整字典比较，没有忽略数值字段或放宽复算断言。

旧包没有证书时保留旧路线并显示未核验。已有 P1/v3 的方案可以直接核验；更早的方案需先生成带原目标台账的新路线。回退通过历史打开旧版本或“基于此版本修改”建立新版本，不改写历史证据。

研发 CLI 保留 `evaluate / verify`，新增 `--algorithm v1|v2`，默认 v1。`verify` 从归档读取算法和路线绑定版本：

```powershell
.venv\Scripts\python.exe -X utf8 tools\check_nominal_coverage.py evaluate --algorithm v2 --project <P1方案.region.zip> --output outputs\coverage_b2_new
.venv\Scripts\python.exe -X utf8 tools\check_nominal_coverage.py verify --project <同一输入方案.region.zip> --archive outputs\coverage_b2_new
```

工程实测、回归日志及未通过的开发中间证据见 [B2 交付记录](../历史开发记录/名义模型覆盖工作台接入_P2_B2_20261009.md)。


## 显式索引覆盖试验版本（2026-10-14）

`indexed-anchor-ball-subedge-coverage-v3` 当前为显式算法选择，尚不替换工作台首次覆盖默认v2。同规范拓扑边和源面内精确直线键上的区间，用AVL树按有理数下界排序，节点维护精确最大上界；查询只排除上界不超过当前下界或下界不小于当前上界的区间，正长度微缝及点接触不闭合。返回正长度重叠按旧插入顺序建立邻接，同球锚点连通与整单元包含规则不变。

端点使用规范有理数的整数分子/分母交叉相乘；每个查询节点计入原邻接上限，插入节点进入确定性步骤和取消检查。新策略写入inputs.search_policy与摘要，策略类型/字段/参数变更拒绝。保存与回读按metadata.algorithm调用对应引擎，旧v2路径原样保留，不能重标算法继承旧证明。

新旧有限预算确认集合须在共同目标分区比较，验证lost_weight_units=0后才能作为候选改善结果；任何时间/工作上限未处理状态仍保留未知。仅在验证后推广默认，不将单个样本视为全部产品场景完成。
