# 局部表面计算与导出提速（2026-11-03）

本轮保留规划边去重、过滤后连通分量计数复用、同卷 ASCII 暂存和默认关闭的细分计时。没有改变原始数据、选区、模型密度、治疗头宽度、几何门禁或算法版本。邻域局部收集和三角形直接复制两个试验没有显示稳定收益，已经撤回。

四轮关闭细分计时的完整对照已通过，重建约减少 2～3 秒；路线生成、保存及完整自动处理尚未证明稳定提速，也未达到十秒目标。最终回归与静态检查结果见文末。

## 范围和基线

- 生产改动为 7 个已有模块及 3 个新辅助模块；不重写规划器，不修改 UI。工作区原有未提交改动保留。
- 本轮起点已经包含 10.001 mm 负例空间格、3.5 mm 第二级实测点见证、三顶点整数去重和紧凑三角缓存。不能把上一轮约 40～48 秒降到当前约 27 秒的差异归入本轮。
- 实现快照、日志、对照产物位于 `outputs/surface_runtime_20261103/`。`baseline/` 为本轮起点的 389 个生产 Python 文件，`candidate_final/` 为最终 392 个文件；各有内容摘要，基准结果另保存所用源码清单。
- `phase1/` 为埋点与规划边去重版本，`phase2/` 增加统计复用和同卷暂存，`phase3_trial/` 为后来撤回的两个小试验。试验快照供复查，不是默认实现。

## 保留的实现

### 规划边去重

`femto/geometry/mesh_edges.py:unique_edge_rows` 统一边端点去重。两个端点为整数且都位于 `[0, 2³¹)` 时，以 `(u << 32) | v` 排序去重，恢复原 dtype、字典序和计数；其他形状、范围或类型沿用 `np.unique(axis=0)`。无向边由调用方先排序，辅助函数也保留有向边的顺序含义。

`quality_constrained._mesh_edge_context` 使用该函数；`surface_patches._unique_edges` 复用同一实现，原三顶点去重保持。边界、邻接、退化输入及无有效边界的报错均有差分测试。没有改写 Trimesh 的水密性或绕向公式。

### 连通分量计数复用

`filter_small_components` 仍实际聚类、过滤完整小连通块、移除孤立顶点并计算法向。完成后，操作内的 `ComponentReuse` 保存 `counts[keep]`，绑定同一个网格对象、线程及完整顶点/三角面内容 SHA-256。

`scene_reconstruction` 将该凭据传到 `export_mesh_formats`。导出重新核对实际数组后才复用；顶点或拓扑通过 NumPy 别名被修改、换网格、换线程、摘要准备失败或没有凭据时，继续原 `cluster_connected_triangles()`。凭据不读取外部报告，不作为跨请求缓存。摘要不宣称支持其他线程并发修改同一网格的事务一致性。

Trimesh 构造、边统计、`is_watertight` 和 `is_winding_consistent` 保留原调用。三面同向共边仍报告非水密、绕向一致；没有替换为“同向最多出现一次”的不同规则。

### 同卷 ASCII 暂存

Windows 原生读写优先使用目标实际卷下的 `FemtoNativeIO/<workspace_id>/`。检查目录为 ASCII、卷号与目标已有父目录一致，并实际尝试创建临时文件；不可用时回退原工作区缓存。临时文件名由目标路径摘要和独立随机后缀组成，不带用户中文文件名。

原生写入成功后先 `os.replace`，失败则保留原移动/复制回退及异常传播。点云写入和几何读入均清理本次临时文件；写入返回失败或抛出异常不会发布半成品覆盖原目标。读取暂存复制失败也清理残留。不是整个方案发布的替代事务，原上层发布和回滚规则保持。

当前机器回退目录本身为 ASCII；没有新增中文用户目录、不同目标系统或任意挂载环境的实机兼容认证。普通 PLY/OBJ/GLB 回归与局部方案保存回读分别验证；单帧纹理仍沿用原独立纹理导出实现。

## 细分计时及实际热点

所有新增观测进入已有 `performance_detail`，默认关闭，只在诊断时按批/阶段向内存聚合，操作结束后输出。不逐邻点或逐子面写日志，不进入几何报告、目标数组和回放摘要。关闭时不调用新增内部计时器。正式性能对照没有开启 `--detail`。

- 完整邻域：查询输入准备、原生搜索、索引展开与坐标差、平方距离、法向收集、高度算术/保护带、分组归约和精确回退。
- 目标台账：批量平面准备、裁剪、投影、子面深度/面积状态判断、扇形剖分/小数组，以及外层列表追加；记录实际调用、已追加子面和预算拒绝量。
- 导出：PLY 原生写入、发布、Trimesh 构造、边统计、连通分量及水密/绕向读取。

`detail_phase1` 与 `detail_phase2` 的实采诊断如下。这是有埋点的两次阶段测量，不作为正式整体加速比；父子阶段不能重复求和。

| 导出子步骤 | 复用前 / 秒 | 复用后 / 秒 |
| --- | ---: | ---: |
| PLY 原生写入 | 0.219 | 0.242 |
| PLY 发布 | 0.0469 | 0.00079 |
| Trimesh 构造 | 0.028 | 0.017 |
| 边计数 | 0.585 | 0.675 |
| 连通分量统计/内容核对 | 2.572 | 0.0116 |
| 水密和绕向读取 | 0.439 | 0.453 |

复用后另有 0.0066 秒过滤后摘要绑定；实际记录 1 次复用命中、无聚类回退，5 次同卷暂存路径和 4 次原子替换。此样本跨盘发布仅占约 0.05 秒，不能据此把跨盘 I/O 称为主要瓶颈。

目标生成的第一次细分诊断：批量裁剪 3.072 秒、批量投影 0.638 秒、子面状态判断 1.534 秒、剖分/小数组 2.111 秒、外层追加 0.157 秒。裁剪父阶段总计 4.238 秒，已经包含批量裁剪和投影，不能再相加。

原目标仍为 237306 像素，但实际子面函数调用 62759 次，已处理并追加 62758 个像素组、199989 个子面；最后一组的 12 个返回子面触及预算而未追加。所有调用共返回 200001 个子面。批缓存计算 190400 个候选，逻辑已处理裁剪计数为 190330；预计算缓存与已计费访问量分别记录，不用全选区像素数替代实际调用量。

完整邻域诊断仍是 121996 个查询、10084 批、214740039 对邻点、91 个精确回退，结果为 278625 个第二层点。`detail_phase1` 完整原生查询约 13.613 秒，其中搜索 3.841 秒、索引展开和坐标差 3.761 秒、原合并算术阶段 4.775 秒、归约 0.131 秒、精确回退 0.133 秒。原合并算术阶段包含平方距离和法向收集；最终细分字段将它们单列，不能直接比较不同字段范围。

最终源码的独立点云诊断 `cloud_detail_final/result.json` 再次得到 278625，实际查询/邻点/回退量相同。完整点云检查 16.859 秒，其中完整原生查询父阶段 13.211 秒；子步骤为输入准备 0.155、搜索 3.783、索引展开与坐标差 3.611、平方距离 0.544、法向收集 1.359、高度算术与保护带 2.676、归约 0.126、精确回退 0.126 秒。预检 0.456 秒，说明继续优化预检无法解决主要耗时。这是诊断阶段数值，不能与正式重建总时间相减推断未记录部分。
