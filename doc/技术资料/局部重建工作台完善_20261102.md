## 验收范围

1. 定位与未来接口：CPU 可运行；保存 W0/RDF/米、XYZ/法向与分段；继续标注 `execution_ready=false`。
2. 交互：采集—涂抹—模型与路线—保存四个可见阶段；主要按钮、擦除/撤销/清空、折叠参数；模型与问题可见。
3. 局部链路：选区提交前不启动主重建；逐帧投影筛选后融合/建面；保留原始 RGB-D 和完整目标意图。
4. 输入：1/2/多帧、无效位姿/数据、部分帧不可用；分支使用实际可用帧数，失败与排除明确记录。
5. 路线：固定作用宽度、独立行距与沿线取点；保留几何/边界/断点约束及历史算法语义。
6. 一致性：编辑/参数变更使依赖结果过期；取消/旧任务不得回写；保存模型/选区/路线同源。
7. 性能：准备、映射、配准、融合、建面、生成、呈现、保存与自动处理总耗时；首次与重复运行分开，不计人工等待。
8. 计算范围：原始/深度有效/局部保留/实际输入数量，网格规模；小、大、分离选区对照。
9. 回读：原始来源、校准位姿、掩码、范围、模型、路线、质量、参数与版本可追溯；原生与便携方案独立核验。
10. 异常与测试：缺失、遮挡、曲率、边界、取消、迟到结果、重试、重选及重开；真实数据存在时优先使用，合成明确标注。

## 已实施修改与当前证据

- 四个可见阶段保留六个内部语义目的地及原门禁。默认直接开始采集、采集框可选；重建前清空可撤销，周边参数折叠；重建后原始选区在后台核验并直接进入路线准备，不再额外确认同一选区。三维查看时底部操作保留，模型检查按钮不再重复弹窗。`ui_tests_v4.log` 中 55 项通过；最终 1120×740 离屏画面已逐张检查，覆盖采集、涂抹、参考图缺口检查、三维模型、路线及保存。按钮和必要问题提示可见，不能由此推断真实相机或 GPU 呈现通过。
- 新增 `pipeline/local_region_inputs.py`：只做逐帧深度准备和选区映射，不建立全场景几何。根据实际有局部有效深度的帧选择单帧或 TSDF；深度数组复用于建面/积分和实测支持检查。每帧记录原始非零/范围内/局部保留/实际输入像素与排除原因。零贡献时保存原始掩码和缺失统计并报错。
- `LocalProcessing` 单帧也验证位姿；验证或局部筛选未完成时计数使用未知，避免先写成成功。最终处理报告记录实际方法及贡献帧，离线子进程结束时不再用旧进度记录覆盖这些结果。
- 多帧输入只有一帧对应选区、零局部表面、非法单帧位姿、原始哈希不变及完整意图保留已有行为测试。`frame_branch_tests.log` 23 项通过；`target_frame_regression.log` 80 项通过；补充报告断言发现并修复旧快照覆盖问题，`diagnostic_final_tests_v2.log` 中新报告断言通过，另一个旧异常测试夹具缺失位姿已补齐，`offline_final_tests.log` 12 项通过。
- 320×240 合成大选区发现原默认四分点门户图超过 200000 搜索边预算。对新建局部模型、固定宽度模式且选区至少 5000 面，显式记录已有 residual-v2 排布与 lazy-v2 中点门户的组合，保留完整网格、扫描取点、作用宽度及质量门禁；旧版本回放使用保存的组合。该路径不做额外访问重排，路线顺序可能不同。`dense_probe/summary.json` 已完成生成、原生/便携保存和独立回读，但生成约 23.42 s、保存约 17.65 s，未达到十秒目标。
- 性能剖析定位大选区的目标建账和沿面连接检查。目标遮挡检查改为在源三角面不能排除遮挡时才准备多边形包围盒；顺序、比较次数、预算和精确回退不变。上述 80 项包括新旧目标数组、预算前沿、遮挡、几何和回读回归。

## 性能验证口径

当前开发机 CPU 为 Intel Core Ultra 7 251HX（18 核/18 逻辑处理器），系统报告可见内存约 15.38 GiB；原始设备记录为 `cpu.json` 和 `memory.json`。使用项目 `.venv`，没有使用 CUDA。现有 `datasets` 没有可用采集目录，因此本轮标为合成标定平面，不能代表真实相机、人体或 ARM 性能。

`tools/benchmark_region_workflow.py` 对 1/3 帧、小/大/分离选区分别重复三次。重建在进程内调用，路线/保存使用实际 Qt 后台流程，并独立回读便携包、核对完整掩码及原始源文件哈希。它不含相机采集、人工查看、离线进程启动或实际 GPU 呈现；首次指每组第一次测量，不声称系统冷缓存。失败样本记录失败阶段而继续矩阵，不缩小原要求。

基线来自修改前源文件快照。规划模块补入的快照记录在 `baseline/planning_snapshot.json`；其中 `planning_revision` 仅移除了本轮新建的密集局部默认组合，其他既有算法代码保留。此说明避免把重建的基线误称为已有 Git 提交。

## 局部计算统计

每帧原始非零深度为 76800 像素，小/大/分离选区分别仅向主要建面或积分输入 5027 / 19261 / 12968 像素；多帧均使用真实测试位姿映射，输入范围与掩码形状相符。单帧输出三角面为 9808 / 38008 / 25370，三帧为 556 / 2244 / 1442。原始图像未裁剪覆盖，目标掩码回读逐像素一致。

此外三帧只有一帧对应目标的测试继续核对发布、历史和回读：模型按一帧建面，历史保留三帧接纳数量，同时单独记录一帧实际贡献，避免把重建数量误显示成采集数量。

## 本轮收尾验证

三帧只有一帧贡献的完整发布测试曾发现历史数量被实际贡献数覆盖。现已分别保存接纳数量与贡献数量；`one_contributor_capture_final.log` 的 30 项和随后 `presentation_regression.log` 的 41 项均通过。早期 `integrated_regression.log` 为 124 项中 123 项通过、这一项失败，保留该日志供追溯，不能将其写成 124 项全通过。

模型检查读取原始可选采集框失败或文件损坏时仍保持失败反馈；仅在可选采集框不存在且存在通过绑定校验的完成记录时，使用该记录重新评估原涂抹目标。局部模型自动接入规划后按选区调整视图缩放。上述 41 项覆盖这两项改动和 1/2/3 帧以及 3 输入、1 贡献的完整流程。

本次受影响的旧固定宽度布局、门户、访问顺序、目标建账回放及历史目录另做定向回归：`final_version_regression.log` 的 47 项通过，用时 19.964 s。保留原版本实现和已存版本选择，不将新密集模型默认组合套用到旧方案。这不是仓库全部算法与全部历史文件的全量验收。

目标建账的同输入交替测量见 `target_hints_comparison.json`。三次修改前后中位耗时为 7.691 s / 6.650 s，约降低 13.5%；目标数组字节、统计及固定预算前沿相同。该收益只属于这一计算阶段，完整流程的前后范围仍以上表为准，不能据此声称端到端同幅提速。

`ui_measurements.json` 单独记录固定参考图加载和离屏控件绘制。1/3 帧来源各加载三次；控件绘制使用 Qt `grab()` 计时，不含截图编码写盘。这些值不代表实际显示器、原生 GPU 或现场交互延迟。最终画面脚本按真实视图分派处理参考图和三维显示，避免用三维渲染覆盖参考图检查画面。
