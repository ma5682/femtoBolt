# 目标面积按需计算与路线保存提速

本轮根据“中间显示可以简化，最终保存路线坐标正确即可”的要求，将可选面积分析移出新建路线的日常生成、保存及重开流程。实际路线仍使用原规范几何、采样、整边支持和质量规则；没有用渲染抽样点替换路线点。

## 当前行为

- Qt 新建路线显式使用 `surface_workspace.generate(..., defer_target=True)`。只保留绑定输入和待计算状态，省去目标台账的三角形去重、像素候选索引、遮挡裁剪、深度子片检查和面积扇形构造。路线本身所需的深度、有效域、作用宽度和选区检查继续执行。
- 原生保存和独立便携重开依然验证完整路线。待计算目标独立验证完整输入、状态、数组及修订，无需重建未请求的面积细分；两种保存间原有的同次验证会话仍有效。
- 界面明确显示“面积与覆盖尚未计算”，提供“计算面积与覆盖”。按需计算沿用原 100 万候选、20 万单元、50 万成对检查及 45 秒构建预算；随后调用原覆盖检查，预算退出仍保留未知和部分结果。
- `target_preparation.prepare()` 返回重新绑定的方案，不修改调用方旧方案；旧方案及待计算资产另存为来源记录。显式严格构造先准备完整目标，再执行原构造及恢复逻辑。取消、失败和输入变化不会安装部分结果。
- 低层 `generate()` 默认保持原完整目标语义；已有完整目标、分块目标及覆盖证据继续独立重放，不自动改成待计算。

## 格式与坐标

新目标 schema 为 `femto-original-target-surface-deferred-v1`，保留原 `planning_context` 三字段、JSON/NPZ 名称、数组清单和大小限制。三个工作预算及时间预算均为零，`metrics.stop_reason=deferred_by_request`，构建计数为零，面积叶数组和重复面映射为空。这里的空映射表示未执行去重，不能据此声称源面没有重复。

原始完整场景 RGB-D、完整规范源几何、选区、参考深度、内参及质量域保持。已知的参考深度缺失、量程外和无源像素仍记录；其他选中像素保持未处理，目标总面积未知。待计算状态即使通过 `reproduce=False` 读取，也必须按轻量规则重新生成并比对，不能通过重新封装摘要升级为已定位或已覆盖。

路线仍为原 `quality-constrained-surface-v3`，W0 / `world_rdf` / 米、坐标与法向、原面编号、点序、扫描/连接角色和断点全部保留。按需准备面积只更新目标及可迁移来源绑定，不重新生成路线。精确比较的是软件输出与原算法的一致性，不是人体、相机或实物误差验收。

新程序兼容旧目标；旧程序不认识新 schema 时会拒绝读取新待计算工程，需要当前源码版本。没有重打 EXE、更新共享运行时、提交或推送。

## 验证记录

新增后端与 Qt 专项 9 项通过（72.349 秒）：连续/分离区域的原算法对照、原生/便携保存和独立重开、按需补建与覆盖归档、严格构造及恢复、未知状态重封装拒绝、修改坐标和参考深度拒绝、取消和运行中输入变化、原始深度缺失原因，以及实际 Qt 的生成→保存→重开→请求覆盖流程。构造器拦截验证日常流程不调用面积构造；旧路线、点序、分段和检查报告逐项一致。

首次新增测试运行 8 项时有 1 个测试夹具错误：测试将字符串来源路径直接调用 `read_bytes()`；生产功能未报错。改为 `Path(...)`，增加严格构造恢复用例后，9 项通过。没有删除断言或放宽几何门槛。

两份按需结果又分别在新进程中完整打开便携工程、读取原生路线，并拦截目标面积构造器以确认没有隐式补算。每份 5464 个路线点、点序、统计和缺口报告均与 A1 一致；导出的 `trajectory.csv` 与 A1 逐字节相同，软件坐标差为 0。记录为 `B1_export_verification.json` 和 `B2_export_verification.json`。

系统其他负载没有被锁定；四轮采样的最小系统可用内存为 622.21 / 6.18 / 307.61 / 266.17 MiB，进程采样峰值为 736.40 / 693.79 / 692.70 / 735.67 MiB。尤其 B1 重开存在内存压力，不把采样峰值当作内存硬上限，也不把个别阶段波动归为几何算法改善。

证据目录为 `outputs/target_on_demand_20261104/`：`comparison.json`、各轮 `result.json` / 日志、`measured_code.json`。运行器逐轮核对全部生产 Python 和基准脚本的字节摘要，确认计时期间代码没有变化。
