# 单机数据访问与文件生命周期设计

面向当前工作台维护者。目标是保留原始数据与核验机制，先从历史管理接入统一文件接口和 SQLite，再按实测瓶颈优化。本文区分当前实现和待实现设计，不涉及未接入的机械臂、底座或治疗头控制。

## 当前读写链路

| 链路 | 当前入口 | 已有约束 |
| --- | --- | --- |
| 原始采集 | `local_capture` → `RawFrameWriter` → `scan_session` | RGB-D 写入回执与跟踪帧号、时间戳对应 |
| 离线重建 | `local_offline.LocalOfflineJob` → 重建管线 | 子进程预算；原始源摘要核对；结果发布凭证 |
| 规划计算 | `surface_workspace.generate` | 选区、参考深度、几何和参数捕获完整修订 |
| 原生方案保存 | `surface_workspace.export` | 保存已生成路线；目标与覆盖证据绑定 |
| 便携方案保存 | `region_project.save_project` | 暂存、资产摘要、版本核对，再发布 ZIP |
| 便携回读 | `region_project.open_project` | 路径/大小限制、来源绑定、资产完整性及数值回放 |
| 历史发现 | `local_history.scan_history`、`catalog.scan_saved_versions` | 读取目录、JSON 索引并核验；打开仍核验 |
| 历史查询 | `history_store.HistoryStore` | 扫描结果以集合事务刷新到 SQLite；参数化搜索、分页和版本关联 |
| 采集历史隐藏 | `local_history.set_records_deleted` | SQLite 保存隐藏状态，不删除文件；首次写入一次性导入旧 JSON |
| 自动草稿 | `planning_drafts.Journal` | 保存标记与参数，不能替代源几何或已保存路线 |

现有 `io_utils.write_json_strict` 已提供唯一临时文件、原子替换及可选 fsync。不要重复编写另一套 JSON 写入器。现有 `publication.json` 是采集结果的发布依据，不能用新增数据库字段绕过它。

## 数据生命周期与留存清单

以下是当前工程的技术留存规则，不是临床法定保存年限。当前不启用自动删除。

| 数据类别 | 典型位置 | 权威用途 | 可否重新生成 | 当前处理 |
| --- | --- | --- | --- | --- |
| 原始 RGB-D、标定、帧时间戳 | `datasets/scene_*` | 采集证据 | 不可补采成同一证据 | 不修改、不自动清理 |
| 跟踪位姿、参考位置、扫描范围 | 会话 `derived/` | 建模/坐标来源与任务绑定 | 部分理论可重算，但依赖当时算法与输入 | 被模型引用时与模型一起保留 |
| 派生建模输入 | `derived/local_posed` 等 | 参与重建的精确输入 | 有条件可重算 | 未建立完整引用检查前不得清理 |
| 最终网格、参考图、深度、重建报告 | `outputs/complete_demo_*/reconstruction` | 选区和规划的绑定依据 | 理论可重建，但不保证逐字节相同 | 有方案引用时必须保留原版本 |
| 原目标台账、覆盖证书、算法版本 | 规划资产目录或便携 ZIP | 保存结论的核验依据 | 只能按对应版本与输入重放 | 与方案版本一起保留 |
| 原生/便携方案 | `surface_paths/`、用户指定 ZIP | 已保存方案与版本 | 不能拿新算法结果替代旧版本 | 不覆盖已有版本身份 |
| 工程解包目录 | `outputs/region_workspaces` | 加载、编辑及原生导出的工作空间 | 仅纯解包内容可从 ZIP 重建 | 可能含未保存草稿或新导出，不能整目录视作缓存 |
| 标记草稿 | `outputs/planning_drafts` | 未保存编辑的恢复 | 丢失后通常不可恢复 | 用户确认保存或放弃后才可清理 |
| 预览缩略图、渲染缓存 | 按当前模块实际位置 | 显示加速 | 可重建 | 后续可按容量管理，不作为几何依据 |
| 临时写入、暂存目录 | 目标目录附近的临时文件 | 未发布操作 | 依操作状态判断 | 先恢复/审计，不凭文件名或年龄删除 |
| 历史索引 | `outputs/history_metadata/history.sqlite3`；既有文件目录索引仍保留 | 查找入口 | 文件扫描索引可重建；隐藏状态不可从资产反推 | 集合刷新保留隐藏状态；通过备份 API 备份数据库 |
| 故障与发布报告 | 操作诊断、publication、processing 报告 | 失败分析、解释资产状态 | 不一定能重现 | 当前保留，未来单独定义保留策略 |

“可重建”不等于“可以立即删除”。必须同时满足没有活动任务、没有独有编辑、没有外部引用、源包仍完整、已验证恢复方式。

## 权威来源

1. 原始清单、发布凭证及方案包继续决定数据来源、几何和证据是否有效。
2. SQLite 第一阶段是可重建的历史检索索引，不是几何结论的权威来源。
3. 隐藏/恢复属于用户业务状态，应迁移为唯一权威存储，不能与 JSON 双向盲写。
4. 迁移旧隐藏索引必须在同一数据库事务中记录迁移完成标志；失败不消费旧状态。
5. SQLite 中的“曾核验通过”仅表示索引时的观察。打开时仍执行当前来源与资产核验。
6. 文件被外部移动或修改后，索引可过期；错误必须可见，不能沿用旧核验结果。

## 接口与实施边界

### 文件资产接口

`asset_storage` 在已有低层文件工具之上提供统一的小型元数据发布和资产定位接口：

- `LocalAssets.locate(location)`：按 `root_id`、`relative_path` 定位，规范化后拒绝越界。
- `LocalAssets.describe(path)`：生成存储根、相对位置、大小和摘要等资产描述。
- `publish_json(target, payload, check)`：同目录准备、摘要核对、发布，保留独立操作收据。
- `inspect_publication(journal)`：只读报告中断状态。
- `recover_publication(journal)`：显式恢复；重新核对操作归属、旧目标和准备文件摘要。

历史方案登记、区域库索引、采集任务首次绑定已接入。任务绑定使用 `create_only=True` 保证协作调用只建立一个绑定；区域库原位置参数 `commit` 保留，并透传取消检查。可选 `commit` 只负责最后替换，不把耗时准备放入不可取消区。

历史元数据发布已提供独立操作编号；数据库行另有稳定 UUID。完整资产目录和跨设备资产 ID 仍属后续设计。现有工程的绝对路径由兼容适配器解析，不直接改写历史包。

算法可继续使用本地路径；未来远端资产由资产层下载到受控缓存后再交给算法。不让 UI 拼接存储目录，也不要求算法处理网络 URL。

### 历史数据访问接口

`HistoryStore` 已提供按集合刷新、查询、分页、版本关联、隐藏和恢复。SQLite 连接在调用线程内创建和关闭。UI 扫描、写入、隐藏和恢复在后台执行；搜索仅在 GUI 线程查询身份集合，无写锁等待，并通过进度回调限制查询时间为50 ms。超时或失败保留当前筛选并提示。树控件仍展示本次读取的集合，尚未实现滚动分页 UI；数据 API 支持分页。

已落地的 schema v1：

| 表 | 内容 |
| --- | --- |
| `migrations` + `PRAGMA user_version` | 数据库结构版本；旧采集隐藏状态随首次迁移在同一事务导入 |
| `records` | 稳定行 ID、扫描负载、搜索文本、时间、项目/版本/父版本、根标识与位置 |
| `membership` | 扫描集合与记录的归属、扫描顺序；整集合事务替换 |
| `hidden` | 采集隐藏状态、操作时间，独立于集合刷新 |

字段以实际扫描器结果为准，不为当前没有的病例或设备控制建立虚假业务记录。大图像、网格和覆盖数组继续存文件。

保留扫描器排序，并以稳定记录 ID 作为第二排序键。分页查询和总数查询来自一致快照。SQLite 使用参数绑定，不将搜索文本拼入 SQL。WAL 允许读取已提交快照，写入使用短事务及100 ms锁等待；取消和失败回滚集合更新。

采集隐藏状态迁移后以 SQLite 为唯一权威，旧 `local_history_deleted.json` 原样保留且不再写入。区域库已有的备注、重定位和隐藏配置继续由原 `region_library` 索引负责；本次没有迁移该配置，也没有新增导出记录移除入口。

## 发布和恢复协议

数据库事务与文件系统不组成跨介质原子事务。优先复用已存在的文件发布协议：

1. 在受控临时目录准备文件，记录操作身份和预期目标。
2. 按既有算法校验来源、摘要和方案版本。
3. 发布文件或已有发布凭证。
4. 在 SQLite 事务内登记索引；只有已完整发布的资产可以登记为可打开候选。
5. 若第 4 步失败，保留完整资产并明确提示“文件已保存、索引未更新”；刷新可幂等补登记。
6. 若发布前失败，不把暂存内容登记为可打开；保留必要诊断，恢复时重新校验。

索引刷新先构建完整新集合，再用单个短事务替换该集合的索引；扫描失败/取消时保留旧集合。隐藏状态独立于集合替换。

同一登记的内容变化继续由既有资产指纹核验拒绝；数据库保存观察结果，不能将其变为有效资产。跨设备全局版本冲突检测仍须在未来服务端设计中实现。删除或搬移未被本次操作创建的文件不属于失败恢复。

### 完整资产的发布边界

小型元数据、完整方案和原始帧各自保留适合其内容的发布验证。统一入口不能跳过已有的资产完整性检查。

| 对象 | 发布接口 | 失败后的处理 |
| --- | --- | --- |
| 历史登记等小型 JSON | `asset_storage.publish_json` | 根据收据检查，完整准备且目标未变时显式恢复；已记录失败不自动重试 |
| 原生方案目录、便携 ZIP | `planning_io.staging_directory`、`planning_io.publish` 及对应保存器 | 发布前保留旧版本；发布后的完整文件在索引失败时保留，可重新导入登记；不从半成品目录拼造成功方案 |
| 离线重建结果 | `local_offline.publish_result` 与 `publication.json` | 普通失败尝试回滚 latest；进程中断时 pending 结果不作为可用最终结果，保留源数据和诊断 |
| 原始采集 | `RawFrameWriter`、`scan_session` 原有帧回执契约 | 保留已记录帧与中断证据；不凭残留文件推造成功采集或位姿 |

多个 latest 文件不构成一次文件系统事务。离线结果发布期间硬退出可能留下部分 latest 已变、收据仍 pending 的状态；恢复入口必须遵守收据，不能只看 latest 指向。现有 `publish_result` 可对仍为 pending 且核验通过的同一结果显式重试；它没有持久化旧 latest 全集，不能承诺跨崩溃回滚到原状态，也没有自动恢复入口。涉及后来产生的新结果时，先由维护者核对上下文。

已发布方案的恢复以完整资产重新核验为准。临时文件清理、任意断电恢复、数据库与资产联合备份尚不在本次实现范围。

## 备份与迁移边界

- SQLite 备份使用一致性备份机制，不能把运行中的数据库主文件单独复制当作完整备份。
- 当前 `tools/history_metadata.py --backup` 只备份元数据。数据库与引用资产的联合备份清单、备份期间新增版本边界仍待实现。
- 当前以根标识/相对位置形成记录身份，但扫描负载和旧清单仍有绝对路径；整工作区搬迁不能仅靠复制数据库完成。
- 多设备阶段用业务 API 替换本地数据服务，中心可使用 PostgreSQL；本次不搭建服务端。
- 独立的离线双向同步、用户权限和并发编辑冲突属于后续功能。
- 不允许多台设备直接共享打开一个 SQLite 文件。

## 性能基线

`tools/benchmark_workstation.py` 使用固定采集输入与固定方案，测量重建、历史列表、方案回读、生成路线、原生保存、便携保存及独立回读。

每轮输出到新目录，保存输入/源码摘要、阶段耗时、进程 CPU 时间、50 ms 采样的进程 RSS 峰值和回读一致性结果。导入模块与输入摘要核对不计入阶段耗时。当前未覆盖相机实时采集、UI 绘制和实际机械设备。

RSS 是整个测量进程在阶段内的峰值，含此前阶段尚未释放的内存，不是该函数独占内存。重复运行不清空系统文件缓存，不声称冷启动性能。
