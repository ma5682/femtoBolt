# 路线计算的局部并行与重复准备消减（2026-11-06）

本轮按用户要求优化串行计算与重复工作。交付为源码；使用既有单帧、三帧规划模型的隔离副本验证。

## 实现

- `selection_intent.encode_runs` 的中间数组已经是 int64；使用 NumPy `tolist()` 直接生成相同的 Python 整数列表，省去逐元素 Python 转换。游程内容、顺序、严格整数类型及碎片预算保持。
- 新增 `quality_components.component_rows`。质量分类图至少 262,144 像素且可用 CPU 数大于 1 时，最多四个线程对六类缺失区域执行 OpenCV/NumPy 连通分量计算。线程读取同一份私有不可变像素快照；调用线程按原类别顺序、首次栅格出现次序生成报告，并执行原 4096 分量上限。取消检查留在调用线程，结束、异常或取消时清理线程池；小图保持串行。
- 有效域构建中的分类图派生报告，在既有单次操作范围内按图像完整内容、维度、类型、标签和编码限制匹配，以不可变 JSON 字节保存、独立解析返回。只复用准备数据，不保存有效域或路线的接受结论。保留工作目录中并发修改的验证短路顺序；有效域验证仍按原顺序比较并重建。
- P1 `prepare`、P2 `calculate` 和 `attach` 各自建立几何/证据准备范围，复用既有的解码、摘要及几何缓冲机制；退出即释放，三个独立入口之间没有跨请求接受缓存。
- P2 绑定直接消费 `from_plan` 本次已完整核验的路线对象，省去一次 `SurfaceTrajectory.from_dict`。绑定前后比较完整方案和已核验轨迹的规范字节，并重新检查当前输入和方案绑定；回调或目标准备期间修改输入，即使重算公开哈希也拒绝。默认 `from_plan` 的旧返回格式保留。

路线搜索、换行的预算和消费顺序、点面支撑、整边、宽度、选区、公开读取及最终核验仍按原规则执行。新并行只涉及独立图像算术，没有更改进程优先级、CPU 亲和性或全局 OpenCV 线程设置。

## 性能对照

最终冻结基线和候选各使用两个独立进程测量每份样本，共八次；第一轮旧→新，第二轮新→旧，样本顺序同时反转。以下为两次算术平均值，范围为新版两次最小–最大值。后台其他程序持续运行，未清除系统文件缓存；样本量不足以证明稳定时限。

| 样本 | 阶段 | 旧版秒 | 新版秒 | 缩短 | 新版范围（秒） |
| --- | --- | ---: | ---: | ---: | ---: |
| 单帧 | 生成路线并核验 | 10.433 | 8.603 | 17.5% | 7.136–10.069 |
| 单帧 | 目标面积 P1 | 9.457 | 7.062 | 25.3% | 7.051–7.073 |
| 单帧 | 覆盖核验 P2 | 6.429 | 5.886 | 8.4% | 5.722–6.050 |
| 三帧 | 生成路线并核验 | 9.558 | 7.693 | 19.5% | 7.016–8.369 |
| 三帧 | 目标面积 P1 | 10.270 | 5.484 | 46.6% | 5.090–5.877 |
| 三帧 | 覆盖核验 P2 | 7.701 | 5.609 | 27.2% | 5.467–5.751 |

生成入口计时从已有模型开始，到 `generate_checked` 返回显示数据结束；不含加载、重建或界面绘制。P1 包含自身必要的台账保存和发布，P2 包含 `calculate + attach`；两版边界完全相同。所有阶段均未达到稳定 ≤5 秒，不能外推为其他数据和负载的保证。

独立并行试验每种线程数六次，包含线程池创建和清理：单帧缺失区域识别中位数 47.94→26.16 ms，三帧 64.35→29.97 ms（串行→四线程）。该子步骤的收益很小，整个流程更大的改善来自编码和重复准备消减，不能把它解释为整条路线四倍加速。
