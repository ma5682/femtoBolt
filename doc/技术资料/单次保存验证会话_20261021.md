# 单次保存的原目标验证复用

面向保存链路维护者。本文描述 `SaveValidationSession` 的输入绑定、使用范围和失效条件。性能和持续运行结论以本轮验证报告为准。

## 使用范围

规划工作台一次点击保存会先发布原生路线包，再写入可编辑便携工程。前者已完整重建并验证原目标，后者可在同一个后台任务中复用这次目标验证。独立另存、历史打开和原生独立回读继续执行各自的完整验证。

会话只复用目标重建。覆盖证据继续经过既有完整复算或既有受限 `VerifiedAssets` 路径，未扩大该凭据的适用算法。未改变文件格式、目标算法、容差、计算预算或精确回退。

## 输入绑定

会话准备时调用 `planning_revision.require_current`，重新计算当前 RGB、深度、有效掩膜、标定、网格、来源、选区和参数的计算修订。另计算完整方案、完整区域、目标元数据、每个目标实际数组以及源网格文件字节的摘要。缓存中的标识或 `store.digest` 不能替代这些计算。

原生导出仍从本次独立快照完整读取并重建目标，写入暂存目标后再回读实际资产，完成覆盖核验、文件清单及发布。只有正常返回后，会话再次核对输入绑定并进入可消费状态。发布后核对失败时，已经发布的路线包记录在任务诊断中。

便携保存消费会话前核对当前目标资产和绑定。便携文件仍经过来源网格核对、目标写入/实际回读、覆盖核验、全部文件摘要和原子发布；最后发布前再次核对会话绑定。

## 生命周期

状态依次为 `new → active → prepared → published → consuming → closed`。会话只在创建它的工作线程中使用，只能消费一次。取消、错误、输入变化、退出上下文或完成消费后立即关闭，清除摘要。失败重试创建新会话并重新执行完整原生核验。

会话不保留模型、数组或文件内容，不写入磁盘，也不进入全局缓存。新任务、历史读入和未来设备消息不能继承它。

## 入口与验证

- `PlanningPage.save_plan`：冻结输入，创建一个会话，依次执行原生和便携保存。
- `surface_workspace.export(..., target_session=...)`：准备绑定，完成原生验证及发布后确认会话。
- `region_project.save_project(..., target_session=...)`：消费并在发布前重新检查。
- `tools/soak_workstation.py --reuse-save-target`：以同一正常保存预算验证组合保存，其他阶段和自然回收观察保持。

`tests/test_save_validation.py` 覆盖组合重建次数、历史独立重建、未发布/过期/跨线程凭据、实际输入和源文件变化、数组改动、压缩期间变化、取消及新任务重试。`tests/test_qt_save_interruption.py` 覆盖清单写入失败、取消、旧版本保留、重试、实际阶段反馈及事件循环响应。
