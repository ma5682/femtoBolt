## 目标与范围

项目目录为当前 checkout（编写时为 `E:\测试3D人体关节坐标-ui`，分支 `ui/workstation-redesign`；在其他 worktree 执行时以实际目录为准）。目标产品是单机运行的一体化聚焦超声设备上位机，未来连接底座、六轴机械臂、随动相机和治疗头。当前确认使用 Orbbec Femto Bolt；机械臂、底座、治疗头型号、协议、安装结构和标定尚未确定。

本轮目标是实现“可接入设备的业务框架＋可运行的模拟联调流程”，继续复用真实采集、建模、选区、路线规划和历史管理。模拟联调必须使用真实的业务状态机、接口校验、事件存储和 UI 绑定，不能用与业务无关的计时器直接增加进度。

最小产品闭环为“打开已保存方案 → 核验并冻结模拟任务 → 连接模拟设备 → 检查 → 模拟运行/暂停/停止 → 保存事件 → 重启只读回看”。先完成一条纵向流程，再补齐故障和辅助功能。坐标与测距准备属于独立功能，缺少真实标定不应阻塞这个模拟闭环，也不得靠伪造标定放行。

本轮不接真实机械臂，不发送运动或超声输出指令，不引入 ROS、MoveIt 或厂家 SDK，不改变现有几何路线的研发属性。模拟运行不代表治疗仿真、声学仿真、机械臂动力学验证或执行资格。

未来硬件到位后，应主要补充“厂家适配器＋参数及能力描述＋实测标定＋集成验证”。不要承诺只修改参数即可接任意硬件；厂家状态语义、反馈能力或同步机制不同，可能需要受控地扩充契约。

## 必须实现的功能

### 设备管理与能力边界

实现设备配置、生命周期和只读状态快照，包含设备身份、种类、协议版本、连接代次、来源、能力、状态时间、故障信息与参数修订。

沿用已有 `DeviceBinding`、`Capabilities`、`DeviceRequest`、`DeviceFeedback`，明确区分 `real`、`simulation`、`replay`。未知保持未知，未配置设备不得显示为已连接或已就绪。

模拟协调器只接收模拟可控设备绑定；当前真实相机状态可由原所有者提供只读显示，但不能被模拟任务控制。切换模式须结束或隔离旧实例并建立新的绑定，禁止在已有对象上把 source 字段改成 real，或让回放事件进入当前控制链。

配置应可本地保存并带 schema/version；能力与动态状态由适配器提供。修改配置不能赋予设备实际并不存在的能力。真实适配器尚不存在时返回明确的“不支持/未实现”，禁止静默回退模拟。

设备种类不等于必需控制器：底座可能仅为固定结构，治疗头也可能由独立超声发生器控制。本轮按场景声明参与设备及能力；固定底座不制造回零/运动接口，未配置设备不强制加入任务。设置中的型号、连接参数、来源字符串均不能单独证明真实连接。

现有 `prepare` 不是装任意运动参数的容器。需要模拟步骤等新消息时使用明确、带版本的独立数据契约，不破坏旧 `Intent` 与请求校验。不提前编造真实运动载荷、协议寄存器、治疗功率范围、控制周期或未知坐标参数。

现有 `Intent` 只有 `query_status`、`query_capabilities`、`prepare`、`cancel_request`、`request_stop`，没有暂停/继续。需要时以兼容方式新增意图，并与其他控制意图一样要求明确协议和能力声明；不得用 `cancel_request` 或 `request_stop` 表达暂停。设备种类不够时同样兼容扩展 `DeviceKind`，例如不用 `treatment_head` 代指独立的超声发生器。

现有 `DeviceFeedback` 只有 `motion_stopped`，没有治疗输出状态字段，不能借用它表示超声输出已关闭；输出状态须在新的状态字段或设备状态事件中单独表示，未知保持 `None`。

现有反馈以请求为单位，不能用它代替所有心跳与持续遥测。必要时增加设备状态事件，带设备绑定、事件类型、时钟域、状态时间和序号范围；明确请求序号与设备事件序号的作用域。旧枚举不得直接重解释；模拟专用步骤只由模拟适配器接收，通用生命周期契约保持可复用。

### 坐标、标定与几何距离准备

记录坐标系名称、单位、轴向约定、变换方向、标定 ID/版本、设备及安装绑定、来源、有效状态、必要时间信息。仓库目前没有通用的变换组合库，只有 `validate_pose` 这类结构校验和各模块内的矩阵运算。新增的组合工具放在 geometry 层，沿用现有 `T_AB` 方向和 RDF 约定，不创建冲突的第二套约定。

约定 `T_AB` 将 B 坐标转换到 A，`p_A = T_AB · p_B`；命名沿用仓库现有写法（`T_W0_Ct`、`T_BC = T_BF · T_FC`），多字母坐标系名用下划线分隔。明确区分固定安装变换和随时间变化的机械臂位姿。为以下关系提供数据表示、校验、组合与详情显示：

```text
T_BC(t)   = T_BF(t) · T_FC              # AGENTS.md 已有的 eye-in-hand 关系
T_W0_C(t) = T_W0_B · T_BF(t) · T_FC
T_W0_U(t) = T_W0_B · T_BF(t) · T_FU
T_UC      = inverse(T_FU) · T_FC        # 仅在相机与治疗头均刚性固定于法兰时适用
```

W0 为本次会话稳定参考；B 为机械臂基座；F 为末端法兰；C 为彩色相机光学坐标；U 为治疗头工具坐标。当前 SDK 封装用 `AlignFilter(align_to_stream=COLOR_STREAM)` 把深度对齐到彩色，同一组内参描述彩色和对齐深度，场景链 `T_W0_Ct` 中的 C 即彩色相机 RDF（+X 右、+Y 下、+Z 前）。深度相机原生坐标只经 `calibration/depth_to_color.json` 关联；手眼标定若基于深度相机或机械安装面，须显式换算到彩色光学坐标。Nerfstudio/OpenGL 的 RUB 只用于导出，不进入设备变换链。

变换平移统一用米、旋转用矩阵。厂家接口常用毫米或欧拉角，由适配器换算，并保留原始单位和角度约定；业务层不能只改单位标签。

变换记录校验有限数值、维数、齐次结构、旋转正交性/行列式、单位和首尾坐标系是否可组合。数值容差按现有约定或有说明的工程策略定义，不能等同于实测精度。现有 `dataset.scene_dataset_validator.validate_pose` 的正交性和行列式容差为 2e-2，面向里程计位姿结构检查；标定记录如需更严格的容差，应另行定义并说明依据，不放宽现有调用。缺失外参不能默认单位矩阵；合成测试的已知单位变换须标明合成来源。结构合法、来源可核验和实测标定通过是不同状态，导入矩阵或点选“确认”不能自动取得实测资格。

现有 W0 定义为局部补采会话首个有效彩色相机，参考帧 Pose 精确为单位矩阵，对应 `origin_reference.kind=initial_color_camera`。机械臂接入后，如果采用 eye-in-hand 且底座在整个会话中保持锁定，可由首帧同步法兰位姿和手眼标定得到 `T_W0_B = inverse(T_BF(t0) · T_FC)`，W0 的定义不变。若改用底座或其他固定基准作为会话参考，须使用新的坐标系名称和 `origin_reference.kind`，不得沿用 W0 名称、重新解释历史模型或把旧矩阵直接改名。现有固定 RGB 选区只接受 `initial_color_camera`，新 kind 的消费者兼容不在本轮范围。缺少变换、同步位姿、安装证据或有效标定时返回不可用。相机到治疗头距离计算在相对安装固定时可直接使用 `T_UC`，但测量仍需新鲜有效表面。

机械臂基座随底座解锁、移动、重新定位，或底座空间状态变为未知时，当前 `T_W0_B` 立即失去实时有效性，由它推出的 `T_W0_C(t)`、`T_W0_U(t)` 同时失效；依赖这些变换的执行资格和实时测距资格一并撤销，在途任务进入停止/未知流程。具体规则：

- 底座没有可核验的锁定或位置反馈时，空间状态视为未知，不能默认仍然锁定。结构固定的底座也只凭安装证据成立，证据缺失或发生碰撞、拆装时同样视为未知。
- 历史模型、方案和运行记录继续按其原始 W0 和变换版本只读追溯，不被新位置改写。
- 必须重新建立并验证 `T_W0_B`，才能进入新的实时执行上下文。上文的 `inverse(T_BF(t0) · T_FC)` 只在相机位于 W0 的首帧成立，底座移动后不能在任意时刻套用它，否则得到的是当前相机系而不是 W0。
- 重新建立只有两条路：一是开新会话，以新的首帧建立新 W0 并重新采集，旧方案不自动继承；二是先用有证据的方法把相机重新定位到原 W0，再求新的 `T_W0_B`。当前跨会话继承（P6）尚未开发，重定位只是默认关闭的实验开关，因此本轮按第一条处理。
- 同理，相机或治疗头相对法兰拆装、碰撞或安装状态未知时，`T_FC`、`T_FU` 及其组合失效。

实现可独立验证的几何间隙计算：输入有来源及支持信息的局部表面、工具前端基准点和工作轴，返回前向射线上最近有效交点及距离、坐标系、单位、来源和失败原因。输入必须统一坐标/单位，轴向非零并归一化；说明多交点、背面命中、边/顶点命中、退化面和边界数值容差的处理。纯几何函数不自行访问设备时钟或状态，由调用方先核验数据与标定适用性。

支持信息复用现有证据：局部补采网格的原始视角支持过滤、深度有效性与 confidence 层（原始 1.0、修复 0.3、未知 0）。修复深度和补洞面不能当作实测支持来证明间隙。现有 Open3D `RaycastingScene` 调用位于 annotation 层，geometry 不能导入它们；可在 geometry 内直接使用 Open3D 或 numpy 实现，使用 `RaycastingScene` 时须注意其 float32 精度并在容差中说明。

没有交点、支持证据缺失、已知遮挡、标定缺失或实时数据过期时不输出当前间隙。算法只能使用输入提供的观测和质量证据，不能仅凭 Mesh 推断所有未观察遮挡。不要将最近任意点距离冒充沿轴间隙；未提供外壳模型时不声称具备外壳碰撞距离。

区分历史几何复算与实时测距：历史模型可在其原始参考和假设下只读计算几何距离，并明确标记历史/离线结果；它不能代表当前患者间隙。实时有效期、同步允差及状态过期规则须有配置来源，未知时阻断实时用途。模拟场景可以定义测试时间预算，但这些值不迁移成真实硬件要求。

此功能用合成几何验证，在真实标定缺失时 UI 显示不可用，不硬造外参接到当前相机。它不判断接触力、耦合、焦点组织定位或治疗安全。变换不确定性和物理精度未知时保持未知，不用帧平均或显示小数位代替精度证据。

### 模拟任务、前置检查与状态机

定义独立的“模拟运行任务”，优先引用已经保存并通过现有入口核验的方案。未保存草稿先走已有保存流程；不额外发明另一种方案保存格式。冻结必要的路线/步骤和配置快照，保留原方案引用、修订与摘要，不回写源方案，也不复制整套原始数据。冻结须防止可变数组或对象别名改变在途任务；对象和缓存生命周期需有释放点。

绑定任务 ID、方案修订/摘要、源模型、区域、坐标、配置、实际所用标定、设备连接代次和模拟场景版本。分别记录源方案的数据来源与本次运行来源：使用实采方案的模拟运行仍为 simulation；合成安装关系必须另存模拟场景，不能登记为真实标定。

方案中的治疗头参数（`treatment_head.json`，schema `femto-treatment-head-parameters-v1`）带 `values_status`，取值只有 `placeholder_not_device_parameters` 或 `user_entered_unverified`。其中治疗深度、外壳直径和安全余量当前只记录、不参与规划。模拟任务原样携带并显示该状态，不将 `PLACEHOLDER_DEFAULTS` 或用户输入升级为设备参数，也不把它们当作碰撞或焦点几何依据。

前置检查分别输出通过、未通过、不适用或未知及原因，并明确区分：

- 模拟软件流程所需条件；
- 真实执行尚缺的厂家协议、标定、运动检查和设备反馈。

允许在模拟条件成立时运行模拟任务，但不得把真实执行检查一并设为通过。所有既有方案的 `execution_ready=false`、`physical_accuracy_verified=false` 保持不变；新增的模拟任务快照、事件导出、前置检查结果和测距结果 JSON 同样固定这两个字段为 `false`，并写明数据来源。

纯步骤模拟不依赖真实坐标和安装标定，相关真实条件应显示未满足或待接，而不是伪造为通过。依赖模拟空间关系的测距演示必须单独提供合成输入。方案来源核验失败是模拟的阻断项；既有几何未知范围、断点与覆盖结论照原样展示，不能以“模拟完成”消除。

用显式状态迁移表管理任务，至少覆盖未准备、检查中、可开始模拟、运行中、暂停请求中、暂停已确认、停止请求中、已停止/已取消、成功、失败、结果未知。按语义拆分“操作员意图”“设备请求进展”“设备报告物理状态”，避免单个布尔值表示全部。

要求：

- 请求停止不等于已停止，超时不等于成功取消；缺少反馈时显示结果未知，不允许在相同未释放资源上直接开始另一任务。
- 取消某一请求不代表设备已停止；机械臂停止也不代表模拟超声输出已关闭。全局暂停/停止完成须依据当前任务所有相关模拟设备的明确反馈，未参与设备按场景记为不适用，不能补造肯定反馈。
- 重复点击不能重复创建同一在途动作；重复、乱序、迟到和旧连接代次反馈不得推进新任务。
- 断线或在途任务所依赖的标定、设备状态失效时撤销资格，并停止下发后续步骤。终止流程不能简单将状态设为失败后释放仍可能在运行的设备。
- 同一设备资源同时只允许一个协调任务占用，明确锁的拥有者及释放条件。单机可能有多个窗口或进程：对同一运行资源实施进程级互斥，或明确拒绝第二个控制实例。可参照 `asset_storage.publication_lock` 的锁文件模式（Windows `msvcrt`、其他平台 `fcntl`，进程崩溃时由操作系统释放），但运行资源锁使用独立文件和明确的持有者信息，不复用元数据发布锁。模拟设备使用独立实例和资源标识，不占用真实相机；已有相机不因本轮被纳入新的通用锁而重构。
- 模拟路线进度由适配器反馈驱动；如有估计动画，单独标记，不能冒充实际反馈。
- 运行期间，其他编辑页产生的新草稿修订只用于新任务，不改变当前冻结快照，也不因无关草稿变化误停任务。若当前引用资产被原地改写、实际设备配置被替换，或操作员要求将新输入用于当前任务，则拒绝继续，并走停止/未知处理。
- 恢复动作重新检查绑定及反馈，不根据百分比自动接着执行。
- 结果未知时，仅阻止相关资源的新动作，不必锁死所有离线页面。模拟实例允许显式关闭并新建独立实例开始新任务，旧任务保留未知结果；该操作不能成为未来真实设备的“强制确认停止”入口。

正常终态也要处理通过身份、来源和连接代次核验的晚到矛盾反馈：重复完成可忽略并按策略记录，当前连接报告的新故障或不一致物理状态要报警并撤销就绪状态。旧代次消息只记录拒绝原因，不影响新连接；不能因任务已结束而静默吞掉仍有效的设备故障。

### 可确定复现的模拟适配器与故障注入

模拟与未来真实适配器共用已定义的生命周期和反馈边界，当前只实现版本化的软件模拟协议。提供可保存的场景配置、显式模拟来源和可控时钟/调度；不要宣称尚未确定的厂家协议已经被仿真。

至少支持正常反馈、接收延迟、完成延迟、请求拒绝、无响应、断线重连、旧代次反馈、重复/乱序反馈、设备报告故障、停止收到但尚未确认停止，以及模拟底座解锁、移动或状态变为未知。

暂停、继续、取消及停止只改变模拟设备的明确状态；测试使用可控时间推进，不用长时间 sleep。模拟治疗头只报告模拟准备/输出状态，不打开真实设备或端口。

真实方案只提供只读几何路线引用，用于模拟步骤调度。现有 `femto-surface-trajectory-v1` 在 W0 RDF 米坐标下给出 `ordered_items`：`scan_segment` 的点带 `role`，其中 `connector` 是行间连接；`gap` 带 `reason`（如 `selection_break`、`surface_gap`、`disconnected_surface`、`row_turn`）。文档固定 `orientation_fields=null`、`normals_are_not_tool_pose=true`。因此无工具姿态时保持缺失，不能用表面法线制造工具姿态或六轴指令。保留路线分段、扫描段/连接段角色及断点，不自动跨断点连线或推断连接段输出状态。冻结时记录 `result_sha256` 和算法版本，不改写路线文件。模拟进度按预先定义的步骤及确认事件计数，不能表示实物完成率、治疗覆盖率或真实剩余时间。

提供独立、显式选择的合成测试场景，无真实方案时也能验证软件。用户选择的真实方案加载失败时留在失败状态，不自动切换合成场景。

能力差异至少覆盖不支持暂停或缺少停止反馈的模拟配置；按钮可用性和协调行为按能力变化，不能假定所有设备支持全部控制意图。同步周期、随机种子（若使用）和故障脚本属于场景版本，测试结果应可复现。

### 本地记录、追溯和中断恢复

复用现有 SQLite、受控路径、原子发布和诊断机制。当前 `HistoryStore.replace()` 用于刷新文件集合索引，不是追加式运行日志；`records` 的身份也围绕文件路径构建，不能直接套用为设备事件主键。

现有数据库事实（2026-10-21 源码）：

- 位置为 `outputs/history_metadata/history.sqlite3`，每个 worktree 各有一份。
- `SCHEMA_VERSION=1`。写连接只接受 `user_version` 为 0 或 1，0 时在同一事务内建表并迁移；只读连接要求恰好为 1，否则拒绝。因此只要把版本升为 2，现有 `HistoryStore` 和旧版软件就会拒绝读写历史。
- 写连接使用 WAL、`synchronous=FULL`、`BEGIN IMMEDIATE`，busy timeout 只有 0.1 s。集合刷新会在一个写事务内处理整个集合，期间其他写入可能因 `database is locked` 失败。
- `backup()` 使用 SQLite 在线备份整个文件。

运行记录使用独立的任务/事件表和专用仓储接口，不将执行状态机塞进根级 `history_store.py`；通用连接与事务代码可最小提取复用。

默认方案：同一产品数据目录，两个数据库文件。

```text
outputs/history_metadata/
  history.sqlite3     # 现有历史索引，保持 schema v1，由 HistoryStore 独占管理
  execution.sqlite3   # 新增：模拟运行任务、事件、恢复记录，由 execution 仓储独占管理
```

- `history.sqlite3` 的表结构、`user_version` 和 `HistoryStore` 版本判断本轮不改；execution 的 schema 变化不影响现有历史功能和旧版软件。
- `execution.sqlite3` 自有 `user_version` 与事务迁移，只由 execution 仓储一处管理；未知新版本拒绝写入。两个文件各有唯一的版本管理者，不互相修改。
- 不使用 `ATTACH` 跨库事务，也不引用 `history.sqlite3` 的行 ID（集合刷新会重建成员关系）。运行记录以方案路径、修订 ID 和文件摘要关联方案，回看时按摘要核对，不一致时显示来源变化，不静默改绑。
- 数据库文件只在首次需要写运行记录时创建；导入模块、打开工作台或只读回看空记录时不创建。
- 两库各自拥有写锁，集合刷新不会阻塞事件写入；但 execution 库自身的写失败仍按下文持久化缺口处理。
- 现有 `tools/history_metadata.py --backup` 只备份 `history.sqlite3`。`doc/使用说明/SQLite历史记录与备份.md` 的恢复步骤要求清空 `history_metadata/` 后只放回 `history.sqlite3`，按原文操作会丢失 `execution.sqlite3`。因此必须同步更新备份工具和恢复说明：两个文件都用 SQLite 备份 API 生成一致快照并一起恢复，不混入旧的 `-wal`/`-shm`。跨文件不存在原子一致点，须说明备份时刻两库可能相差的范围，以及恢复后如何显示这一缺口。

只有能说明独立文件不可行的具体理由时，才改为把表放进现有数据库。那时须由一处统一管理 `user_version` 和迁移，同步修改 `HistoryStore` 的版本判断及测试；旧版软件将无法打开升级后的数据库，须在使用说明中写明，并在迁移前自动备份。

无论哪种方式，新增表不得被原有集合刷新覆盖；旧版数据通过事务迁移，未知新版本拒绝写入。必须验证集合刷新与事件写入并发时的锁竞争（默认双文件方案下，还要验证两者互不阻塞），以及运行记录自身的并发写入：锁超时要按持久化失败处理并进入缺口流程，不能静默丢弃事件，也不能为写入事件无限等待而阻塞停止和反馈处理。

使用数据库副本验证迁移、失败回滚和备份恢复，再接入产品入口；不要把用户当前数据库当测试样本直接改写。独立事件存储不等于重建历史产品，仍通过现有工作台提供回看入口。

保存冻结任务快照与按序事件，包括任务/请求 ID、设备身份及连接代次、来源、方案修订、配置与标定版本、时间、状态变化、反馈和失败原因。跨设备时钟未经同步不能直接相减；超时使用单调时间，审计时间记录时钟域或对应来源。

模拟运行记录与真实采集、正式方案记录在类型、UI 和路径上明确区分。禁止更新原始数据、生产 latest marker、既有证明资产或临床完成状态。存储路径从 `femto.paths` 管理，不把运行数据写到源码目录。

事件与任务状态保持一致：唯一运行 ID 和本地递增事件序号用于排序与去重，设备原始序号及其作用域另存；关键事件与状态快照用同一短事务提交。数据库事务不能跨设备等待、SDK 调用或大文件处理。

记录请求意图后再分发，分别记录发送结果与反馈。数据库事务和设备动作无法原子提交，必须覆盖“已记录未发送”和“可能已发送但未记录确认”的崩溃窗口；后者恢复为中断/待核对，不自动重发。记录失败时仍应允许停止请求与接收反馈，不让日志异常阻断退出处理；未持久化部分需明确提示，不能承诺磁盘故障时所有事件都已保存。

进程重启后未结束任务保持中断/待核对，模拟回放只读，不重新执行请求。关键记录不可写时阻止新模拟任务开始；恢复可写后追加缺口/恢复事件，不补造未收到的设备状态。单调时间值不能跨进程重启直接比较。

不将高频图像、网格或原始 SDK 数据全部写进 SQLite；使用已有文件资产和引用机制。

### 接入现有 Qt 工作台

在当前桌面入口增加清晰可发现的设备管理与模拟联调入口，复用样式、导航和历史能力。不要重做采集规划页面，不新建另一套正式窗口体系。

现有 `qt_main.WorkstationWindow` 的结构：顶部导航按钮为采集工作台、打开项目、历史记录、部位记录、高级工具；`QStackedWidget` 中有采集、规划、回看三页；标题栏 `execution_badge` 固定显示“研发预览 · 不可执行”。新入口按此结构接入，作为导航按钮加页面或对话框。具体要求：

- 新页面或对话框必须并入切换项目和关窗检查链，即现有的 `can_leave()`/`busy` 判断和 `closeEvent` 中逐页 `shutdown()`；`shutdown()` 返回未完成时窗口保持打开并按现有定时重试流程等待，不能绕过链路直接退出。
- `execution_badge` 保持“不可执行”语义，模拟提示另行显示，不能改为“可执行”或“已就绪”。
- `--ui-preview` 下模拟联调必须可用，且不连接相机；构造页面时不自动连接模拟设备、不创建数据库。

至少提供设备连接/来源状态、配置与能力详情、标定缺失说明、模拟前置检查、方案选择、任务进度、事件列表和历史回放。开始/暂停/继续/停止等按钮由状态机决定是否可用。

模拟模式持续显示“模拟联调，无真实运动及超声输出”。真实未配置设备显示原因，不展示假遥测。导入真实方案后须先通过原有来源与完整性核验，再创建模拟任务。

Qt 主线程只更新控件和 VTK 对象；IO、设备等待和重计算在后台。协调器串行处理业务事件，避免多个回调同时修改状态；页面接收不可变快照。明确工作线程/进程的所有者、取消、关闭和资源回收；不要用 daemon 线程掩盖退出问题。

业务关键事件与显示遥测分开调度。显示更新可合并，关键事件不得静默丢弃；关键队列溢出时停止接纳新步骤、报告记录/状态缺口并进入规定的停止或未知流程，不能以无限队列解决。模拟时间预算可配置并验证，不宣称硬实时保证。

保存模拟记录后可重启软件只读回看；切换项目、退出、计算取消或错误不能串用旧结果。关闭中禁止新任务，等待反馈采用有期限的异步流程；期限结束仍未知时保留中断记录，不伪装为已停止。历史回放不能激活设备控制。方案加载核验只在明确加载/创建任务边界进行，不在每次 UI 刷新中重算完整几何和覆盖证明。

- 必须验证未连接就检查、运行中关闭实例、未知结果取消/确认关闭、历史页新建任务、心跳中阅读设备详情及阶段提示切换。除按钮禁用外，后台还需拒绝不合法的检查顺序和在途关闭。

### 后续六项交互完善验收（2026-10-22）

本文仍为实施与维护要求；当前实现及验证见[六项交互完善记录](../历史开发记录/模拟联调六项交互完善_20261022.md)。实施时核对现有能力，不重复创建已有入口。

1. 当前任务状态、确认步骤进度、暂停/继续与请求停止放在标签页外。运行或暂停中切换模拟记录、配置及滚动内容后仍可见可用；停止不是硬件急停。
2. 方案回看页提供“用此方案模拟联调”，只带入已保存版本。按原完整来源与几何链核验，再显示任务、部位、患者左右、体位、正背面和修订摘要；未知字段不补造。确认摘要后才能冻结，版本或资产变化拒绝，不能回退合成。
3. “撤销冻结”只允许正向证明未下发请求的未准备任务。协调器和事件仓储均核验，无请求尝试/在途请求/记录缺口且零步骤才追加“已放弃、未运行”；事务失败保留任务所有者。准备/在途任务必须走停止确认。实例关闭和正常退出对同样可证明的未运行任务沿用该状态，不制造未知停止。
4. “选择方案 → 冻结 → 连接 → 检查 → 运行”显示当前阶段，每阶段突出一个下一步主操作。异常状态不提示正常继续；连接不代替前置检查。
5. 主视图使用中文设备状态与历史摘要。历史显示方案名称、结果、步骤、任务上下文和异常原因；空列表有操作说明。设备无关字段显示“不适用”，相关字段缺少证据显示“未知”；连接代次、完整字段和最近事件进入工程详情，完整快照与全部事件保留导出。
6. 异常区显示原因、影响与下一步，提供适用的重试、记录缺口恢复或旧模拟实例关闭入口。故障和停止未知不能被普通心跳/导出通知隐藏。关闭取消保留原任务和资源，恢复不补造未收到状态。

事件库存储新增终态时须升级独立 execution 版本并验证旧库只读、事务迁移回滚、备份恢复与降级拒绝。原 history schema v1、真实控制边界、几何格式和资格字段不改变。

## 明确延后的内容

- 机械臂逆运动学、控制器轨迹上传、真实速度/加速度控制和接触力闭环；
- 自动机械臂扫描路径、真实运动到位与取帧同步；已有人工采集流程保持；
- 底座定位、真实手眼及工具标定求解、患者运动补偿；
- 超声声学模型、组织靶区推断、剂量计算、焦点治疗验证与真实输出；
- 真实硬件联锁、急停和安全认证；软件停止按钮不得标成硬件急停；
- 网络服务、云平台、多机调度、跨会话目标继承或通用插件市场。

待办须记录依赖谁提供什么资料和如何验收，不能用空类或假参数声明完成。底层协议未定时，业务状态可以用明确的模拟合同运行，真实执行始终阻断。

按下列顺序推进，完成一阶段就验证并更新记录，然后继续后续阶段。常规目录和命名选择自行处理，不逐步索要批准；只有缺失信息确实阻止真实硬件工作时才保留待接项，本轮可做的软件工作继续完成。

| 阶段 | 必须交付 | 阶段验收 |
| --- | --- | --- |
| A：现状与边界 | 实际复用清单、目录依赖、契约及兼容策略、阶段任务表 | 旧链路和原有修改被识别，未把已有模块重建一遍 |

| C：模拟闭环 | 模拟适配器、任务协调、故障脚本、无 Qt 诊断入口 | 正常任务完成；暂停、拒绝、超时、重连、迟到反馈及未知停止结果符合状态表 |

必须覆盖的行为验证：

1. 未配置设备能力为空，未知物理状态不能默认成已停止或已就绪。
2. 真实/模拟/回放绑定、不同设备、不同连接代次和不同请求不能互相确认。
3. 延迟、重复、乱序和取消后的回调不影响新任务；重连不能自动重发运动类意图。
4. 当前依赖失效或引用资产被改写会阻止继续；编辑其他草稿、显示切换等操作不影响冻结任务。恢复不能覆盖未知停止结果。
5. 缺失标定、轴线无交点、无效表面及过期输入时距离不可用；合成刚体变换和已知间隙结果正确。模拟底座移动或状态未知后，`T_W0_B` 及其派生变换、实时测距和在途任务资格均被撤销；历史记录不变；未重新建立 `T_W0_B` 前不能开始新的实时上下文，也不能用首帧公式在非首帧时刻重算。
6. 方案被篡改或来源核验失败时拒绝运行，不能降级用测试方案代替；合法方案的原始文件及摘要保持不变。
7. 设备无响应、停止未确认、应用退出、崩溃恢复都有明确结果及可追溯事件；磁盘写失败须明确报告持久化缺口及恢复边界。
8. 无真实相机、机械臂和治疗头也能完成端到端模拟；未安装未来机械臂/超声厂家 SDK 不影响默认启动和原有离线规划。现有相机依赖按原环境要求保留。
9. Qt 关闭、后台取消、连续切换记录和事件大量到达时无旧任务覆盖、无永久等待；原生渲染另按实际条件验收。
10. 所有模拟产物明确标记来源，旧方案执行资格保持 false，原始 RGB-D、模型及证明资产未被改写。
11. 不支持暂停、缺少停止反馈或只有固定底座时，能力判断正确；机械臂停止与超声模拟输出停止分别确认。
12. 事件重复投递不产生重复状态迁移；在请求分发前后和反馈落盘前后模拟崩溃，恢复不自动重发。
13. 数据库迁移中断可回滚，集合索引刷新不删除运行日志，未知数据库版本拒绝写入；迁移后现有历史列表仍可正常查询、隐藏和恢复；集合刷新与事件写入并发时锁超时被记录为持久化缺口；默认双文件方案下 `history.sqlite3` 仍为 v1，运行任务和事件的写入、迁移与回滚都不修改该文件（测试中对比其摘要）；备份工具同时生成两库快照，按更新后的说明恢复后历史记录、任务和事件都在。
14. 多窗口/进程争用得到明确拒绝或隔离；关键事件队列溢出、日志失败和退出超时不会被显示成正常完成。
