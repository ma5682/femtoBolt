> 日期：2026-09-20　状态：方案已确认，进入实现　适用：当前无固定底座、无机械臂阶段
> 输入：固定 RGB 页"保存并导出当前结果 GLB / PLY"产生的区域导出目录　输出：W0 坐标系下只含 X / Y / Z、受 Mesh 表面支持的**唯一有序 Surface Trajectory**

## 0. 两条定义（本方案的基础）

> 2026-09-23 用户追加业务语义：医师选择拓扑决定治疗工作块，点云 / Mesh 只提供 XYZ 支持，明确未选区域是绕行约束，采集 / 建模缺失是数据质量问题而非"未选"。现行 v4（`mesh-slice-serpentine-v4`）以固定 RGB 页保存的选择意图掩膜定义工作块（一个 4 连通选中组件 = 一块），Mesh 连通分量只作块内碎片诊断，块内每对相邻段沿真实表面连接（边界折返优先，其余沿碎片网格边最短路），成功块为单链、块间只放 `selection_break`；连续与覆盖分开报告；派生工作表面待用户决定。数据契约、链接规则与待决项见《三维表面轨迹_选择组件分块与派生表面待决项_20260923.md》。以下 v1–v3.1 描述在每个网格碎片内部继续成立。
>
> 2026-09-22 用户追加确认：分块规划、块内折返、块间断开。现行 v3（`mesh-slice-serpentine-v3`）按区域 PLY 三角面共边连通分量分块，每块单独按 5.1–5.5 与 v2 折返规则规划，块按参考图像阅读顺序（`start_corner` 决定）依次访问，块间只记 `disconnected_surface` gap；不可规划块记录原因，全部不可规划拒绝。数据、统计与预览细节见《三维表面轨迹分块规划交付记录_20260922.md》。以下 v1/v2 描述在每块内部继续成立。
>
> 2026-09-21 用户追加确认：需要逐行折返连接，不是外围独立扫描圈。以下 v1“所有换行均为 gap”描述作为原始方案留档；现行 v2 在相邻切片、同一连通表面上沿真实区域网格边界寻找两行间的贴面连接，禁区/图像外/不连续或歧义边界拒绝连接。新点标 `role=connector`，保留全部边界拐角并以 ≤1 mm 采样；每条 connector 边两端必须受同一三角面支持。连续 segment 可跨行，segment.row_index 为首行，点的 row_index 保留所属行。旧 v1 兼容回读不改变。历史生成与 CLI 启用 `connect_rows=true`，算法版本 `mesh-slice-serpentine-v2`；原函数不传该参数仍按 v1。行/间距报告仍基于原扫描切片，连接长度单独统计，不纳入扫描间距测量。其余冻结阈值和不可执行约束保持。

**定义 1（只生成有表面支持的点）**：规划器只在存在有效 Mesh 表面支持的位置生成 XYZ 扫描点。遇到 Mesh 缺失、分离表面或禁止区域时，不做几何补点、不桥接、不猜测、不补面，而是记录一个 `gap`，并沿当前扫描方向继续搜索下一个有效表面。所有有效扫描段按唯一的 START → END 顺序组成一个完整扫描任务。

**定义 2（统一数据模型）**：投影式规划（当前固定 RGB，未来多帧 / 多视角 RGB-D）和 Mesh 自动规划输出同一个 `SurfaceTrajectory` 数据模型。两者只在"轨迹点如何产生"上不同，最终都是 W0 坐标系下、受 Mesh 表面支持的 XYZ 扫描点。下游（JSON / CSV / GLB / 播放 / 历史记录 / 未来机械臂接口）只依赖这个模型，不依赖具体 planner。

由此推出的三条纪律：

- **gap 不是轨迹**：它是扫描任务中的"跳过事件"，不是另一条 trajectory，也不是虚拟运动点。gap 内不存在任何 XYZ 插值点。
- **v1 不做自由空间过渡**：当前没有机械臂、底座和运动执行层，不规划离开表面后从 A 到 B 怎么走；gap 只表示"这一段没有有效表面扫描轨迹"，以后由运动执行层决定如何跨越。
- **"完整路线"= 唯一的规划顺序**，不代表所有相邻点之间都存在连续空间运动：`segment 0 → gap → segment 1 → gap → … → END`。

## 1. 边界（不变）

| 项 | 本阶段 |
|---|---|
| 参考坐标系 | **W0 不变**：首次有效采集的初始彩色相机坐标系，RDF（+X 右、+Y 下、+Z 前），米。轨迹 JSON 原样携带导出清单里的 `origin_reference`，`kind` 必须是 `initial_color_camera`，否则拒绝生成 |
| 轨迹点内容 | 只有 X / Y / Z（米）。**不输出** Pitch / Yaw / Roll、Rx / Ry / Rz、四元数或任何工具姿态字段 |
| 法线 | 不作为工具姿态。算法内部只用一个**全局**扫描面法线 `n`（区域整体朝向）决定切片方向；不给轨迹点输出法线 |
| 机械臂 | 不做 IK、ROS / MoveIt、手眼标定、真实运动执行、自由空间过渡。输出固定 `execution_ready=false`、`physical_accuracy_verified=false`、`orientation_fields=null` |
| 深度 | 轨迹点的 Z 就是相对初始相机光轴的深度；每段、每行带深度统计，俯视图按深度上色 |

## 2. 统一数据模型 `SurfaceTrajectory`（schema `femto-surface-trajectory-v1`）

```text
SurfaceTrajectory
├─ schema, coordinate_frame=world_rdf, unit=metre, axes, origin_reference（原样）
├─ planner: {kind: mesh_slice | projection_fixed_rgb | projection_multiview(未来),
│            algorithm_version, parameters, sweep_frame?}
├─ source:  {region_export_dir, region_manifest_sha256, mesh_file_sha256,
│            geometry_sha256, region_id, region_signature}
├─ ordered_items[]                      ← 唯一 START→END 顺序，scan_segment 与 gap 交替，首尾都是 scan_segment
│   ├─ scan_segment {segment_index, row_index, points[]}
│   │     point {xyz_m, row_index, route_index, geometry_support: "measured_mesh",
│   │            triangle_index, pixel?(仅显示与门禁), role?(scan|connector，投影式旧结果兼容)}
│   ├─ gap {gap_index, reason, detail, previous_point{route_index, xyz_m}, next_point{route_index, xyz_m},
│   │        scan_direction_w0, row_index_from, row_index_to, chord_length_m(仅信息，不是运动)}
│   └─ …
├─ statistics, gap_report, spacing_report, row_report
├─ orientation_fields: null, normals_are_not_tool_pose: true
├─ execution_ready: false, physical_accuracy_verified: false
└─ result_sha256（对 ordered_items 规范化 JSON 取哈希）
```

`trajectory.json` 不保存自身文件哈希，避免自引用。所有输出文件的字节哈希写入最后发布的独立 `trajectory_files.json`（schema `femto-surface-trajectory-files-v1`）；该清单不包含自身。规范化 JSON 固定为 UTF-8、键排序、`ensure_ascii=false`、紧凑分隔符、禁止 NaN/Infinity，文件末尾一个换行。

约束：

- `route_index` 在整条轨迹上全局单调递增；START = 第一个 segment 的第一个点，END = 最后一个 segment 的最后一个点。
- 一个 `scan_segment` 内相邻两点是同一切口上连续的表面采样，三维弦长 ≤ 采样步长；任何其他相邻关系都必须由一个 `gap` 表示。因此 `ordered_items` 严格交替，且不存在"尾随 gap"。
- `gap.reason` 只取规划器**能可靠判定**的类别；不可靠的推断放进 `gap.detail`，只作信息，不影响任何决策：

| reason | 含义 | 判定（可靠） |
|---|---|---|
| `forbidden_region` | 两段之间被禁止区域隔开 | 两段端点之间的弦按采样步长取样，投影到参考图像后任一样本落在 `forbidden_screen_polygon` 内（优先级最高，先于其他判定） |
| `disconnected_surface` | 两段属于不同连通分量 | 三角面连通分量标签不同 |
| `surface_gap` | 同一连通分量、扫描线上表面缺失 | 同分量且非禁区。规划器无法可靠区分 TSDF 真孔洞、外边界凹口和其他 Mesh 缺失，所以统一叫 `surface_gap` |
| `unsupported_geometry` | 被丢弃的碎片、退化切口、无参考像素支持 | 碎片 < `min_segment_mm`，或切口退化，或投影落在参考图像外 |
| `row_turn` | 行末到下一行行首的换行 | 相邻 `row_index` 不同。表面在这里通常存在，但 v1 不规划换行运动 |

`gap.detail` 字段（所有 reason 都有，`surface_gap` 才有推断）：

```text
detail {
  inferred_cause: interior_hole_likely | boundary_concavity_likely | undetermined | not_applicable,
  method: "sweep_plane_outer_loop_containment",   ← 见 5.3
  confidence: "heuristic",
  decision_use: "none"                             ← 任何逻辑都不得依赖 inferred_cause
}
```

- `row_turn` 记为 gap 的一种（已确认）：换行也是"没有规划表面扫描轨迹"的区间，显式记录才能保证"segment 内相邻点必连续"这条不变量，也让未来执行层能区分"表面存在但未规划"（`row_turn`）与"表面不存在"（`surface_gap`）。
- `geometry_support` 只有一个合法值 `measured_mesh`：每个点必须能给出所在三角面索引，且点到该三角面的距离 ≤ 1e-6 m（测试用）。没有其他支持类型，也就没有"补出来的点"。
- **`triangle_index` 的统一定义**：绑定的 `region_N_mesh_m.ply` 的 **0-based 局部三角面索引**。该 PLY 由 `scene_annotations.region_mesh(source_mesh, region.triangle_indices)` 生成，内部用 Open3D `remove_triangles_by_mask` 裁剪，保留的三角面按**源网格全局索引升序**排列，因此 `local_index = sorted(unique(region.triangle_indices)).index(global_index)`；顶点经 `remove_unreferenced_vertices` 重新编号。所有点都必须能通过这个索引在该 PLY 上找到三角面并通过 ≤ 1e-6 m 的几何验证。
- **共享边 / 顶点上的点**：可能同时落在多个三角面 1e-6 m 内。Mesh 自动 planner 记录的是该采样点被插值时所在的切口线段对应的面（折线首点取其第一条线段的面）；适配器几何重定位时取满足容差的**最小局部索引**。两条规则都是确定性的，保证同输入重复运行索引一致。
- 投影式规划的旧结果通过适配器转换（第 7 节）。旧结果里 `motion_kind=connector` 的点本身也是像素命中的 Mesh 支持点，转换后保留为 `role=connector`，仍是合法的 `measured_mesh` 点；旧结果的 `chain_breaks` 转成 `gap(reason=row_turn 或 unsupported_geometry)`。旧结果的点携带的是**源 TSDF 网格的全局** `triangle_index`，适配器必须按上面的规则换算成局部索引并验证，见 7.1。

现有导出目录 `outputs/complete_demo_*/reconstruction/annotations/<时间戳>_<8hex>/` 每个区域含：

|---|---|
| `region_N_mesh_m.ply` | **轨迹生成的唯一几何输入**。所选整三角面子网格，W0 RDF 米，顶点色；禁区已扣除（`selection_method=work_minus_forbidden`），孔洞保留 |

生成前校验，任一不满足即拒绝并写 `trajectory_blocked.json`（不输出伪轨迹）：

1. `region_N.json` schema 为 `femto-region-export-v1`，`unit=metre`、`coordinate_frame=world_rdf`，`origin_reference.kind=initial_color_camera`。
2. PLY 文件名取 `files.mesh_file`，其 SHA-256 等于 `file_sha256[files.mesh_file]`；三角面数等于 `region.triangle_indices` 长度。
3. 网格非空、坐标有限、无非流形边（复用 `metric_region_path` 里同样的边计数规则）。
4. `view_reference.undistorted_intrinsic` 存在（禁区判定与像素显示要用）。

| | A. 投影式 planner | B. Mesh 自动 planner（本方案新增） |
|---|---|---|

## 5. Mesh 自动 planner 算法（核心方向不变）

```text
Region Mesh PLY → PCA 稳定扫描方向（含模糊判断与 W0 X 回退）→ 平行平面切片 → 每个切口得到受 Mesh 支持的表面扫描线
→ 1 mm 重采样 → XYZ → 遇缺失 / 禁区 / 分离表面记录 gap → 沿扫描方向继续 → 唯一有序 SurfaceTrajectory
```

### 5.1 PCA 稳定扫描方向（含模糊判断与回退）

**目标**：同一输入重复运行得到完全相同的 `sweep_frame`；在 PCA 无法给出明确方向时，用确定性的 W0 轴回退，而不是依赖数值噪声。

1. **协方差与特征值**。以三角面质心的面积加权均值为 `μ`，计算 3×3 面积加权协方差矩阵 `C`（用固定顺序的分块累加，不用随机化算法），`np.linalg.eigh(C)` 得特征值 `λ1 ≥ λ2 ≥ λ3`（单位 m²）与特征向量 `v1, v2, v3`。3×3 对称矩阵的特征分解是确定性的。
2. **法线 `n`**。候选 `n_pca = v3`。判定"平面性充分"的条件：`λ3/λ2 ≤ planarity_ratio_max`（默认 0.5），且 `n_pca` 与初始相机视轴 `(0,0,−1)` 的夹角 ≤ `normal_view_angle_max_deg`（默认 60°，取绝对值后比较）。满足则 `n = n_pca`，`normal_source=pca`；否则回退 `n = (0,0,−1)`（W0 = 初始相机，区域是从这里看到的，视轴是最可靠的朝向先验），`normal_source=view_axis_fallback`。符号统一为 `n·(0,0,−1) > 0`。
3. **行方向 `e1`**（默认 `auto`）。候选 `e1_pca = v1` 投影到 `n` 的垂面并归一化。判定"面内方向明确"的条件：`λ2/λ1 ≤ inplane_ambiguity_ratio_max`（默认 0.8；等价于两个面内标准差之比 ≤ 0.89）。满足则 `e1 = e1_pca`，`direction_source=pca`；否则（近似方形或圆形区域，`λ1 ≈ λ2`）回退到 **W0 X 轴在 `n` 垂面上的投影**，`direction_source=w0_x_fallback`。
4. **用户覆盖**。`row_direction=w0_x` / `w0_y`：`e1` = 该轴在 `n` 垂面上的投影；若投影长度 < `sin 10°`（轴几乎垂直于表面）则拒绝并提示换轴。`row_direction=<角度>`：在 `n` 垂面内以 W0 X 的投影为 0° 逆时针旋转，因此角度语义不依赖 PCA。
5. **符号规约**（消除特征向量 ± 号的不确定）：`e1` 取与 W0 +X 夹角 ≤ 90° 的一侧；若 `|e1·X| < 1e-6` 则改用 +Y 判定，再退到 +Z。`e2 = n × e1`。
6. **记录**。`sweep_frame = {origin: μ, e1, e2, n, eigenvalues_m2: [λ1, λ2, λ3], ratios: {inplane: λ2/λ1, planarity: λ3/λ2, normal_view_angle_deg}, direction_source, normal_source, thresholds}` 写入 JSON；`ratios` 与阈值一起出现在报告里，方便判断某次回退是否合理。
7. **阈值属于参数，且 v1 冻结**。三个阈值进入 `planner.parameters`，参与 `result_sha256` 与回读校验；v1 固定为 0.8 / 0.5 / 60°，Phase 2 只记录校准数据，不得自行修改（第 14 节）。

模糊判断只在"是否回退"上做二选一，不做插值混合，因此同一输入的结果不随浮点噪声漂移；不同机器上的极小数值差异只可能出现在恰好落在阈值附近的输入，这种情况会在报告里显示 `ratios` 贴近阈值，属于已知限制。

### 5.2 等距切片得到行

- 顶点在 `e2` 上的投影范围 `[t_min, t_max]`，切片位置 `t_k = t_min + d/2 + k·d`（`d` = 行距，默认 5 mm），首行半个行距起。
- 每个位置用 `trimesh.intersections.mesh_plane(mesh, e2, μ + e2·t_k, return_faces=True)` 得到该平面与网格的线段集及每段所属三角面（每个三角面最多一条线段，端点在三角边上，天然贴面）。
- **线段拼链只用 numpy**：端点按 1e-7 m 量化去重，建邻接表，从度为 1 的端点出发沿链走，得到该行的若干折线；每条折线携带所经三角面索引与连通分量标签。不用 `trimesh.load_path`（它依赖 scipy，本项目未登记 scipy，不新增依赖）。闭合环没有度为 1 的端点时，从量化坐标字典序最小的节点开始；候选下一边按对应局部面索引、另一端量化坐标排序，取最小者，保证闭环起点与方向确定。重复边按同一排序规则去重；出现度大于 2 的分支时在节点处拆段并记录 `unsupported_geometry`，不得任选分支。
- 连通分量标签用三角面邻接的并查集（numpy，真实区域 23 065 面 0.04 s）。

### 5.3 行内：碎片与 gap（不桥接、不猜测、不补面）

同一行内的折线按 `e1` 方向排序，奇数行整体反向（含折线顺序与点序），形成蛇形。相邻折线之间一律是 gap：

1. 折线长度 < `min_segment_mm`（默认 2 mm，即不足两个采样点）的碎片**丢弃并记录**到 `gap_report.dropped_fragments`，其位置并入相邻 gap，reason 为 `unsupported_geometry`。丢弃不是补点，只是不输出噪声碎片。
2. 相邻两条保留折线之间生成一个 `gap`，reason 按第 2 节表格判定，`forbidden_region` 优先：因为禁区孔与缺测孔在 PLY 里长得一样，只能靠导出清单里的像素多边形区分，禁区是用户意图，缺测只是没有数据。
3. `surface_gap` 的 `detail.inferred_cause` 用一个廉价启发式填写，**只作信息**：取该连通分量的边界环（边计数为 1 的边连成的环），把每个环投影到 `e1`–`e2` 平面，投影面积最大的环视为外轮廓，其余为内环；gap 弦的中点投影若落在外轮廓多边形内记 `interior_hole_likely`，否则记 `boundary_concavity_likely`；边界环无法闭合或投影退化时记 `undetermined`。这个推断在自遮挡、卷曲表面上可能出错，所以不得用于任何决策。
4. gap 只记录 `previous_point` / `next_point` / `scan_direction_w0` / `chord_length_m` / `detail`，**不生成任何 XYZ 插值点**。

所以一条扫描方向上遇到"有效表面 → 禁止区 → 有效表面"，输出就是 `scan → gap(reason=forbidden_region) → scan`，禁区内没有扫描点。

### 5.4 行间：换行 gap（v1 不规划换行运动）

上一行最后一个 segment 的末点到下一行第一个 segment 的首点之间生成 `gap(reason=row_turn)`，记录两端点与弦长。不生成沿表面的连接点，不生成抬升点，不生成空间直线。整条轨迹的顺序因此是：行 0 的各 segment → row_turn → 行 1 的各 segment → row_turn → …。

### 5.5 重采样与逐点支持证明

- 每条折线按弧长重采样，步长 `sample_step_mm`（默认 1 mm），端点保留；相邻采样点三维弦长 ≤ 步长。
- 平面与三角面的交线是该三角面内的直线段，沿它线性插值得到的点精确落在三角面上（原型实测到面平面距离 1e-17 m），因此每个采样点都能给出 `triangle_index`，`geometry_support=measured_mesh` 是逐点可验证的事实，不是声明。
- 点字段：`xyz_m`、`row_index`、`route_index`、`geometry_support`、`triangle_index`、`pixel`（见 5.6，仅显示与门禁）。深度只在 `xyz_m[2]`，不重复存。
- 行统计：`depth_min_m / depth_max_m / depth_span_m`、有效长度、segment 数、gap 数与原因分布；整体统计：segment 数、gap 数（按原因）、点数、扫描长度（只累计 segment 内弦长，**不含 gap 弦长**）、行数、总深度范围。

### 5.6 像素投影（利用 W0 = 初始相机的事实）

W0 就是初始彩色相机坐标系，任意 W0 点 `p` 投到参考图像只需去畸变针孔投影：`u = fx·x/z + cx`，`v = fy·y/z + cy`（`K` 取 `view_reference.undistorted_intrinsic`）。用途：

- gap 的禁区判定（`fixed_rgb_geometry.polygon_contains`）；
- 给每点附带 `pixel`，使现有 `route_motion.MotionPlayer`、`path_presentation.render_diagram` 通过适配器即可播放和画路线图；
- 像素只是显示与门禁用途，JSON 里标 `pixel_semantics=display_and_exclusion_check_only`；投影落在图像外的点记为 `unsupported_geometry` 并从 segment 中切出（它仍在网格上，但无法做禁区判定，v1 保守处理）。

### 5.7 坡度与实际行距（报告，不隐瞒）

平面等距切片在倾斜处的表面行距是 `d / cos θ`（`θ` 为面法线与 `n` 的夹角）。原型区域上 5 mm 平面行距对应表面行距中位 6.1 mm、P95 14.4 mm、24% 的三角面超过 7.5 mm（第 10 节）。处理：

- v1 必做：按行输出实际表面行距估计（相邻两行对应点之间的网格边图最短路下界，复用 `surface_spacing_report` 的思路），`spacing_semantics=parallel_plane_spacing_not_uniform_surface_spacing`，超过 `d × (1 + spacing_tolerance)` 的行在报告和俯视图中标黄。
- v1.1（已确认不在 v1）：`adaptive_rows=true` 时，对实际行距超限的相邻行之间插入中间切片（插入的是真实切口，不是补点），迭代到满足或达到最小行距 `d/4`。
- 需要严格等表面间距时，继续用现有 `surface_spacing_plan`（它按网格边距离等值线走），两种模式在 UI 上并列，不互相替代。

### 5.8 预算与取消

沿用现有约定：采样点上限 200 000，时间预算 120 s，`check()` 回调支持取消（`TaskControl` / `GeometryBudget`），超限直接拒绝并说明"增大行距或缩小区域"，不留部分文件。

### 7.1 `from_projection_plan` 适配器对 `triangle_index` 的处理

旧 plan 的每个点带的是源 TSDF 网格的**全局**三角面索引（`raster_path`、`serpentine_plan`、`metric_path`、`surface_spacing_plan` 都写 `triangle_index`）。适配器按下面顺序处理，任何一步都不得伪造：

1. 取绑定的区域网格：优先该区域的导出 PLY（`region_N_mesh_m.ply`，校验 `file_sha256`）；没有导出时用 `region_mesh(source_mesh, region.triangle_indices)` 现场生成，两者面序相同（都是全局索引升序）。JSON 记录 `bound_region_mesh: {source: exported_ply | rebuilt_from_source_mesh, sha256}`。
2. `local = sorted(unique(region.triangle_indices)).index(global)`；全局索引不在区域内的点（例如旧 connector 落在允许区之外）视为不可映射。
3. 对每个点做 ≤ 1e-6 m 几何验证；通过则 `face_index_source=mapped_from_source_mesh_index`。
4. 不通过或不可映射的点，在绑定区域网格上做几何重定位：在点的邻域内搜索满足 ≤ 1e-6 m 的局部面，多解取最小索引；成功则 `face_index_source=relocated_geometrically` 并计数。
5. 仍失败的点**不能进入** `SurfaceTrajectory`：整次适配拒绝并报告哪些点、哪条链失败，不得删点、不得挪点、不得改旧文件。
6. 适配只读：旧 `path.json` / `plan_binding` / CSV v2 逐字节不变（测试对比哈希）。

依赖：`trimesh`（已登记，切片与连通分量）、`open3d`（已登记）、`numpy`、`PIL`；**不新增 scipy**。

| 深度 | 轨迹 Z 范围 518–833 mm |
| 耗时 | 切片 + 拼链 + 排序 0.10 s（numpy）；连通分量 0.04 s |

结论：算法本体很快，逐点表面支持可以严格证明。这块真实网格的缺失很多，v1 会如实输出大量 `surface_gap`，这是当前 TSDF 网格的数据质量信号，正确的改善方向是上游（采集覆盖、补洞策略、网格清理）或放大行距，而不是在规划器里制造点。

## 11. 风险与限制（写进输出与文档）

- 轨迹贴的是 5 mm 体素 TSDF 表面，不是皮肤真值；深度一致性只在采集会话内成立；没有任何实物精度验证。
- W0 只对该会话有意义；换会话、复制目录后来源校验会降级为 unknown，与现有标注同样拒绝。
- 单视角局部采集：背面和遮挡处没有几何，轨迹只覆盖可见表面；缺失 = 缺测，不是平坦。
- `surface_gap.detail.inferred_cause` 是启发式，可能把自遮挡或卷曲表面的缺口判错；任何逻辑都不得依赖它。
- 平面等距 ≠ 表面等距（5.7）。
- PCA 回退阈值附近的输入在不同机器上理论上可能选到不同分支；报告里的 `ratios` 会显示是否贴近阈值。
- gap 处、换行处**没有任何运动定义**；`MotionPlayer` 在 gap 处暂停只是演示语义，不是过渡规划。
- 没有姿态、没有速度规划、没有执行接口。

## 12. 未来接入底座与机械臂时的扩展点（本阶段一律不做）

- 自由空间过渡：由运动执行层决定如何跨越每个 gap（按 reason 区分：`row_turn` 可考虑贴面过渡，`surface_gap` / `disconnected_surface` 只能离面），届时才引入抬升、避障、速度约束。
- 桥接：如果将来允许在小缺口上"视觉连续"，那也是执行层的过渡策略，不是表面轨迹的一部分；`SurfaceTrajectory` 里永远不出现补点。
- 逐点姿态：由局部法线 / 扫描方向构造 `T_W0_tool`，届时才引入 Pitch / Yaw / Roll 或 Rx / Ry / Rz 字段与离面距离。
- 底座外参：`T_B_W0` 通过手眼标定获得，轨迹只需左乘，W0 定义不变。
- 执行：IK、ROS / MoveIt 对接；届时 `execution_ready` 才可能为 true。
- 投影式 planner 的多帧 / 多视角版本：换掉"点如何产生"，输出模型不变。
- `adaptive_rows`（v1.1）。
