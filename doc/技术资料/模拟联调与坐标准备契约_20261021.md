# 模拟联调与坐标准备契约

面向软件维护者与未来厂家适配人员。对应当前硬件预备迭代；原始采集、几何质量、覆盖证明及研发执行边界保持。

## 兼容扩展

原 [硬件接口预留契约](硬件接口预留契约_20261020.md) 的五个意图、字段及校验语义保留。`DeviceKind` 增加独立 `ultrasound_generator`。`Intent` 追加 `request_pause`、`request_resume`、`simulation_step`，均要求协议与明确能力；模拟步骤限定 simulation 来源和 `femto-simulation-v1`，不放进 `prepare`，没有真实运动/功率载荷。

`DeviceFeedback` 尾部追加 `output_off: bool | None`，不借用 `motion_stopped`。`DeviceStatus` 单独记录持续状态，序号在一个设备绑定内递增；请求反馈序号仅在单个请求内递增。绑定含设备、种类、来源及连接代次；请求 ID 与意图同时核对。未知保持未知。

`DeviceConfiguration` schema 为 `femto-device-configuration-v1`，连接配置不能赋予 capability/readiness/connected。能力由适配器返回。真实、回放、未配置适配器当前明确拒绝连接，不静默回退模拟。模拟设备不占用真实相机。

配置保存在 `outputs/hardware_configuration/<device_id>/<revision>.json`；场景保存在其 `simulation_scenarios/<scenario_id>/<revision>.json`。同修订不可覆盖。读取真实配置可查看静态字段，连接仍明确拒绝；来源标签与型号不能证明连接或反馈能力。

## 模拟步骤与状态

`femto-simulation-scenario-v1` 保存软件测试时钟、能力及故障脚本。默认收到延迟 0.03 s、完成延迟 0.25 s、心跳 0.1 s、请求期限 2 s、状态最大龄 0.5 s、退出期限 2 s、调度检查 0.02 s、关键批次 256 事件。这些是软件场景预算，不是硬实时保证或厂家控制周期。

默认步骤输出状态为关闭。只有场景显式设置 `step_output_active=true` 才报告模拟输出活动；这是软件状态，不按扫描/连接角色推断超声输出。连接角色、断点和无工具姿态保持原方案内容。`contiguous-role-runs-v1` 将一个扫描段中连续相同角色的边作为一个确认步骤，边角色沿用原 `surface_trajectory` 的末点语义（缺省 scan）；断点独立作为 gap 步骤，不跨断点运动。全部原始路线项留在冻结快照，未更改源路线。

协调状态包括未准备、检查中、可开始模拟、运行、暂停请求/确认、继续请求、停止请求、已停止/取消、已放弃未运行、成功、失败、未知、中断待核对。成功必须经过全部参与设备的停止/输出关闭确认；取消某请求不证明全局停止。暂停和停止分别核验机械臂 motion_stopped 与输出设备 output_off。未知结果保留资源，显式销毁旧模拟实例后才释放；不用于真实设备强制确认停止。

`abandoned_unrun` 仅从未准备进入。协调器要求零请求尝试、无 pending/请求组/记录缺口、零步骤且未持有运行资源；`ExecutionStore.abandon_unrun` 在短写事务内再次要求原未准备状态、冻结事件、相同事件序号且无请求/准备/开始事件。成功追加 `task_abandoned_unrun` 后释放任务所有者与冻结数据，保留实例；失败保留原任务。它不表示任何设备停止确认。在途及可能已发送任务继续沿用停止/未知流程。

最终停止阶段仍处理故障和事件缺口：停止已在途时只撤销正常结束意图，不重复发送同一组停止请求。全体静止/关闭已确认但记录或状态有缺口时记为失败；某已确认设备随后报告活动或未知、其他设备尚未确认时立即记为结果未知并保留资源。成功还要求全部冻结步骤已确认，不能由请求结束意图跳过步骤。暂停已确认后静止/关闭反馈失效同样撤销继续资格。

同一实例冻结下一任务时清空上一任务的前置检查、停止期限、控制组及错误上下文。状态心跳以独立显示修订更新 Qt 快照，可合并显示但不制造关键事件或创建数据库；检查和事件正文不因只有心跳变化而重复重排。

同代次晚到故障或矛盾物理状态撤销就绪；正常或失败终态后的较新有效请求反馈若不再证明机械静止或输出关闭（包括 None 未知），结果转为未知并保留资源。按设备种类检查相关物理字段，无关字段未知不报警；旧代次/重复/乱序记录拒绝原因。变更无关草稿不影响冻结任务，当前资产原地改写或设备配置被替换则停止下发。恢复重新检查来源、绑定和时效。

带 `at_s` 的状态故障以首次模拟连接为时间零点；请求类故障以设备、意图及 occurrence 选择请求。场景回读保留原能力、延迟和故障列表，不用默认场景替换失效配置。只有固定底座或没有参与设备时，前置检查未通过，不产生准备/步骤请求。

`at_s` 仅接受 disconnect、reconnect、fault、base_unlock、base_move、base_unknown 和 mount_unknown 状态事件。延迟、拒绝、无响应、停止不确认及重复/乱序/旧代次等请求故障使用 intent/occurrence；混用在场景加载阶段拒绝。适配器轮询异常和未知事件类型按关键事件缺口处理，结束确认仍受原场景期限约束。

原生方案绑定 `trajectory_files.json` 登记的输出、对应区域清单资产和核验来源；同目录未登记草稿不参与冻结。便携包绑定所选 ZIP 及可核验的外部采集来源。完整来源、目标、覆盖与采集完成核验仍走 `planning.saved_source`；冻结、检查、开始、继续和回看重新核对完整文件 SHA-256。运行轮询只比较设备/文件号、大小、mtime/ctime 签名，发现变化即停止。这是应用文件变化检测，不是对抗性文件系统防篡改保证；开始/继续不能依赖旧签名跳过 SHA。

方案摘要核验与 SQLite 写入可能长于场景状态年龄，协调器在发送新步骤前重新轮询。超时判断先接收当前批反馈，再以批开始时刻检查尚未完成的请求；收到回执的记录耗时不能把尚未轮询的完成反馈误判为无响应。真正无心跳或无请求响应仍在下一次有界轮询阻断。请求意图写入或发送确认记录失败立即阻止其他非停止请求，停止与反馈仍继续。

状态时效在本批事件接收完成时核验，避免将随后串行写入的耗时误算为设备失联。发送下一步骤前另以当前单调时间逐设备核验；本地写入耗尽有效年龄时本批不发新步骤，下一次有界轮询先取反馈。即使写入长期较慢，接收时本已过期、缺少心跳或时钟域不同仍会阻断；状态最大龄保持原场景值。

完成阶段与设备故障分开判断：`completed` 同时含 error 或未就绪时不能证明步骤成功；停止完成还需独立 still/off 反馈。所有者退出会尝试关闭每个模拟设备；关闭失败记录未知并保留资源，发出结束通知，不制造成功停止。

## 坐标与间隙

`T_AB` 将 B 转到 A，平移统一米，旋转矩阵；C 是对齐深度所对应的彩色光学 RDF，W0 为首个有效彩色相机。多字母坐标名用下划线。组合检查端点及轴约定，缺失外参不补单位矩阵。安装记录独立保存到 `outputs/installation_calibrations/<id>/<revision>.json`，不可覆盖原始数据集 calibration。

`femto-installation-transform-v1` 区分 synthetic 与 measured_import_unverified；记录设备、安装、来源、版本、原始单位/旋转约定和时间。导入不获取实测资格。旋转正交和行列式容差为 1e-6，齐次底行 1e-9（float64 文件结构策略，不是测量精度），已有里程计 2e-2 规则不改。

导入来源须列出文件路径与 SHA-256。`evidence_status` 区分合成、来源摘要可核验但实测未合格、来源变化/缺失；不把证据摘要相同解释为标定精度合格。测量误差仍为 null。

组合支持 `T_BC=T_BF·T_FC`、`T_W0_C=T_W0_B·T_BF·T_FC`、`T_W0_U=T_W0_B·T_BF·T_FU`；刚性安装已核验时支持 `T_UC=inverse(T_FU)·T_FC`。本轮实时空间上下文只开放显式合成测试。真实安装与同步未知时不可用。首帧公式只允许参考首帧；底座移动/解锁/未知使当前 `T_W0_B`（将 B 坐标转换到 W0）及派生链失效，要求新会话，不在任意时刻套公式。旧冻结记录不变。安装碰撞/拆装未知撤销相应关系。

`SpatialContext.current` 必须传入 `camera_timestamp_s`，并核对与法兰位姿同一时钟域、同步允差与位姿年龄；缺省时间不能自动借用法兰时刻证明相机同步。设备与安装 ID、标定版本和空间代次绑定改变同样撤销当前上下文。

`femto-axial-gap-v1` 使用 float64 前向射线与网格面求交，距离容差 1e-9 m、重心容差 1e-10；退化面跳过计数，同距边/顶点交点合并；最近命中背面或不支持面阻断，不挑更远的“可用”面。支持要求原始 confidence=1.0 与原始视角信息；修复 .3 或未知 0 不证明间隙。遮挡未知/已知遮挡、无交点、轴为零、标定不适用、实时输入过期均返回距离 null。纯函数不读取时钟，由调用方核验适用性；历史离线和合成结果不代表实时患者间隙，不声明外壳碰撞、接触力或临床精度。

## 存储、资源与恢复

`history.sqlite3` 继续由 HistoryStore 独占 schema v1。`execution.sqlite3` 当前写 schema v2，支持只读 v1/v2，v1 首次写事务升级到 v2；升级仅追加迁移记录及版本，不改原任务和事件。v2 记录新增 `abandoned_unrun`，旧版事件软件拒绝打开 v2，降级需恢复旧备份。以任务 ID 和本地事件序号追加；状态快照与关键事件同一短事务提交。SQLite WAL、synchronous FULL、写锁期限 0.1 s；两个文件不用 ATTACH，不引用旧库行 ID。数据库首次写任务才创建。本轮交互及 v2 验证见[六项交互完善记录](../历史开发记录/模拟联调六项交互完善_20261022.md)。

任务状态及有序事件在同一个 SQLite 只读事务内读取；源资产 SHA 核对在事务外进行，能取消。恢复事件、状态与 interrupted 标志一起提交；失败一起回滚。回看报告原来源摘要变化，不修改原任务快照、不重新绑定当前方案。导出使用有取消检查的原子写入，失败不留下伪完整文件。

中断恢复在遍历任务、读取事件和追加恢复记录前检查关闭/取消；取消时释放当前恢复所有者锁，不补造状态。备份清单 schema、有限时间范围及非跨库原子声明无效时显示时间范围未知，保留任务和事件只读回看。

冻结任务拥有独立进程锁，参与资源另有模拟实例资源锁。历史恢复先核验所有者锁已释放，仍在运行的其他窗口任务不被误标中断。正常运行资源在全部停止确认后释放，未知资源仅在显式关闭模拟实例时释放。锁目录由 femto.paths 管理，不复用元数据发布锁。

分发前先记录意图，再记录发送结果和反馈。崩溃窗口没有跨设备原子性，重启任务显示中断/待核对，不重发。日志失败阻止新步骤，仍发送停止并处理反馈；恢复可写后记录序号范围及缺口数，不补造状态。关键队列有界，溢出报告缺口并停止/未知处理。显示快照可合并，关键事件不可静默丢弃。

双库在线备份分别生成快照，manifest 明确时间窗口及非跨库原子性。恢复必须同时恢复两文件且不混用旧 WAL/SHM，原图像/网格/方案资产需要单独保留。操作见 [模拟联调说明](../使用说明/设备管理与模拟联调.md) 与 [双库备份说明](../使用说明/SQLite历史记录与备份.md)。

恢复时保留 `history_metadata/manifest.json`。运行回看显示其开始/结束时间窗口；缺失或清单无法读取时不能声称两库同一时刻。监控和回看展示结论摘要与最近 400 条事件，导出保留全部原路线和事件。显示摘要不改变待检查像素、断点、覆盖结论或物理资格。

所有模拟任务、事件、检查和测距 JSON 固定 `execution_ready=false`、`physical_accuracy_verified=false`，运行来源与方案来源分开。原参数 `values_status` 不升级为设备实测参数。
