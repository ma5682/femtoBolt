## 开发前需要细化的约定

### 1. 区分保存版本、计算修订和目标身份

当前 `region_project.save_project()` 的 `revision_id` 是每次保存生成的 UUID，用于历史版本关系。方案建议的输入摘要修订具有另一种含义，不能直接覆盖现有字段。

建议保留保存版本及 `parent_revision_id`，新增独立的计算修订摘要，覆盖参考图/深度、标定与变换、规范网格、选区、质量配置、作用模型、算法及数值策略。请求代次只用于异步安装控制，不作为输入摘要。目标身份绑定原选区与对应几何；质量阈值、行距或宽度改变会使计算结果失效，但不会把质量剔除后的范围重新定义成原目标。

名称备注和纯页面导航是否参与摘要应明确排除，沿用现有 `region_signature()` 区分元数据和计算输入的做法。区域修改或模型更换则建立新的目标/计算修订。第一版每次全量重算。

### 2. 目标台账与路线采用同一份规范网格

当前 [canonical_region_mesh()](E:/测试3D人体关节坐标-ui/femto/planning/surface_workspace.py:189) 明确使用与 PLY 导出一致的 `float32 → float64` 表示。若目标裁剪基于原始 float64 网格，路线和覆盖却基于另一份坐标表示，边界包含、面积和回读就可能不一致。

P0 应冻结规范几何表示及摘要，记录原网格面编号到规范局部面编号的映射。目标建立于质量筛选前的原选区，使用明确的参考图像坐标约定；当前链路是绑定的去畸变参考图及相应内参，不能直接混用原始畸变 RGB 像素。遮挡、深度冲突或裁剪归属不确定时保留未定位状态。

可定位但质量未通过的单元仍属于目标台账；无可靠定位的像素单独计数，不虚构三维面积。任何进一步细分均保留原面与父子对应。

### 3. P2 所需的保守几何判定应提前实现

方案中“同一球包含三角形三个顶点，则包含整个平面三角形”有凸性依据。但这个结论要求目标单元构造正确，包含比较不会因浮点误差误判，且覆盖种子与相应表面的绑定可核验。

当前 [_supported_chord()](E:/测试3D人体关节坐标-ui/femto/planning/quality_constrained.py:116) 使用平面、重心和区间容差，不能作为严格模式已经完成的证明。**P2 可以先于完整 P4 交付，但其目标裁剪、种子定位和同球包含判定必须先能保守返回“确认/不包含/数值未确认”。** 不确定的情况保留未确认。不得把旧容差直接清零，或把吸附后的种子当作未经重新检查的原路径。

纯几何谓词可放入低层几何模块；目标/修订/证书模块放入规划层，界面消费结果，保持现有分层。第三方精确几何库是否必要，应由小型原型和性能数据决定。

### 4. 明确名义模型与作用段角色

固定半宽球形模型可以先作为软件模型开发。名义计算采用 δ=0，只表示该模型不引入实际偏移，不能将未知配准或标定误差写成已证实为零。

旧 [checked_evidence()](E:/测试3D人体关节坐标-ui/femto/planning/quality_constrained.py:74) 要求配准和标定不确定性为 `None`；有界偏移应采用新证据类型与适用条件，不修改旧证据的解释。参考深度残差继续表示观测一致性。

当前路线点已有 `scan/connector` 角色，连接边由目标点的角色描述。首版仅明确的扫描作用边产生覆盖种子，连接边默认不计入。球内连通性基于共享表面及子边关系，不能按 XYZ 距离把邻近折叠层连起来。仅依靠整个三角形已经入球的邻接会比较保守，细分后仍无法证明时保持未确认。

### 5. 新格式必须覆盖完整读写链路

当前工作台、轨迹验证、规划导入和版本提示中存在明确的算法版本分派。新增覆盖字段或新算法后，需要同时接入规划绑定、验证器、导出清单、便携 ZIP、报告、历史读取及播放器。

可将覆盖证书版本与路径生成器版本分开记录：只增加覆盖核验时仍记录真实的 v3 路线来源；后续 P3/P4 改变生成或接纳规则时另用新算法版本。新结果包应将目标、路线、作用模型与覆盖证据绑定到同一计算修订。旧包缺少证书时显示“未进行该项核验”，通过生成新包完成迁移。

当前便携工程 `project.json` 上限为 100 MiB。大型叶单元、邻接和种子关系应使用有摘要、类型、形状、索引范围和大小限制的独立数组文件；禁止用巨量嵌套 JSON 撑大原清单。沿用既有 staging/publish，发布前验证语义一致性，发布完成后才更新当前引用。

### 6. 覆盖完整性与性能要同时有可验收目标

全量“目标单元 × 覆盖种子”遍历、无界细分或对所有候选使用精确运算，可能使交互不可用。现有路线有 200,000 级节点/边检查/输出预算，这不能替代目标裁剪与覆盖细分的新预算。

P0 应测量候选单元数、叶单元数、种子与单元比较次数、最大细分层级、耗时、峰值内存和取消响应。建议优先使用空间索引筛候选、批量包含计算和按需细分；跨修订局部缓存继续后置。预算退出保留未处理目标，不能缩小分母。

除了“确认集合不超过真值”反例，还要有明确可确认的正例，避免总返回零覆盖也通过测试：整单元在球内应确认；部分相交时细分应产生可复算的确认面积；球外、孔洞和异层表面不得误计；预算不足时明确未完成。

## 一个完整操作示例

选择右肩与体位 → 在真实画面确认扫描范围 → 采集并检查模型 → 涂抹工作区域 → 生成路线 → 分别查看“路径约束结果”“原目标几何待核验范围”“模型表面已确认覆盖”。

若存在待核验范围，可定位原因并回到标记页检查。仅返回页面保留结果；实际修改选区后，旧路径和覆盖证据一同失效，重新计算后再保存。即使可定位面积已全部确认，仍有未定位像素时也显示“另有目标范围待核验”。B2 交付到此形成状态、显示与保存闭环；C 阶段才增加对可用表面缺口的“补充规划”。

## 本次验证与可用样本

本次调用现有 `evaluate_coverage()` 做了一个独立合成反例：直角三角形两直角边均为 10 mm，中心附近有一条 0.4 mm 的段，有效宽度为 8 mm，即名义半宽 4 mm。三个覆盖采样点距离该段约为 2.220、3.549、3.642 mm，旧模块返回 **采样覆盖 100%**；三个顶点距离约为 4.575、7.275、7.366 mm，均在该作用范围之外。

这验证了采样 100% 不能当作整个三角形已覆盖。旧模块保留 `full_surface_coverage_verified=False` 的语义是正确的。该反例仅调用旧评估函数，没有把短段提交给当前 v3 的路线准入，不证明 v3 错误接纳，也不涉及物理作用范围。

脚本与实跑结果见 [`coverage_probe.py`](../../outputs/iteration_plan_review_20261008/coverage_probe.py) 和 [`coverage_probe.json`](../../outputs/iteration_plan_review_20261008/coverage_probe.json)。结果同时记录原方案与评估模块的 SHA-256。

当前工作区存在可用于 A0 的真实记录候选：`outputs/complete_demo_20261008_174650/`。其已读取元数据记载 `real_femto`、`published`、5 个重建输入帧、30,553 个三角面；关联原始会话 `datasets/scene_20261008_174618_local_cbe4e7b4/` 的 manifest 记载 80 帧。原始帧总数与选中/派生位姿帧数应分开冻结和追踪。这是已有元数据核对，尚未完成该样本全资产哈希、几何复核或 P0 性能基准。基线中较早列举的 2026-09-17 路径未在当前工作区找到，A0 不应继续仅依赖那组旧路径。
