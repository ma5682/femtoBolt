## 环境

三套互相隔离的虚拟环境，**不要合并**：

| 环境 | Python | 用途 | 安装 |
|---|---|---|---|
| `.venv` | 3.12 | 采集、几何、查看器、标注、规划、单元测试。所有非 gsplat 的 `.cmd` 默认用它 | `setup_environment.cmd`（版本硬编码在脚本里，不读 requirements.txt） |
| `C:\FemtoRuntimes\<workspace_id>\gsplat` | 3.10 x64 | **产品 3DGS 训练/查看运行时**：PyTorch 2.7.1+cu128、`gsplat==1.5.3`、`spz==1.1.0`。没有 open3d/cv2/trimesh，跑不了完整测试 | `setup_direct_gsplat_environment.cmd` |
| `.venv-3dgs` | 3.12（已死） | 内部 Splatfacto 历史对照，因传递依赖 GPL-3.0 PyMeshLab **禁止随产品分发**；旧环境数据保留 | 旧安装 CMD 已移除，不再提供日常入口 |

`.venv`：只装 `opencv-contrib-python`，`pyorbbecsdk2` 用 `--no-deps`，因此 `pip check` 会名义性报缺 `opencv-python`，属预期，不要"修复"。`psutil` 由 open3d 传递带入并被 `scene_temporal_fusion.py` 可选使用，但未登记到合规材料。

工作区专属产品环境：
- 产品环境直接创建于 `C:\FemtoRuntimes\<workspace_id>\gsplat`，工作区 ID 由仓库绝对路径派生；没有指向其他分支的联接，不回退全局运行时。
- 需要 CUDA Toolkit 12.8 `nvcc` + VS2022 C++ Build Tools；`TORCH_CUDA_ARCH_LIST=12.0`（RTX 5060 / sm_120）。
- `patch_gsplat_windows.py` 对已安装 gsplat 1.5.3 的 `cuda/_backend.py` 做精确字符串补丁；重装 gsplat 后必须重跑，版本不是 1.5.3 会拒绝。
- LPIPS 需要 torchvision 官方 AlexNet 权重 `alexnet-owt-7be5be79.pth`。训练器**不会**联网下载：手动下载到 `%USERPROFILE%\Downloads\` 后运行 `install_lpips_weights.cmd`，校验 SHA-256 后放进 torch hub 缓存。缺失或哈希不符时训练在优化前阻断；`--skip-lpips` 仅冒烟且不能验收通过。`TORCH_HOME` 与安装时不同会导致"缺失"。
- SPZ 由 `setup_spz_environment.cmd` 从工作区专属 `C:\FemtoRuntimes\<workspace_id>\spz-deps` 源码缓存构建；固定版本/哈希不变，PEP 517 后端未离线锁定，不能称发布级可复现。

版本被 `commercial_compliance_check.py` 的 `EXPECTED_PACKAGES` / `EXPECTED_GSPLAT_PACKAGES` 钉死。升级依赖时要同步改：该字典、`setup_*.cmd` 中的硬编码、`requirements*.txt`、`THIRD_PARTY_NOTICES.md`、`licenses/`。

## 长期技术分工（固定）

| 技术 | 固定职责 |
|---|---|
| PySide6 + Qt Widgets | 医师工作台 UI、工作流程、状态与参数、Dialog、History |
| VTK | 嵌入式三维 Viewport、Mesh/区域/轨迹显示、Pick、Camera Interaction |
| Open3D | Point Cloud、ICP、TSDF、Mesh processing 及其他三维计算 |
| pyorbbecsdk2 / Femto SDK | Femto Bolt RGB-D 设备连接、采集、时间戳与设备参数 |

业务状态和持久化数据独立于 Qt 控件和 VTK actor；采集与计算在后台执行，Qt 控件及 VTK 渲染对象由 GUI 线程更新。三维显示适配统一单位和坐标系，不用显示降采样结果替换计算输入，拾取须保留原始点/面编号。W0 几何以米传递到 VTK，不添加隐式轴翻转；视角变化只修改相机。移动相机继续使用同步位姿，eye-in-hand 为 `T_BC = T_BF · T_FC`。

迁移按页面逐步推进：首批接入规划与只读回看的 VTK 三维视口，保留固定 RGB 二维 Mask 标注作为区域编辑入口；采集预览与旧独立 Open3D 调试查看器尚未全部迁移，属于过渡实现，不再扩展为第二套正式工作台三维交互。三维计算及原生保存格式继续复用已有后端。渲染状态、区域、路线都是派生层，不覆盖完整场景原始 RGB-D；研发坐标不可称为临床治疗靶点，`execution_ready=false` 保持不变。

固定技术职责，不冻结库的未来升级；当前验证组合为 PySide6 6.11.2、VTK 9.5.2、Open3D 0.19.0、pyorbbecsdk2 2.1.2。两个运行时固定同一 VTK 版本，3DGS 环境仍不引入 Open3D 或设备 SDK。依赖来源和许可证记录见 `licenses/vtk/`。

## 架构

2026-09-20 起源码位于 `femto/` 包；2026-10-21 硬件预备迭代登记 `execution` 后，依赖层表共有 17 层。**文件基名沿用迁移前的名字**，文档与历史记录可对应文件。包入口以 `python -m femto.<pkg>.<module>` 从仓库根运行；`tools/` 为独立诊断脚本。数据树统一由 `femto/paths.py` 管理，新增设备配置、安装记录、模拟资源和执行数据库位置，不写入原 RGB-D 数据集。

## Windows / 中文路径注意事项

仓库路径含中文，新代码沿用同样写法：

- **不要用 `cv2.imread` / `cv2.imwrite`**。统一用 `io_utils.imread_unicode` / `imwrite_unicode`（`np.fromfile` + `cv2.imdecode` / `imencode` + `write_bytes`），或 PIL。不要再在模块里复制私有实现，也不要为公共 IO / 几何函数创建 `_read_image`、`json_dump` 等兼容别名；调用点和测试 patch 目标都直接使用公开名。
- **Open3D 原生读写**走 `fusion.write_point_cloud_safe` / `read_geometry_safe`，先落到 `%LOCALAPPDATA%\FemtoPatientPose\native_io` 的 ASCII 临时路径再搬运。`fusion.py` 在 import 时就读 `os.environ["LOCALAPPDATA"]`，无该变量的环境 import 即崩。
- 带 `confidence` 属性的自定义 PLY（`depth_confidence_cloud`）被 Open3D 重读时会丢掉该属性，下游融合必须读 depth + `.npy`，不能读回 PLY。
- **Open3D Filament 资源**在中文路径下加载失败；`scene_demo_viewer._open3d_ascii_resources()` 镜像 wheel 资源到 `%LOCALAPPDATA%\FemtoSceneDemo\open3d_resources_*`，`live_point_cloud` 子进程也依赖它。
- **CUDA JIT / SPZ C++ reader** 需要 ASCII 路径：gsplat 使用工作区专属 ASCII 环境，原生 I/O、MediaPipe 模型、Open3D 资源及 ML 缓存按工作区 ID 隔离。
