# 全流程响应与计算提速（2026-11-04）

本轮以单贡献帧为优先对象，检查采集写入、固定参考、涂抹、局部重建及模型检查、规划、保存和回读。接入四项等价优化，改善交互响应及多个计算阶段；**尚未做到每个阶段都明显变快**。采集编码试验没有净收益，固定参考准备已在本次样本的约 0.08–0.12 秒内，规划表面准备未显示改善，均未为追求数字放宽检查。

工作台既有后台线程方式下，真实单贡献帧样本从已有位姿及确认选区到双格式保存、独立回读的直接墙钟均值为 **89.788→80.430 秒，减少约 10.4%**。首次普通主线程对照为 **100.775→101.128 秒，没有整体收益**；两组完整保留，不能用第一组旧值对第二组新值计算加速比，也不能把后一组收益全部归因于线程方式。

## 修改内容与适用边界

| 模块 | 修改及作用 | 保持的约束 |

| `femto/geometry/triangle_components.py`、`local/local_geometry.py`、`geometry/fusion.py` | 以整数共享无向边计算面连通标签和数量，供局部小分量过滤、导出统计使用 | 不计算不需要的面积，不改过滤阈值、顶点、法向或水密/绕向检查；仅共享顶点不连通；非流形及退化面与原生行为对照 |
| `femto/geometry/pixel_clip_batch.py`、`planning/target_surface.py` | 裁剪批上限 64→256；后者仅同步预取上限说明 | 原行内算术、逐候选消费/计费顺序、精确回退和显式回放前沿保留；不复用跨模型或跨请求结论 |

整数连通性采用每面 256 字节的保守工作量估计和 384 MiB 可选工作预算，最多 64 轮。超限、不支持输入、可选分配失败或未收敛回退原 Open3D 聚类。该估计不是进程 RSS 上限。批裁剪最多提前准备 255 个后续候选，准备量有界；预算仍在原循环消费时计入，停止前沿不提前推进。

本轮没有新增依赖或运行时编译，没有改写已有点云原生内核、低级别无损压缩或线程调度实现。保存格式和算法版本不变，新旧读取器交叉回读验证了本次实现的兼容范围。未提交、推送或打包 EXE。

## 单帧、多帧及局部计算范围

用户继续使用：采集一帧或多帧 → 固定参考图 → 手动选区 → 局部重建 → 模型检查 → 几何路线 → 保存与回读。内部按**实际局部贡献帧数**选择：一帧贡献采用实测深度像素邻接建面；两帧及以上贡献采用原局部 TSDF；零贡献明确失败。采集多帧但只有一帧贡献仍走单贡献分支，不要求用户选择算法。

已有逐帧内参、实际位姿和深度一致性映射保持。原 RGB-D 可完整保存，准备阶段可读取整帧；建面/积分仅接收局部掩码筛出的深度及必要支持带。支持带没有成为规划目标，缺深度、遮挡、内部留空和分离区域没有被补造或删除。

本次真实输入来自 `outputs/complete_demo_20261103_092829/reconstruction`，1920×1080，目标像素 237306、实际贡献帧 1，保留 40 mm 工程支持带。参与局部输入的有效像素/点 546948，完整测量面为 546873 顶点、1089433 面；既有规划派生表面为 34484 顶点、64655 面。各轮密度、输入范围及产物一致。原始全图读取与真正建模输入在来源记录中区分；`test_region_first_reconstruction.py` 还检查实际 TSDF 接收局部输入、多帧映射遮挡拒绝、缺深度意图保留和单贡献分支。

本轮没有调整规划派生表面的表示、5 mm 映射位移限值或原表面深度核验，也没有将显示降采样计作计算优化。质量报告的内部点面一致性中位/P90/P95 均仍为 0 mm、第二层比例仍为 0.5094177142982513；这些是该实采桌面样本的内部指标，不能视作真实相机、人体或临床精度验收。

## 测量方法与环境

- Windows 11 10.0.26200，Intel64 Family 6 Model 198，18 个逻辑 CPU，本机物理内存约 15.38 GiB。Python 3.12.10、NumPy 2.2.6、Open3D 0.19.0、PySide6 6.11.2、psutil 7.2.2。未安装 SciPy/threadpoolctl，不假设原生线程池数量。
- 冻结旧代码 396 份、新候选 397 份（含基准脚本、C 和 PYD），所有实际执行的 Python 导入及原生模块单独留摘要。接入时复核全部 397 份候选与当前源码一致，仅原有 CRLF 文件的换行可不同。
- 两组分别采用串行 A→B→B→A，每次新进程，相同输入、预算与默认线程环境，保留系统文件缓存；首轮/后续轮次分别列出，未声称冷盘测试。细分埋点只用于定位，完整对照关闭。
- 第一组在普通主线程执行。开始 A1/B1 时记录到另一个全量回归进程，B2/A2 及第二组开始时未再观察到该进程。未终止或调整它；其他系统负载仍可能存在。
- 第二组在独立工作线程调用工作台原有 `interactive_task_thread()`，旧/新两侧均成功采用相同的 High QoS 和首选处理器提示。没有更改进程优先级或 CPU 亲和性。工作线程方式与外部负载同时不同，因此不从两组差异推断单因素原因。
- 各阶段互不嵌套；总墙钟直接计时，另含阶段之间必要处理，不等于阶段简单相加。总墙钟从已具备位姿及确认选区开始，不含现场传感器采集/跟踪、手工操作、进程导入或真实窗口/GPU 显示。重建行包含其内部质量报告，不再将细分检查时间重复相加。
