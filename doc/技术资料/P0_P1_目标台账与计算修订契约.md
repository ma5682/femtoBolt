# P0／P1 原目标台账与计算修订契约

当前版本：2026-11-04。对应[后续迭代方案评估](后续迭代方案V1.0_开发可行性评估_20261008.md)中的 A0、A1、A2。当前路线生成器保持 `quality-constrained-surface-v3`；本契约约束原目标账目和输入绑定，P2 覆盖证书及 P3 补规划由各自契约约束。

## 1. 三种身份分别保存

局部重建的 `local-route-geometry-v1` 产物配置不再生成点云辅助统计、Gaussian、照片纹理、训练目录和展示报告；这不是新的路线算法或目标版本。完整测量网格及网格法向、参考 RGB-D、实际位姿、原选区和来源绑定继续进入下述计算修订。移除点云显示法向会改变中间点云 PLY 字节，不允许据此省略规范网格、路线及独立保存回读核验。详见[局部流程移除辅助计算](局部流程移除辅助计算_20261104.md)。

| 身份 | 含义 | 变化规则 |
| --- | --- | --- |
| 保存 `revision_id` / `parent_revision_id` | 区域工程的保存 UUID 和父版本 | 沿用原有保存、另存和历史关系，不改为内容摘要 |
| `femto-planning-computation-v1.sha256` | 一次计算的完整输入摘要 | 任一计算依赖变化即改变；不支持跨不同修订的局部缓存 |
| `target_id` | 原选区及其参考几何身份 | 绑定参考证据、规范网格、原选区和目标裁剪策略；质量资格、行距、宽度和路线算法改变不缩小或重命名原目标 |

计算修订由[planning_revision.py](../../femto/planning/planning_revision.py)统一生成、验证和比较。依赖包含十组：

| 输入组 | 实际绑定内容 |
| --- | --- |
| `image` | 已加载 RGB 数组、原图有效像素数组的 dtype、shape、SHA-256 |
| `depth` | 参考深度数组、最小与最大量程 |
| `calibration` | 实际投影内参与完整参考图绑定 |
| `geometry` | 源几何摘要、规范顶点数组、原顺序面数组 |
| `reference` | 原点、局部来源、任务及部位体位上下文、坐标系与单位 |
| `selection` | 原区域的计算字段、选择意图、支持记录及原面绑定 |
| `quality` | 当前固定的参考图质量规则与未知不确定性 |
| `effect_model` | 现有 v3 宽度约束模型及完整参数记录；覆盖证书为空 |
| `algorithms` | 路线 `quality-constrained-surface-v3`、目标 `reference-pixel-clipping-v1` |
| `numerics` | 规范网格、像素单元、裁剪与面积语义 |

数组摘要读取实际内容，不依赖缓存的 `store.digest` 或文件名。区域和任务的显示名称、备注、创建/更新时间等元数据，以及保存 UUID、请求代次、页面位置和便携源网格文件位置，不作为计算依赖。采集参考身份仍须绑定。

完成结果只有在**完整输入摘要完全相同**时才能复用。已有路线参数改动后恢复到完全相同的完整输入，可恢复该路线的可用状态；人工核对会清除，仍需重新核对。这不是对不同修订进行局部复用。

## 2. 构建原目标，再附加有效域资格

[surface_workspace.generate()](../../femto/planning/surface_workspace.py) 的低层 API 默认按以下顺序处理：取得当前修订及参考质量证据 → 对完整源网格按原选区构建台账 → 构建旧 v3 有效域 → 给台账附加质量资格 → 保存规划输入及评估 → 调用既有候选生成和块内重连。

### 工作台默认按需计算面积

根据“显示可简化、最终保存路线坐标保持正确”的产品要求，Qt 新建路线显式传入 `defer_target=True`。面积台账不参与候选路线和块内重连的数值输入，因此暂存完整绑定输入与有效域，省去逐像素候选索引、遮挡裁剪和面积扇形构造。路线坐标、源面、点序、分段、作用宽度、深度及选区检查仍走原路径；显示、保存和回读继续使用同一条路线。

待计算资产的 schema 为 `femto-original-target-surface-deferred-v1`，文件名及数组清单与普通目标一致。三个工作量预算及 `seconds` 均为 0，`metrics.stop_reason=deferred_by_request`，全部构建计数为 0。叶单元数组为空、重复面映射为空，表示尚未检查，并非源网格没有重复面。选中像素保留参考深度缺失、量程外和无源像素状态；其余为未处理，不能获得“已定位”资格。总目标面积保持未知，覆盖未核验。界面显示“面积与覆盖尚未计算”，不把这些像素当作已经发现的几何缺失。

保存和独立打开仍检查输入、数组、质量域、状态及完整路线。待计算状态按轻量规则独立重建，即使 `reproduce=False` 也不能通过重新封装摘要将其变成已定位目标。已有完整或分块台账继续原几何/面积重放，不因该模式而跳过。

点击“计算面积与覆盖”时，`target_preparation.prepare()` 核对当前输入并用原完整预算建立台账，保留原路线数值内容，只更新派生资产与绑定；旧方案写入独立来源记录。随后才进入 P2。严格构造入口也先准备完整目标；后续 P3/P4/P5 使用原证据契约。直接覆盖 API 对待计算资产报错，不能把空面积数组当作完成覆盖。准备失败、取消或输入变化不替换当前方案。低层完整构建默认值、旧格式解释及历史结果保持；旧程序不认识新 schema 时应拒绝读取，需要当前源码版本。

目标构造不以有效域合格面作为输入，也不局限于旧 `triangle_indices` 的面心选面结果。因此，边界处面心在选区外、但确实与选中像素单元相交的源面，可以进入原目标；它们的局部路线面编号为 `-1`。没有有效面、候选失败或路线约束拒绝时，已建立的台账及修订仍进入 `planning_assessment.json` 对应的输入快照。

### 几何与像素约定

- 坐标为 W0 / `world_rdf`，`+X` 右、`+Y` 下、`+Z` 前，长度为米，面积为平方米。W0 是初始有效彩色相机坐标；缺少可核验的 `initial_color_camera` 原点时拒绝构造。
- 参考像素是当前绑定的去畸变图及其内参，不是任意原始畸变 RGB 坐标。当前只接受与投影一致的无偏斜针孔内参。
- 完整源顶点统一 `float32 → float64`，保留原面顺序，与区域 PLY、现有路线规范几何一致。保留源面与旧区域局部面映射。
- OpenCV 整数坐标表示像素中心；像素单元为 `[u−0.5,u+0.5) × [v−0.5,v+0.5)`，边界归属使用 `floor(uv+0.5)`。保存闭合几何边不意味着重复累计面积。
- [pixel_clip.py](../../femto/geometry/pixel_clip.py)以像素反投影半空间裁剪三角面，近零裁剪符号可回退到针对二进制输入的有理数运算。共享源边、投影分离和前景完整遮挡可判定时按规则处理；遮挡、重叠或数值归属不能确认时保留未知。
- 完全相同的几何三角面去重，保存 `duplicate_faces` 映射；不把任意邻近或折叠表面当作相同表面。
- 可见裁剪多边形与参考深度的一致性沿用 10 mm 门槛，并检查其整个深度范围。该门槛是观测一致性规则，不是已标定的误差上界。

面积为规范网格上的 float64 **名义面积**。有理数符号回退不使全部裁剪、遮挡或面积计算成为严格误差证明；P2 的球包含、扫描种子和共享子边连通在独立覆盖证书中核验，P1 台账自身不判定覆盖完成。

### 单次建账中的等价计算

候选像素稳定排序后，以相邻像素编号变化确定分组，保留组内源面顺序。同一像素的四个裁剪平面只计算一次；每个平面仍先执行原符号误差检查和有理数回退，全部顶点明确位于内侧时保留原顶点数组，全部位于外侧时返回空多边形。候选、裁剪及停止前沿计数规则保持。

源面投影在同一次构造内按面编号缓存，最多4,096个只读投影；不同面对应可复用同一源面的投影。该缓存独立于下述成对分离缓存，均不跨构造复用；逐像素的裁剪多边形和遮挡判定仍重新检查。

每次 `_construct` 在自己的规范源三角形副本和当前内参上，建立最多 4,096 对源面的分离关系缓存。只复用原共享源边分离或原源三角形投影分离的结果；逐像素裁剪多边形的重叠、前后遮挡、参考深度、质量和像素未知状态仍按原顺序计算。每个像素中的面对应继续计入原成对预算，缓存命中不会免计。缓存随本次构造释放，不跨请求、修订或独立回读复用。

扇形三角化的面积计算展开原 float64 三维叉积，随后执行原点积、平方根及除以 2，省去通用轴处理。顶点顺序、运算顺序、像素父子编号、细小面积及异常处理规则保持。完整源目标的数组和指标须逐项对照；保存回读仍重建目标，按保存的停止边界核验预算中止的台账。诊断增加 `target.construct` 阶段，耗时不进入台账证明字段。

### 账目与状态

每个可定位叶三角单元保存 `source_face`、`local_face`、`pixel_index`、`parent_id`、`child_index`、`barycentric`、`area_m2` 和 `quality_status`。父编号为 `pixel_linear_index × source_face_count + original_face_id`；子编号是确定性多边形扇形三角化序号；重心顶点可以重建源面内的实际三角形。P1 自身不做覆盖自适应细分，`maximum_subdivision_depth=0`、`coverage_seed_comparisons=0`；后续覆盖分区单独保存。

像素区分：未选、完整定位、参考深度缺失、量程外、无源像素、无网格、深度冲突、遮挡/多表面歧义、数值未确认、预算未处理、像素单元部分定位。部分定位的已知几何保留，同时该像素计入含未知范围的像素数。

质量资格与几何独立：当前域合格、质量域排除、旧面心区域外、质量待核验。`with_quality()` 只更新资格，不能删除原目标几何。

| 摘要字段 | 解释 |
| --- | --- |
| `located_area_m2` | 全部已定位叶单元的名义面积 |
| `quality_eligible_area_m2` | 已定位且进入当前有效域的面积 |
| `quality_excluded_area_m2` | 已定位但未进入当前有效域的面积，含区域外与待核验资格 |
| `outside_route_region_area_m2` | 上一项中属于旧面心区域外的子集，不能再相加 |
| `unlocated_pixel_count` | 含任何未定位范围的选中像素数，包含部分定位像素 |
| `unlocated_area_m2` | 保持 `null`；不得用像素比例推造面积 |
| `total_target_area_m2` | 存在未知范围时为 `null`，否则是已定位面积 |

所有记录保持 `coverage_status=not_evaluated`、`target_completion=unverified`、`coverage_certificate=null`、`execution_ready=false`、`physical_accuracy_verified=false`。台账构造的 `stop_reason=complete` 只表示预算内遍历完成，不表示几何全定位或目标已覆盖。

## 3. 预算与取消

| 项目 | 当前上限 |
| --- | ---: |
| 源面 | 4,000,000 |
| 参考图像素 | 8,388,608 |
| 候选像素—源面记录 | 1,000,000 |
| 叶单元 | 200,000 |
| 遮挡/重叠成对检查 | 500,000 |
| 构建阶段时间预算 | 45 s |
| 台账数组总字节及 NPZ 文件/解压预算 | 512 MiB |
| 台账 JSON 清单读取上限 | 1 MiB |
| 原 `project.json` 上限 | 100 MiB，保持不变 |

候选、叶单元、成对检查或时间预算用尽时，保留全部原选区及相应未处理像素。数组资产或源输入超过硬上限时拒绝，不发布截断资产。保存工作进度边界，回读可重现相同的预算退出位置；不依赖再次运行时的墙钟速度得到相同结果。

45 s 是构建检查点的合作式预算，不是包括哈希、质量检查、压缩和磁盘读写在内的整次操作硬期限。测试可显式缩小预算；`seconds=0` 的特例是在候选索引后、像素处理开始处停止。取消沿用 `GeometryBudget.check()`，以异常中断，不把取消伪装成一个可发布的成功结果。实测方法和局限见[交付记录](../历史开发记录/原目标台账与计算修订_P0_P1_20261009.md)。

## 4. 异步安装与界面

`TaskRunner` 集中核对当前请求代次、忙状态、取消标记及调用方提供的输入修订；重复完成、旧代次或取消后的成功回调不能安装结果。规划页另绑定模型对象、输入代次、完整修订和当前画布掩膜。生成和保存使用冻结的网格、RGB、Depth、投影数组与来源元数据，避免 worker 混用新旧输入。

选区质量面板也使用冻结输入，并通过同一安装门禁核对模型、代次、内容摘要和画布。即使绕过常规 UI 信号原地修改深度，旧质量结果也不能回来覆盖当前状态。调用方准备任务后，如果结束一笔绘制改变了选区代次，任务不启动，提示先确认新区域。

路线页直接显示原目标含未知范围的像素数，详情、核对保存、完整报告及历史回看显示已定位面积和当前域外面积。核对页按实际侧栏宽度扩展换行内容，允许滚动；不截断待核对摘要。纯节点导航继续保留原路线，不触发输入变化。

## 5. 资产、回读与旧格式

`femto-surface-trajectory-v1` 及其播放器记录可带可选的 `planning_context`（`femto-planning-context-v1`），其中包含完整计算 `revision` 和目标 `target` 清单。路线算法版本仍为真实的 v3，不用一个新版本号暗示覆盖证书已经实现。

新增派生资产：

- `target_surface.json`：`femto-original-target-surface-v1`，保存坐标、输入/质量/有效域摘要、映射规则、状态、预算、统计和各数组摘要。
- `target_surface.npz`：完整规范源网格、区域面映射、深度/有效像素/原选区、质量证据、逐像素状态、叶单元和重复面映射。叶单元的重心数组形状为 `[N,3,3]`，其余叶字段为 `[N]`；数组不得为 object dtype。

两者写入规划输入快照、轨迹导出和带新路线的便携 `.region.zip`。大数组不嵌入 `project.json`。便携工程仍保存完整源网格和参考图，原规划目录不可用时可以从自带台账恢复并再次导出。

回读先检查条目白名单、重复文件名、尺寸/解压预算、NPY 头、shape/dtype、精确字节数与摘要，再核验计算修订、质量证据及有效域。正式读取/发布独立重建目标归属、面积和旧 v3 路线；篡改后仅重新计算外层 SHA 仍不能通过语义重现。算法、数值和质量策略未受支持时拒绝。

沿用 staging → 校验 → publish；成功前不更新当前保存引用。缺少新资产、混用不同修订或当前输入已变化时阻断。若路线文件夹已经成功发布、随后便携工程保存失败，界面明确报告已保存的路径和未完成的部分，不声称全部成功。

工程清单写入采用共享 `io_utils.write_json` 的可选分段模式。保存与回读 `project.json` 都在独立临时文件中编码，按原 UTF-8／平台换行字节累计，在下一批超出 100 MiB 前拒绝；保存拒绝非有限数，历史回读保留原解析语义，后续数值有效性仍完整核验。回读临时 `candidate_path.json` 同样分段写入并检查原任务回调，其读取限额保持原规则。缺省 JSON 写入调用仍用原实现。

每批写入小于 128 KiB，编码每 1,024 个片段及最终替换前检查取消／时间。写入失败清理本次临时文件，清理本身失败不能掩盖原异常；外层仍按原 staging 规则处理。分段模式避免分配整份 JSON 输出文本及编码字节，不改变已经加载的输入对象、单个字符串的编码需求或其他资产内存。原 120 秒预算是合作式检查，无法中断正在进行的系统调用。诊断阶段分别为 `portable.manifest`、`portable.validation_manifest` 和 `portable.archive`，不进入证明数据。

旧 v1/v2/v3 记录缺少新上下文时仍按原版本校验和回放，显示“原目标台账：旧记录未进行此项核验”。不补造旧记录的目标、修订或证书；需要时重新生成并保存新版本。未来 P2/P3 使用新的证据契约，不改变本版面积和未知范围的解释。
