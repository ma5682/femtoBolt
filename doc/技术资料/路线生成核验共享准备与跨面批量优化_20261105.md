# 路线生成核验：共享准备与跨面批量优化

日期：2026-11-05。目标是在保持原始测量、路线内容、几何判据、资源门禁及独立保存回读的前提下，缩短单帧与多帧路线生成和最终核验的总等待。

## 计时范围

此前 `9.984 / 9.781 秒` 仅计入 `surface_workspace.generate()`，包含其内部检查，未包含 Qt 随后调用的 `planning_state.validate()`。本轮基准比较旧 `generate + validate` 和新 `generate_checked` 的完整墙钟；不含 TSDF 表面准备、采集、重建、人工操作、保存或界面绘制。

冻结基线位于 `outputs/route_speed_implementation_20261105/baseline/`，以当前用户工作区为起点保留已有修改。每次复测使用独立进程、相同已采集输入和隔离的派生副本，单帧及三帧分别执行旧／新／新／旧顺序。新流程另在计时范围外执行公开独立核验，不能将这次额外验证当成界面必经耗时。

## 本次任务内的准备共享

`task_preparation.py` 复用参考图积分图、残差分块以及选区组件标签和三角面归属。每次命中核对完整内容指纹、形状、dtype、原规则及实际依赖函数；同一操作、同一线程内有效，退出、异常或取消后释放。完整有效域判断、宽度、边界、连接和最终几何核验仍执行，没有跨操作复用已接受路线。

原 RLE 快照上限仍为 16 MiB，新增准备数据合计独立限制为 64 MiB。积分图及残差快照以不可修改的 bytes 为底层，调用方不能重新打开写权限；选区结果提供独立副本。内存不足或输入不支持时走原路径。残差首次分块逻辑计费及每个消费者的采样预算不因共享而减少。

普通整数类型证明改为有界分块扫描，缓存命中仅在完整记录 SHA、精确类型及策略一致后省去已验证值的重复范围扫描。独立审查发现并修复自定义元类伪装普通整数的边界问题：类型比较使用身份，不能用元类重载的相等或哈希来证明类型。原缺失深度与几何质量规则保持。

## 跨三角面批量证书

`triangle_batch.py` 使用现有 `TriangleSolve` 的逆映射、条件数界及残差界，将不同面上的点或弦放入同一数值批次。新正例加入更保守的舍入余量；未确定的查询继续原逐面证书及原标量判据，不以近似结果替换临界判断。

少于 32 条、超过 262144 条、非 float64 或非默认浮点策略时保持旧路径。面表每块不超过 4096 个面，数值查询每块不超过 8192 条；准备及块之间响应取消。可选表和临时块分配失败时整块回退，不发布部分结果；原求解器和取消回调的异常继续传播。

冻结实现差分覆盖 288 个面、4320 条点／弦查询及三种输入顺序，包含六种尺度、三种平移、旋转、退化面、薄三角形条件门禁、法向 `1e-6` 和重心容差边界及非连续数组。判定差异为零，批量正例另由冻结的最终标量判据确认。证据见 `cross_face_differential.json`。

复测后进一步复用原始矩阵分解：在原 compact geometry row 中按需追加不可变逆映射及误差界，计入原共享池上限，不增加第二套缓存项，也不提前全量求解。输入几何摘要、矩阵身份、线程、活动作用域、求解方法及浮点策略均受绑定；独立 solver 仍逐查询计算，不能修改共享逆矩阵。144 面、288 个独立 solver 只产生 144 次真实分解，逆矩阵及误差界位级差异为零；该证据集占用 175807 字节，低于原 4194304 字节上限，见 `decomposition_differential.json`。

## 生成对象直接进入最终核验与显示

新增 `generate_checked()` 并接入 Qt。生成的轨迹对象完成原正式几何、布局、宽度、来源及规划上下文核验后，直接构造显示数据，再完成绑定和末尾内容/输入复核后返回，避免预览结构核验、字典转换、再次反序列化和正式核验之间的重复工作。

公开旧 `generate()` 和 `validate()` 契约保持。项级构造检查仍执行，固定文档头由原序列化函数产生；全内容指纹和末尾输入复核覆盖回调期间的嵌套修改。Qt 中生成及最终核验各自创建原预算。保存、便携读取及原生读取继续独立解析和完整核验，不沿用生成阶段的接受结论。

最终辅助流程复用第一次 `to_dict()` 的 payload 计算初始指纹，核验和显示构造期间不发布结果，仅在最后一次回调之后再核对完整内容及原输入。相较本轮初版辅助流程，该辅助流程自身的完整对象转换从 4 次减少到 2 次，全内容摘要从 3 次减少到 2 次；原 `validate_trajectory` 的结果摘要检查保留。末尾回调修改网格、选区、嵌套字段或替换整个点容器仍被拒绝。

## C/C++ 后续评估

第 4 项为条件性迁移评估。现有 native 接口服务于点云，没有路线三角面内核。连接阶段还含图搜索、节点与容器处理、分段和核验，不能把整个阶段耗时当作可移植数值计算；边检查计时嵌套其中，也不能重复相加。

前三项最终实采均值分别下降约 22%／18%，因此本轮交付已验证的共享、批量和流水线实现，完成 C/C++ 迁移的条件性评估，未新增路线原生内核。大批算术已由 NumPy 批量执行，QR 重复求解也已减少，直接迁移这些部分未证明额外端到端收益。若仍需进一步提速，应先确认剩余单边小批数值热点，再考虑只迁移正例证书或边界距离块，保留不确定回退、原预算、取消以及严格浮点设置。完整 A* 和核验器的原生重写涉及排序、浮点累加、失败顺序等更大契约，本轮未实施。

本轮不改变算法/方案格式版本、TSDF 参数、选区意图、原始测量或覆盖状态，不执行人工路线审核。源码工作台重启后启用新流程；未重启用户当前窗口、重打包 EXE、提交或推送。
