# 单帧复用局部 TSDF 的可行性（2026-11-04，隔离原型）

结论：现有多帧的局部 TSDF 分支可以接收一份真实单帧输入，并完成模型读取、规划、原生/便携保存和独立回读。本次桌面实采样本显示较大的速度潜力，**但它改变了几何表示和统计点集，不是像素网格实现的等价替换，尚未改为正式默认**。

用户要求从长时间全量回归转回算法提速后，停止了本聊天所属的全量测试，保留已落地的[四项等价优化](全流程响应与计算提速_20261104.md)。随后直接研究单帧与多帧的算法差异，没有重复扩大常规测试矩阵。

## 实验如何复用现有算法

当前生产分支在逐帧选区映射后，以实际贡献帧数决定是否走 `local_single` 像素建面。隔离原型只使这一份单帧输入进入既有局部 TSDF 分支，保留原实际帧数、内参、位姿、原始深度和选区过滤；没有复制第二帧、伪造位姿或重建整景再裁剪。

同一 1920×1080 输入、237306 个目标像素、40 mm 支持带，三个版本建模输入均为 546948 个局部有效深度像素；实际贡献帧均为 1。像素分支积分次数为 0，两个 TSDF 原型均只积分 1 次。原始 RGB-D、固定参考、原掩码和原完整像素网格仍保存在原目录，没有被覆盖。原型输出全部在独立研究目录，不作为已发布的新算法版本。

TSDF 截断距离保持 20 mm，对比体素边长 5 mm 和 3 mm；没有图像降采样、深度补洞或更改原观察支持门禁。使用工作台原有独立后台线程调度提示。局部范围和每帧实际输入数量记录于各重建报告的 `reconstruction_scope`。

嵌套统计不能再与重建相加。明显收益同时来自稀疏网格与点云统计对象减少；原 TSDF 分支在点云降采样/离群过滤后统计，而单帧像素分支统计完整点集。因此两侧的第二层比例和点面残差**不能直接当成同范围质量改善**。3 mm TSDF 的点云 P95 点面距离约 1.17 mm，也不能代替下述对完整原始表面的比较。

## 相对完整原表面的几何差异

对同一完整原像素网格建立一次独立参考。在全部目标像素上，以原始深度构造射线提示，原表面和候选表面的原生浮点射线漏判均使用各自原三角形重试；不使用候选深度改变原表面可用点集。最终各候选共享同一原表面基准：237306 个支持像素。

| 路径 | 候选支持像素 | 丢失原支持 | 原表面深度差 P50 / P95 / 最大 | 差值超过 2 mm 的像素 |
| --- | ---: | ---: | --- | ---: |
| 像素网格 | 237306 | 0 | 0 / 0 / 0 mm | 0 |
| TSDF 3 mm | 237306 | 0 | 0.264 / 1.004 / 5.962 mm | 983（约 0.41%） |
| TSDF 5 mm | 237283 | 23 | 0.372 / 1.356 / 7.312 mm | 3694（约 1.56%） |

这是选区像素位置的离散几何对照，不是连续面误差上界或真实相机精度。2 mm 是目前派生规划表面的工程检查尺度，用于本轮比较；体素 3 mm 也不意味着“精度 3 mm”。原型 TSDF 分支自身仍使用现有实测深度支持门禁，不能因此宣称所有目标满足相对像素网格的 2 mm 约束。

第一次快速统计仅为候选可用像素重试原表面射线，导致不同候选的原支持分母不同；该口径已由上述独立原表面审计取代。最初 `*_result.json` 中的 `quality` 保留为过程记录，最终质量表以 `independent_original_surface_audit.json` 为准。统一重试后，初始疑似新增支持的像素被证实为原生射线漏判，不再误报为新增表面。

| 阶段 | 当前保真优化版两次范围 | 3 mm TSDF 原型直接完整单次 |
| --- | ---: | ---: |
| 重建及报告 | 13.058–13.516 s | 1.206 s |
| 模型读取 | 0.922–1.043 s | 0.352 s |
| 规划表面准备 | 6.369–6.525 s | 0.574 s |
| 选区确认 | 0.426–0.479 s | 0.365 s |
| 目标与路线生成 | 20.497–21.051 s | 14.991 s |
| 原生保存 | 16.712–17.564 s | 14.066 s |
| 便携保存 | 4.875–5.105 s | 4.010 s |
| 独立便携回读 | 15.723–16.121 s | 11.700 s |
| 至双格式保存直接墙钟 | 63.940–64.921 s | 35.832 s |

对照版来自此前冻结候选的相同输入/后台线程运行；TSDF 是后续原型，不是交替随机对照，不能将上述差异视为稳定加速比例。另一次从已经生成的 3 mm TSDF 模型开始的流程也完成保存回读，生成 16.697 s、原生保存 14.967 s、便携保存 4.088 s、回读 12.368 s；它没有包含重建，不能冒充第二次完整重建墙钟。

墙钟不含现场采集、在线位姿、手工涂抹、人工检查及进程导入。正式接入时保留完整测量表面、增加所需版本绑定与偏差处理还会有成本，不能直接承诺上线后仍是 1.2 秒重建或 47.6 秒全链。

保存和回读成功只表示各自模型/路线按当前规则一致，并不表示新旧模型或路线相同。两条路径的目标像素均为 237306；TSDF 原型目标仍受 200000 单元预算约束，生成 199999 个叶单元、处理 70221 个像素组，167085 像素仍为预算未处理。路线和覆盖保持 `partial`，没有以删目标获得完成状态。当前像素网格对照为 199989 叶单元、62758 已处理组、174548 预算未处理像素。模型密度和预算处理前沿改变，因此不能按几何等价验收。

## 正式接入的边界

更值得推进的是“保留完整测量证据，使用受原表面约束的稀疏计算表面”，并把单帧的质量检查范围单独明确。不能把原型中的降采样统计直接覆盖为全量原始点检查结果，也不能直接把现有 `local_single` 判断改成 False 后发布。

若接入，应给单帧新表示明确版本，保留固定参考、原掩码、完整测量表面及其来源绑定；对超出原表面约束的位置采用局部细化、原表面回退或明确未确认状态，继续保留全部目标。内部留空、缺深度和遮挡边缘还需用对应案例检验。用户仍走同一流程，无须选择 ICP、TSDF 或体素参数。

本轮只对一份真实桌面单贡献帧做算法可行性验证，尚未验收真实人体、不同曲率/深度噪声、多帧真实场景或跨平台结果。因此保留正式默认，未增加界面试验选项或更新 EXE。

## 证据与并行修改

证据目录：`outputs/single_tsdf_speed_20261104/`。`scene_reconstruction_research.py` 是隔离分支；`compare_reconstruction.py` 记录实际执行源码摘要与三条重建路径，`audit_original_surface.py` 生成统一原表面对照；完整结果位于 `full_tsdf_3mm_combinedv2/result.json`，实际模块来源在其 `executed_imports.json`。

研究期间另一个开发进程修改了目标延后计算相关模块和基准工具。本聊天保留这些变化，不覆盖或回退；原型继续使用此前冻结的生产候选。第一次组合驱动混用了新基准参数 `defer_target` 和旧冻结函数，发生参数不匹配，失败目录及脚本保留；改用冻结基准驱动后完成。该失败不是 TSDF 几何失败，亦未通过修改生产签名掩盖。

`concurrent_changes_observed.json` 记录当时的并行变化范围。本报告及此前保真优化性能均不代表这些后续并行修改组合后的性能。
