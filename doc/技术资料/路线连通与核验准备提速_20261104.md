# 路线连通与核验准备提速

本轮只修改路线算法及其输入准备，不调整界面、重建路径、选区范围、网格密度、路线算法/文件版本或 EXE。保持上一轮零周边选区、完整测量表面与规划派生表面、最终整段核验及独立保存回读。修改已接入源码，其他未提交改动保留，无提交/推送。

## 算法修改

1. `surface_trajectory.face_components` 改用项目已有的整数边连通收缩算法：边键无碰撞编码、稳定归组、父节点收缩，输出仍按最小面编号标记连通分量。仅共享顶点不连接，重复/退化面和非流形共享边按原规则处理。超出整数范围、工作区或收缩轮数预算、可选分配失败，回原 Python 并查集。原始面数组不改写。
2. `continuous_quality.VerifiedSurfaceGraph` 对每一个保留扫描点，仅在邻接面首次出现时执行原点面判据。仍执行该面的第一次检查，包括失败和异常；没有直接假定所属面通过，也没有跨点保存接受结果。相邻关系、节点次序、候选对、A*、路径采样、整边检查及其预算不变。
3. `quality_constrained` 对不少于 64 条边的批次准备共同的中心投影。逐元素除/乘/加保持分开，**范数仍逐点调用原 `np.linalg.norm`**，避免轴向归约的 ULP 差异改变像素 floor/ceil。半径、残差、两个球的取整和每次 probe 的计费保持；只复用本批次的中心与范数，不缓存边的接受结论。非普通 float64、异常浮点策略、非有限/极端坐标/标定、接近零的深度、可选分配失败保留原路径；准备时每 1024 点检查取消。
4. 新增 `evidence_preparation`，只在 `surface_workspace.generate` 内启用：相同质量证据使用一次解码的不可变字节快照，最多保留一对数组、16 MiB。每次仍重新计算并比较完整记录 SHA，检查原始容器/整数类型、当前解码限制，返回独立可写数组；原参考标定、残差范围、未知像素不能有伪造残差、意图摘要及当前区域绑定继续检查。同 JSON 的 tuple/list 或整数子类不能借缓存绕过原解码规则。输入或预算改变失效，跨线程/失活上下文不复用，成功/取消/异常退出释放；可选分配失败回原解码。保存及独立回读不进入这个生成作用域，不复用生成时的接受结论。

本次没有把不确定面“判成支持”，没有关闭检查、放宽作用宽度/深度阈值或重排输出点。新准备数据不进入保存格式或计算修订。单帧及实际仅一帧贡献仍为选区像素邻接，多帧贡献仍为按实际位姿/深度映射的局部 TSDF，路线阶段共用这些改进。

## 定位与同输入对照
