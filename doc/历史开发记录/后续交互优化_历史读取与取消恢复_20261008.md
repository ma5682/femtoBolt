## 已实施行为

原历史弹窗在 `open_review()` 返回“任务已启动”时即关闭。现在任务启动后弹窗继续显示，只有所选来源的模型成功安装并发出 `loaded` 才关闭。

| 状态 | 用户可见行为 |
| --- | --- |
| 正在核验 | 显示实际读取进度，保留所选行；暂时禁用搜索、切换列表、刷新、移除和重复打开 |
| 核验成功 | 自动关闭弹窗，进入所选记录的只读回看 |
| 文件缺失或读取失败 | 保留弹窗、所选记录和原模型；显示原因，恢复可用操作，可重试或检查文件位置 |
| 点击取消读取 | 取消当前工作台读取，保留弹窗；取消后返回的迟到结果不能安装 |
| 读取中按关闭 / Esc | 请求取消并等待结束，再关闭弹窗；不强行结束后台线程 |
| 任务结束 | 断开本次进度、完成、成功及取消回调，后续记录不会继续更新旧弹窗 |

同时修复原 `HistoryDialog.reject()` 再次调用 `close()` 导致关闭流程未完成的问题。列表自身读取和工作台模型读取使用独立状态，避免把两类任务混为一个 runner。成功退出模态弹窗后由主窗口安排删除该弹窗。

修改仅涉及 `qt_history.py`、`qt_main.py` 及测试。原数据读取与来源校验、ReviewPage 的取消检查和模型安装规则继续复用；没有改动采集、几何、W0、单位、规划、数据格式或依赖。

## 操作示例

操作人员在历史记录中选择肩部采集甲并点击查看。核验期间继续看到所选行与进度，可取消。若参考深度缺失，弹窗显示原因，原模型仍保留；检查文件后可刷新重试或选择另一条记录。核验成功后弹窗才关闭，所选记录以只读方式回显。上述是研发软件交互，不代表患者身份或治疗几何已取得临床有效性。
