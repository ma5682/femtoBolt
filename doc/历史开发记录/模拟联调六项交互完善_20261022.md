面向当前工作台的使用者与维护者，记录六项交互修复、业务约束及本轮实际验收。工作区为 `E:\测试3D人体关节坐标-ui`，分支 `ui/workstation-redesign`；沿用当前 `.venv`、PySide6 和原模拟业务链。

本轮接续[五项交互修复](模拟联调五项交互修复_20261022.md)，对应[硬件预备提示词](../技术资料/单机上位机硬件预备开发提示词_20261021.md)的后续六项交互要求。启动与操作见[设备管理与模拟联调](../使用说明/设备管理与模拟联调.md)。当前仍是软件模拟，未接入真实运动、超声输出或实时患者测距，所有结果保持 `execution_ready=false`、`physical_accuracy_verified=false`。

## 六项问题与实现

| 问题 | 当前行为 | 验证方式 |
| --- | --- | --- |
| 切到历史或配置后看不到任务与停止按钮 | 当前任务、确认步骤进度、暂停/继续和请求停止位于标签页外；固定停止按钮独立着色 | 运行、暂停期间切换全部标签及滚动；1120×740、1600×940窗口检查 |
| 保存方案到模拟需重新找文件 | 回看页增加“用此方案模拟联调”，传入保存版本和路线摘要；后台完整核验后先显示任务、部位、患者左右、体位、正背面与版本，等待操作员冻结；同一路径重核验继续保留版本约束 | 真实加载右膝/仰卧合成保存包、实采保存方案传递；摘要或资产变化拒绝，无合成回退 |
| 冻结错方案后无法直接改选 | 可证明未下发请求时显示“撤销冻结”，追加“已放弃、未运行”记录后释放任务所有者与冻结数据，保留模拟设备实例 | 零请求、准备/在途拒绝、数据库证据变化、写锁/磁盘失败、重启回看及后续任务 |
| 下一步主操作不清楚 | “选择方案 → 冻结 → 连接 → 检查 → 运行”显示当前阶段；正常阶段突出一个下一步按钮，结束后突出“查看本次结果”，异常时不突出正常继续 | 核验、冻结、连接、检查、运行、暂停、结果和异常阶段检查 |
| 英文与 JSON 淹没主视图 | 中文设备、检查、事件与历史摘要；连接代次、原字段和完整计算信息进入“工程详情”；空历史和未导入安装记录有说明 | 真实来源与缺失字段、不适用机械/输出字段、固定底座、只读历史和工程详情 |
| 故障及恢复提示不醒目 | 标签页外异常区显示原因、影响与下一步，按状态提供方案核验重试、记录缺口恢复、旧模拟实例关闭与详情 | 停止未知的取消/确认、持久化失败与恢复、来源错误及配置/历史读取失败 |

“请求停止”继续由协调器等待参与设备分别确认机械静止和输出关闭。它不是硬件急停，也不能用请求已发送、取消或超时替代已停止证据。

## 关键业务边界

保存方案候选由非 daemon 后台所有者持有，UI 只接收摘要及候选标识。方案核验复用 `planning.saved_source` 的原来源、资产、目标和覆盖链；立即冻结时复核摘要并复用同次核验结果，不在心跳刷新时重算几何。更换来源、配置、关闭实例、取消或失败均使旧候选失效；迟到结果不能覆盖新选择。回看入口传递的修订或路线摘要不一致时拒绝冻结，不根据当前设备或名称补造旧任务字段。

接续核查发现同一路径再次点击摘要核验会丢失回看传入的版本约束；现保持该修订及路线摘要，重试同样保持，只有明确切换来源才清除。新增回归先复现替换后的版本被接纳，再验证拒绝与恢复。结束后的“查看本次结果”直接读取当前任务并同步历史选择，导出不会沿用先前选中的其他任务；结果入口不重建设备、不重发请求。

`abandoned_unrun` 只能从未准备状态进入。协调器要求零请求尝试、零完成步骤、无在途请求/请求组、无持久化缺口、无恢复待核对状态且没有运行资源占用；事件仓储在同一短事务核对原未准备状态、冻结事件、预期事件序号和不存在请求意图/准备/开始事件。成功追加事件后才释放任务所有者；事务失败保留原任务和所有者。正常关闭与退出对可证明的未运行任务沿用该状态。已经准备、运行或可能发送请求的任务继续走停止/未知流程。

关闭实例后保留历史记录，并显示如何刷新回看；方案区重置为尚未核验，旧候选参数清除。恢复按钮依据实际失败动作显示，配置、回看或导出错误不会触发方案核验并意外冻结合成任务。发生操作异常时取消正常主操作的突出状态。

显示语义与完整证据分开：设备无关字段显示“不适用”，相关字段缺证据显示“未知”。主界面显示中文安装来源与实测资格未验证，独立合成间隙显示 `0.200 m`、参考坐标 C 及合成平面来源。工程详情保留原字段，历史显示最近 400 条事件；完整冻结快照、路线和全部事件仍通过独立导出保存。

## 数据库兼容

独立 `execution.sqlite3` 当前写 schema v2，可只读 v1/v2。v1 首次写入在事务中追加迁移记录并升为 v2，原任务 JSON、原事件和序号不改写；失败回滚。原 `history.sqlite3` 继续为 v1，事件库升级不修改它。

新状态不能让旧软件静默误读，因此 v1 版本门禁拒绝 v2。测试通过隔离旧版门禁模拟检查读取/写入拒绝，另验证 v2 SQLite 备份副本可完整恢复“已放弃、未运行”，v1 事务迁移中断后原记录保持。需要降级时保留升级前备份，不手改 `user_version`。双库备份仍由 SQLite 备份 API 分别生成一致快照，不承诺跨库原子时刻，见[SQLite 历史记录与备份](../使用说明/SQLite历史记录与备份.md)。

## 完整操作示例与剩余范围

打开右膝 / 仰卧的已保存方案 → 用此方案模拟联调 → 核对任务、部位、患者右侧、仰卧、正背面和保存版本 → 冻结 → 连接 → 检查 → 开始 → 暂停 / 继续 / 请求停止 → 查看本次结果 → 导出所选记录。切换模拟页内部标签与滚动时，当前任务和停止入口保持可见。选错方案且未准备时可撤销冻结后改选；在途任务先停止并等待结果。

这条操作链证明软件交互、状态机、事件与原方案引用一致。厂家协议、实测手眼/工具标定、同步位姿、真实反馈/联锁与急停、机械可达性、实际运动和超声输出仍待接入并独立验收。依赖与验收对照见[厂家资料交接清单](../技术资料/厂家资料交接清单_20261021.md)及[模拟联调与坐标准备契约](../技术资料/模拟联调与坐标准备契约_20261021.md)。本轮未提交或推送，不改写原始 RGB-D、模型、保存方案或既有证明资产。
