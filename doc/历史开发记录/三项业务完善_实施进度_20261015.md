# 三项业务完善实施进度

日期：2026-10-15。目标：原目标建账分块续算、缺口处理闭环、实采缺面原因排查。

## 当前实现

1. `target_surface._construct` 支持明确的候选像素组起点；历史无起点路径与停止前沿继续按原格式复算。
2. 新增 `target_paging`：多个不可变分块绑定同一个原目标和计算修订；每块保持原 `TargetBudget`，按连续前沿推进，不删除旧单元。清单记录各块摘要、起止组、累计候选/邻接检查和单元统计；分块数组累计不超过512 MiB，最多128块。各块保存与独立重建校验，拒绝跳前沿、混来源和零进展。当前候选索引仍需在单块原限制内完成，候选索引预算退出不冒充可续算。
3. 重建增加可选 `geometry_observer`，默认关闭；五个阶段仅进行观测。`GapProbe` 对同一缺面像素集合记录逐阶段首交点，不改重建、实测支持或过滤判据。
4. 新增独立重建排查后端与CLI，读取原参数、新建派生输出、核对输入文件摘要，只有最终缺面射线重现原结果时才允许解释阶段归因。
5. 规划页检查类覆盖任务从仅定位和提示改为缺口检查对话框：显示当前定位范围的参考深度、有效数量，提供同参数重建排查和已有同任务/部位新采集入口。数值或预算单独筛选不启用补采。后台排查不安装新模型或改当前路线，沿用请求代次与输入失效保护。
