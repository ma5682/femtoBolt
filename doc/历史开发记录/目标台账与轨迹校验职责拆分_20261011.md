## 改动与约束

目标构建提取像素多边形裁剪、遮挡处理、深度分类与子三角形生成三个辅助函数。主函数保留原候选索引、像素遍历、预算停止、行记录写入与质量标记顺序。候选、单元、配对和时间预算、回放 frontier、取消检查位置、去重、浮点面积计算与质量资格保持原实现。

旧版本轨迹校验提取扫描点检查和断点记录检查；入口继续负责版本分派、来源绑定、段顺序、块一致性、端点对应与结果摘要。辅助函数使用原局部变量名称和显式输入/返回值，不新增持久状态或运行时类型检查。所有新函数位于原模块，既有调用和 patch 路径保持。

| 入口 | 拆分前 | 拆分后 |
| --- | ---: | ---: |
| `target_surface._construct` | 198 行 | 119 行 |
| `surface_trajectory.validate_trajectory` | 174 行 | 118 行 |

五个辅助函数为 25～40 行。代码总量没有因此减少，目的在于使每段职责能独立阅读；本轮没有提速或覆盖增益结论，也没有修改数据格式、算法版本、数值策略、设备行为或已有证明。

## 对照

保存开工时 403 个生产、测试和工具 Python 文件摘要；本轮源码变化核对为上述两个模块。将新辅助函数在调用位置展开，参数逐一与原变量对应，返回目标与接收变量逐一对应，再与原入口完整 AST 比较：语句、表达式、分支与计算顺序一致。该检查不能代替运行时验证。

同进程加载原函数快照，在固定 monotonic 时钟下直接对照 **280 组目标构建**：普通平面、重复面、遮挡、部分像素、空选区内核输入、缺深度、深度冲突、无源像素、穿越相机平面和非有限坐标；组合候选、单元、配对、时间预算、索引/像素回放停止点及不同取消位置。全部数组的 dtype、shape 和原始字节摘要，全部 metrics、取消检查次数和异常类型/信息一致。空选区仅作为内核探针，产品入口仍拒绝空选择。

对照 **15 组旧轨迹**：正常结果及路线索引、行、三角形、显示像素、角色、重访、间距、几何支持、断点索引/原因/详情/长度/端点和方向字段错误。通过结果、拒绝异常与消息一致。固定时钟用于数值与工作预算对照，不能证明真实墙钟时间预算在不同调度下必定停在同一像素。

分层检查 `upward edges: 0`；217 个生产模块导入通过。

定向回归覆盖 17 个测试文件、172 项：初次 171 项通过，0 失败、1 错误、0 跳过，约 490.3 秒，运行期间源码摘要稳定。唯一错误在旧版本回放测试用默认 GBK 读取含中文的 UTF-8 JSON，报 `UnicodeDecodeError`。修复 `tests/test_optimized_selection_routes.py` 中四处默认读取（两个 JSON、两个 CSV），显式指定 UTF-8；在原 Windows 默认编码下重跑该模块 8 项全部通过，约 3.6 秒。其他 164 项及两个生产模块均未再改动；最终 172 项测试均有成功验证结果，保留初次错误与修复回归日志，没有将其改写成一次完整全绿运行。
