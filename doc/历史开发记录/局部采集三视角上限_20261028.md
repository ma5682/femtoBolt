# 局部采集三视角上限（2026-10-28）

用户要求将最高采集限制调整为3帧。按前一轮确认的有效融合视角口径实现：初始参考帧占1个名额，再接纳2个合格不同视角，达到3个后自动结束并重建。原始连续跟踪帧可能多于3帧。

## 实现

`femto/capture/local_capture_policy.py`定义新建局部采集的`MAX_ACCEPTED_VIEWS=3`，单独记录`capture_limit`，不将历史选择器的128个视角证据资源预算改为3。`LocalCapture.request`及`_select`阻止第4个视角；在第3个视角匹配原始写入回执、提交跟踪日志后调用原`finish`，不消费下一个排队帧。新`local_finishing`事件通知Qt开始收尾，保留后台取消和失败处理。

`finish_reason=accepted_view_limit`写入跟踪报告与派生manifest，最终采集评估另存`capture_end_reason`。原`assessment_status`、`end_status`及`confirmed_for_planning`校验契约不变，`manual_end_pending/unknown`保留为旧格式的待人工核对状态，实际自动结束原因由新增字段表达。上限不把缺失区域视为覆盖完成，执行与实物精度标记仍为false。

界面显示活动采集的1/3、2/3、3/3计数和自动结束说明；达到上限后补采按钮不可用，收尾与重建期间仍可取消。历史记录按原数量显示，例如原6视角记录仍显示6帧。达到上限即结束同一会话，因此原来至少3帧才能发起的阶段检查在新的3视角流程中不会成为继续补采入口；若模型有缺口，需用“重新采集该部位”重新取景。

原始RGB-D、标定、W0参考、逐帧位姿血缘、五帧支持规则及所有质量门槛保持；本轮不修改TSDF参数、路线采样或历史重建输入。通用多视角CLI和固定机位后端不受这个局部采集上限影响。
