## 正式接入

`checksum_resources` 使用当前可用内存、文件数/字节数和进程 CPU affinity 选择工作数量。至少 4 个文件、合计 16 MiB、至少 4 个可用逻辑 CPU，且可用内存扣除系统/界面预留后至少 512 MiB 时最多使用两个摘要工作线程；其余与未知条件保守单线程。预留取至少 2 GiB 或物理总量的 1/8，两者较大；该策略不强制操作系统保留内存。

`checksum_batch` 已接入原生文件清单和便携工程资产清单。输入顺序、全部文件字节与原 SHA-256 保持，只有完整有序结果才交付；采用只读结果映射和最多两个在途任务。预算/取消回调只在调用线程运行，工作线程使用私有停止事件，异常/取消等待工作线程退出后保持原异常传播。几何、连接、覆盖遍历及证明预算不并行、不扩大；单文件缓冲仍按实际内存取最多 64 KiB 或 1 MiB，不依赖模拟内存扩大缓冲。

Windows 内存查询改为单个静态 ctypes 类型与一项惰性 API 绑定缓存，每次读取当前状态。此前 20 次查询新增并保留 20 个 ctypes 类型，现正式用例连续 40 次查询不再增长；接口拆分为 Windows/Proc 读取和统一保守回退。类型项数不是进程内存节省量。

成功父阶段释放其已处理预算中断的异常引用，避免 traceback 暂时留住旧计算对象；真正传播的错误继续保留最内层阶段及原异常身份。弱引用用例验证 1 MiB 测试对象在下一计算前可回收，不把该构造用例换算为实际应用内存降幅。

新增公开资源/摘要接口、只读结果和回调均有类型标注，保存适配器的摘要和清单接口也补齐。原生清单准备与便携资产摘要从长保存流程中抽成独立职责；Windows 资源查询拆分，并将失败阶段/引用释放放在后台诊断层，Qt 继续只呈现当前任务结果。未新增第三方依赖和提前加载 Torch/OpenCV。
