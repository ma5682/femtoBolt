## 接入前需要解决的问题

1. **数据接口不同。** 现有 VTK 接口接收包含 `model.mesh` 的规划模型；采集页返回 `clouds` 和 `surface`。不能直接把采集字典传入现有 `set_scene`，也不应为查看点云强行加载完整的固定 RGB 标注模型。
2. **旧显示数据不适合作为完整网格。** `read_review` 将点云降到最多 35,000 点；`read_review_surface` 对较大网格返回抽样三角形坐标。新适配应保留顶点、拓扑索引、颜色和原始面 ID，不把旧边线抽样解释成完整表面。原始 PLY/网格继续只读。
3. **渲染构建仍可能阻塞界面。** 当前 `set_scene` 在 GUI 线程复制数据并重建所有 actor。大模型需要后台读文件/准备 NumPy 数据，GUI 线程只提交 VTK 对象与渲染；设置明确资源预算，超限时提示并采用标注清楚的显示采样。预算应先基于本机实测确定。
4. **刷新标识偏弱。** ScenePanel 用 Python 对象身份判断变化；同一对象原地更新时可能不刷新。采集预览会频繁变化，应增加显式场景版本或数据版本，避免只比较对象地址。
5. **坐标语义需显式携带。** 当前适配层约定 world RDF metres，但快照没有 frame/source 字段。历史 W0 模型与实时相机 C 点云应带各自来源、单位、坐标系及会话标识，不在同一空间直接叠加。更改观察相机不改变数据坐标。
6. **生命周期与错误回退。** 采集页目前只关闭后台任务和相机；接入后还须释放 VTK 资源，防止切历史、切项目或关窗后出现旧模型回填。VTK 不可用时给出明确提示并保留旧预览入口，不阻断采集数据保存。

## 实施顺序

### 阶段一：步骤 03 的静态模型检查（优先）

复用现有 VTKViewport，新增通用数值场景入口，原规划模型入口保留并委托给通用入口。扩展现有 `vtk_scene.py` 数据结构，避免复制第二套渲染器。

采集页在已有三维视图位置嵌入可延迟创建的 VTK 视口：

- 保留“初始点云 / 累计点云 / 最终模型”选择；历史累计继续读取已保存融合点云，不能指向实时缓存。
- 最终模型优先显示已有实测网格；缺网格时显示融合点云并明确说明。没有初始点云时显示缺失状态，不借用其他图层冒充。
- 增加“参考正视 / 自由检查”与“复位视角”；默认恢复参考方向，允许自由检查时旋转、平移、缩放。
- 同一数据来源切换图层保留观察位置；切换采集记录后重新适应模型。
- 显示记录名称、坐标系、单位、点/面数量及是否显示采样；读取、失败、空数据均有可见状态。
- 后台读取采用请求编号/来源校验，晚到结果不得覆盖新记录；退出时释放视口资源。

第一阶段继续沿用当前 RGB、深度及实时单帧预览，只完成已结束采集和历史模型的检查。这使静态模型接入能够独立验收。

涉及文件：`qt_capture.py`、`capture_viewport.py` 的模型读取边界、`qt_vtk_viewport.py`、`viewer/vtk_scene.py`；按需扩展组件，不复制整个 ScenePanel（其依赖二维画布、finish_stroke 和播放 timer，不能直接放进采集页）。

### 阶段二：实时点云与累计点云统一显示

- 将实时相机 C 点云和当前会话 W0 累计点云接入通用数值入口；显示明确的来源和坐标标记。
- 更新 vtkPoints/颜色数组，避免每帧重建整个场景；显示队列只保留最新帧，渲染负载不影响采集接纳。
- 相机停止、帧过期或会话切换时清空相应实时视图，不能保持旧画面而继续标成实时。
- 默认保留用户视角；仅首次显示、来源改变或用户复位时自动适应。
- 测量实际更新频率、交互延迟、CPU/内存/显存，与当前预览对照后确定显示预算。

### 阶段三：规划页与检查页的一致性

- 统一颜色、图层开关、坐标提示和相机操作。
- 当前 VTK 只显示已确认工作区及统一黄色路线；再补禁区、扫描段与连接段的区分、断点/未规划跨区移动提示。
- 路线播放和拾取仅关联核对，不改变路线坐标或补连断点。
- 三维直接画区域、测距与工具姿态预览另列任务：需要原始面 ID、选择意图与撤销/重做一致性设计，不能将视觉拾取直接当成已确认规划输入。

## 验收条件

| 验证对象 | 必须确认 |
|---|---|
| 数据准确性 | 显示前后源文件哈希及几何数组不变；颜色、米单位、W0/C 来源一致；网格编号映射正确 |
| 回放 | 打开历史 → 返回采集 → 检查初始/累计/最终 → 再进入规划，始终为同一记录 |
| 大模型 | 实际小、中、大记录的读取、旋转、图层切换耗时与内存记录；采样有标识，超限可恢复 |
| 失败路径 | 无网格、缺文件、读取异常、VTK 创建失败、快速切项目和关闭中断均不会展示错误来源 |
| 交互 | 单击拾取与拖动旋转不混淆；高 DPI、窗口缩放、重复进入/退出无黑屏或资源持续增长 |
| 原生渲染 | 在本工作区环境和真实 Windows 图形窗口上完成 OpenGL 渲染与交互验收 |
| 回归 | 原有历史、质量检查、进入规划门控、区域/路线保存行为保持；运行相关回归及项目要求检查 |

阶段一通过后再做阶段二；阶段三只扩展明确的核对需求。无需新项目目录，也无需引入 gsplat 或 PyVista。

当前分支有较多未提交改动。实施前以当前工作树为基线确认在途修改；若另建分支，应包含当前已实现 VTK 的状态，不能从旧提交创建空基线后重复开发。
