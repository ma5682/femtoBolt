1产品定位与交付物

用一台 Femto Bolt RGB-D 相机，把相机实际拍到的完整场景重建为可交付的三维资产。人体 Pose / Mask / 物体语义只是可删除重算的派生标注层，永远不裁剪或覆盖原始画面。

RGB-D 原始数据 已实现

  • 完整 RGB、uint16 毫米深度、内参、双时间戳、逐帧位姿
  • 不可变证据层，任何派生结果不得回写

点云 / TSDF Mesh 已实现

  • 固定机位与多视角融合点云 PLY
  • TSDF 网格，导出 GLB / OBJ / PLY，米制单位

3D Gaussian Splatting 合成 GPU 链路已验收

  • 直接调用 Apache-2.0 gsplat 的自研训练器
  • 训练后 SH3 PLY，可选 Niantic SPZ；真实 Femto 多视角仍待人工采集

质量报告 已实现

  • 数据集门禁、位姿质量、3DGS 验收 JSON + HTML
  • 每一步失败都阻断并写报告，不输出伪结果

人体语义层 可选原型

  • MediaPipe 33 点 Pose、人体 Mask、区域标注
  • 仅研发可视化，不声称临床靶点

桌面 / Web 查看器 桌面已实现，Web 未做

  • Open3D 中英双语专业查看器：Mesh / 点云 / Gaussian / 相机轨迹叠加
  • React + Three.js Web 端待建

三种采集模式决定整条链

模式适用场景处理方式位姿与下游
关键帧快照（默认）人物可动，相机固定对深度覆盖率、RGB 清晰度、RGB/Depth 同步差和深度稳定性评分，自动选一张 RGB 与 Depth 同源的最佳帧T_WC = I；单视角几何；不进 3DGS
固定机位融合相机与场景都静止逐像素深度时间中值 + 最小支持帧数，抑制深度噪声T_WC = I，写 derived/fixed_median_*；不进 3DGS
完整背景多视角场景静止，相机缓慢移动，相邻约 70% 重叠约每秒异步抽样低分辨率 RGB 提示是否移动；结束后再以多帧对光流 + RANSAC 单应性门禁并跑顺序 RGB-D 里程计提示不是 Pose；原始 pose_valid=false；估计位姿写 derived/posed_rgbd_odometry_*；唯一可进 3DGS 的模式
产品原则：相机移动时禁止写单位外参。位姿不合格时阻断并写质量报告，不得输出伪 Pose，否则会同时破坏 TSDF 与 3DGS。

3总体数据流与系统架构

所有重建输出必须从同一个不可变原始数据集派生。几何管线、写实管线、语义管线三条并行，共同前提是每帧有可信的 T_WC。

坐标与单位约定：磁盘一律 Orbbec/OpenCV RDF（+X 右、+Y 下、+Z 前）；深度 PNG 为 uint16 毫米，0 表示未知；3D 关节、点云、Mesh、Gaussian 一律米。T_AB 把 B 系坐标变到 A 系。只有导出 Nerfstudio/OpenGL 时右乘 diag(1,-1,-1,1) 做 RDF→RUB，训练前再转回 RDF，所以训练后的 Gaussian 与 Seed PLY 同处 RDF 世界系。

5各技术环节实现与考量

每个环节按"做了什么 / 为什么这样做 / 必须考虑的事"整理，便于汇报时回答追问。

5.1 RGB-D 同步采集与对齐

实现：Orbbec AlignFilter 做 Depth→Color 对齐，输出 1920×1080 对齐 RGB-D；保存彩色/深度内参、K6 畸变、双时间戳；固件可提供时保存曝光、增益、白平衡、激光状态、传感器时间戳。

  • 三档量程各有适用距离，页面实时显示"有效/过近/过远/无返回"比例，低于 35% 提醒调整
  • 预览不落盘，点击才采集，避免无意义大文件
  • SDK 缺失字段保持缺失，不伪造元数据
  • RGB 像素没有有效深度就没有真实几何；大块黑区多为过近/无返回/遮挡，单视角不能补全

5.2 三种采集模式与位姿策略

实现：模式选择一路传播到 manifest、位姿、重建参数与报告口径。

  • 关键帧：RGB 与 Depth 必须同源，避免时间中值把移动人物删掉或把不同时刻纹理贴到同一几何
  • 固定融合：只适合完全静止场景，写 temporal_support.png 供审计
  • 移动：先用 RGB 特征光流 + RANSAC 单应性判断"相机其实没动"，是则阻断并建议改固定模式
  • eye-in-hand 正式方案优先机器人位姿 + 手眼标定 T_BC = T_BF · T_FC；手持需回环/全局优化

5.3 顺序 RGB-D 里程计与位姿门禁

实现：Open3D Hybrid RGB-D Odometry 估算相邻帧 source→target，按 T_WC(i)=T_WC(i-1)·inv(T) 累积。

  • 单帧门禁：位移 ≤0.25 m、旋转 ≤25°、fitness ≥0.15、inlier RMSE ≤60 mm
  • 整条轨迹：≥3 帧通过且跨度 ≥20 mm 或 ≥2°，否则阻断
  • 异常帧只进报告，不进派生 Pose；原始 pose/ 永不改写
  • 没有回环与重定位，会累积漂移，定位为静态场景研发 Demo

5.4 数据集门禁

实现：检查帧文件完整、格式、RGB/Depth 同步差、标定合法、位姿刚体性、深度覆盖与模糊分数，写 quality/validation_report.json。

  • Pose 不完整允许归档通过，但输出 ready_for_multiview_reconstruction=false
  • 有效深度 <35% 标 warning_low_depth_coverage，不能标 PASS
  • 后续增加曝光跳变、相邻 Pose 速度/加速度门禁

5.5 去畸变、世界变换与 TSDF

实现：RGB 与 uint16 深度执行同一套 Brown-Conrady K6 去畸变；按彩色内参反投影，p_W = T_WC·p_C；Open3D TSDF 积分用 inv(T_WC)。

  • 补孔只补内部小孔，保留外轮廓，避免把未观测区域"编造"成表面
  • 合成真值场景自动算融合点到真值表面的中位数 / P95 / 最大距离
  • 输出目录已存在直接报错，从不覆盖
  • Gaussian 不是可用于碰撞或尺寸测量的工程表面，尺寸以 Mesh/点云为准

5.6 Nerfstudio 格式转换与 Seed PLY

实现：femto-to-nerfstudio-v2：去畸变 RGB、无损毫米 Depth、transforms.json、按真实内参反投影并用 T_WC 变到世界坐标的 XYZRGB rgbd_init_points.ply（10 mm 体素，≤100 万点）。

  • 相机矩阵仅在写 transforms 时右乘 RDF→RUB，世界点不重复翻轴
  • 训练从相机实测的尺度与表面起步，而非随机初始化
  • 3dgs_input_report.json 汇总深度覆盖、同步差、亮度与曝光稳定性；变化过大标 photometric_unstable
  • 无 Pose 或所有机位相同直接阻断；不做人体 Mask

5.7 直接 gsplat 产品训练器

实现：只调用 gsplat.rasterization 与 DefaultStrategy 公共 API；损失 = 0.8·L1 + 0.2·(1−SSIM) + 0.1·米制 Depth Smooth-L1(β=0.02) + 尺度/透明度轻量正则；RGB+ED 渲染模式同时得到期望深度。

  • 三档：low_vram 15k 步/降采样 2/10 万初值；balanced 30k/1/25 万；quality 45k/1/50 万
  • 致密化：复制、分裂、低透明度裁剪、周期透明度重置，由 gsplat 策略执行，本项目只管调用顺序与参数
  • 原子检查点：Gaussian、Adam、策略状态、Python/NumPy/Torch/CUDA 随机状态、输入 SHA-256 指纹；跨数据集 --resume 会被拒绝
  • 不依赖 Nerfstudio / PyMeshLab / Graphdeco；patch_gsplat_windows.py 仅替换 MSVC 编译标志，不改内核

5.8 验收指标与 Depth 口径

实现：留出视角（eval_stride=8）计算 PSNR、SSIM、LPIPS、Depth RMSE/MAE/AbsRel，保存 RGB 与毫米 Depth 渲染证据。

  • Depth 口径收紧：模型没渲染出几何的"黑洞"像素按预测 0 m 计入误差，不排除；另设覆盖率 ≥0.90 门槛，漏渲染不能把误差做好看
  • 门槛：PSNR ≥20、SSIM ≥0.65、LPIPS ≤0.40、Depth RMSE ≤0.12 m、覆盖率 ≥0.90，五项同时满足才 accepted=true
  • LPIPS 主干 AlexNet 权重按官方 SHA-256 离线装载（install_lpips_weights.cmd），训练器不隐式联网下载；缺失即拒绝构造并写入报告
  • --skip-lpips 只用于冒烟，验收必然不通过

5.9 导出格式与模型血缘

实现：训练后 PLY 含 f_dc_0..2、f_rest_0..44、opacity logits、log scales、scalar-first 四元数（62 属性，二进制小端）；SPZ 仅经 Niantic 官方 MIT binding 做 RDF→RUB 转换。当前官方 tag v3.0.0 已构建为 spz==1.1.0。

  • SPZ 构建固定 zlib 1.3.1、zstd 1.5.6、nanobind 3.0.1 及其 robin-map 1.4.0；运行 DLL、静态组件版本、commit、SHA-256，以及 Adobe、zstd 旧解码器和 libdivsufsort-lite notice 均已登记
  • 缺少 SPZ binding 时只保留有效 PLY，报告明确记录转换失败，不伪造 .spz；已安装时官方回读核对 Gaussian 数量
  • model_manifest.json 记录输入指纹、轴转换、检查点、指标与输出
  • 未训练初值 gaussian_init_untrained.ply 状态固定 initialization_only_untrained，在 manifest / 报告 / UI 中与训练后 3DGS 严格区分

5.10 桌面查看器与报告

实现：自定义 Open3D Window + SceneWidget，中英即时切换；Mesh、点云、Gaussian 初值、相机轨迹、视锥为独立对象可任意叠加；着色/线框/法线/顶点色、点大小实时改材质、八种视角。

  • 轨迹与视锥只读源数据集中通过刚体校验的真实 T_WC，单帧不生成虚假轨迹
  • Y 翻转只作用于显示副本，不改磁盘坐标
  • 直接 gsplat 查看器对大模型按显存/像素预算运行；超时或明确 OOM 时仅临时降分辨率或采样，其他 CUDA 错误原样记录并失败；报告保留原始/实际 Gaussian 数、每帧耗时和峰值显存
  • Web 端（React + Three.js + 专用 splat renderer）尚未实现

5.11 人体语义分支（可选）

实现：MediaPipe Pose Landmarker Full（模型 SHA-256 钉死）33 点 + 人体 Mask；关节反投影与表面共用内参；短时 TSDF 原型。

  • 尺度只能来自 Femto 深度与验证位姿，不能来自模型 world_landmarks
  • 输出仅供研发可视化，不得声称临床靶点或驱动机械臂
  • 真人数据需隐私影响评估与单独同意

5.12 Windows / 中文路径工程问题

实现：仓库路径含中文，多处原生库需要兜底。

  • OpenCV 读写走 np.fromfile + imdecode / imencode + tofile
  • Open3D 原生 IO 与 Filament 资源先落到 %LOCALAPPDATA% ASCII 路径
  • CUDA JIT 走 C:\FemtoGsplatRuntime 目录联接
  • GUI 无控制台，stdout/stderr 重定向到 Log/；JSON ensure_ascii=False 写、utf-8-sig 读

9风险、边界与下一步

技术边界（必须如实告知）

  • 顺序里程计无回环/重定位，长轨迹会漂移；生产级位姿应来自机器人正运动学 + 手眼，或验证过的 SLAM/COLMAP
  • 单视角无法补全遮挡与无返回区域；深度黑区不是算法能"猜"出来的
  • 3DGS 验收目前只在合成数据完成，真实 Femto 场景的噪声、标定误差与位姿误差尚未验收
  • Gaussian 不是工程表面，不能用于碰撞或尺寸测量
  • 人体关键点未经临床验证，只做研发可视化

下一步实施顺序

  1. 用真实静态多视角 Femto 数据跑完整 low_vram / balanced 档，验收指标与显存
  2. 真实移动采集后验收真实 3DGS 指标与尺度；SPZ PLY→SPZ 转换已完成，继续保持 PLY 为训练主格式
  3. 接入机器人位姿 + 手眼；补回环 / Pose Graph 与全局优化
  4. 数据集门禁增加曝光跳变、相邻 Pose 速度/加速度
  5. React + Three.js Web 查看器：GLB / PLY / 视锥 / 标注先上线，再接专用 3DGS renderer
  6. 建立静态几何靶、室内场景、动态人体三套验收集
