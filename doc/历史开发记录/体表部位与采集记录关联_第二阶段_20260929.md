# 体表部位与采集记录关联：第二阶段

目标工作区：`E:\测试3D人体关节坐标-ui`；分支：`ui/workstation-redesign`。使用本工作区独立 `.venv`（Python 3.12.10、PySide6 6.11.2），按 `body-surface-planning` Skill 在第一阶段上增量实现。

开始时已有 227 条 Git 工作区变更，保留原有修改与未跟踪文件，没有切换分支、提交或修改其他工作区环境。本轮范围为部位与真实采集、保存方案的关联闭环。

## 检查与实现

已有 `femto-ui-task-v1` 任务标签、结构化 `body_selection`、采集历史扫描、便携方案目录及独立只读回看页可复用。原始任务 ID 不是病例身份；原先每次“新建采集”均创建新任务，不能仅凭同名任务或相同部位认定记录归属。

1. 新增只读计算索引 `femto/app/body_records.py`，从现有采集历史和已登记便携方案目录汇总。匹配键为任务 ID、部位、患者侧别、正背面、体位和覆盖范围；无新持久化格式，不按名称、路径相邻关系或影像猜测归属。
2. 新增 `BodyRecordsDialog`。顶部“部位记录”、采集页“查看部位记录 / 同任务采集”均可进入；新建采集确认人体部位后自动查找该任务下的记录。任务下拉显示名称与短 ID，详情展示完整 ID 和来源；未知当前任务时要求显式选择，列表不自动选中记录。
3. 记录状态区分“已采集 · 待检查”“已保存 · 待复核”及文件/来源待检查；无匹配时提供“在此任务下采集该部位”。扫描失败不能被解释为未采集；缺少可核验归属的旧记录计数提示，并保留原历史入口。
4. 选定记录后复用真实加载器和 `ReviewPage`，在后台复核实际任务/部位/体位、来源可用性、保存版本和索引后文件变化。通过后才安装数据并关闭弹窗；失败保留原模型与可重试入口。读取期间禁止重复打开和切换筛选；关闭取消后忽略迟到结果，临时信号连接在完成后解除。
5. “在此任务下采集该部位”保留已有任务 ID、名称和创建时间，创建全新 `CaptureState`，清理旧来源与预览缓存，应用新确认部位。原“新建采集”继续创建新任务 ID。两者均不自动开始硬件采集；后续沿用真实 RGB-D 与部位准入。
6. 保存方案继续只读回看，修改通过既有“基于此版本修改”流程产生新结果。切换记录仍遵守草稿保存与任务忙碌检查，不把当前编辑区域或路线合入另一条记录。

主要改动为 `body_records.py`、`qt_body_records.py`、`qt_main.py`、`qt_capture.py`、`qt_review.py` 和 `tests/test_body_records.py`。

## 数据与产品边界

- 第一阶段部位白名单、手部仅腕部/手背/手掌、头足暂不支持新建、患者左右及正背面映射保持原规则。
- 人体示意图仅用于导航。真实影像、模型与区域仍绑定各自采集；同任务标签不意味着不同采集共享 W0，也不建立跨会话几何变换。
- 新建区域仍为工作区域涂抹与擦除，可分离、可留空；历史 forbidden region 保留、显示并继续扣除。
- 任务 ID 不代表患者身份。新索引涵盖现有采集历史与已登记便携工程，不扫描任意外部路径；未产生关联结果的原始会话及缺少标签的旧记录需从历史核对，不静默补标签。
- “待检查”表示需要人工核对，不保证深度、位姿、配准或几何质量。逐像素质量覆盖反馈属于后续阶段，本轮未实现。
- 无新增依赖或历史 schema；未修改原始 RGB-D、W0/RDF、几何映射、配准、重建、路径算法及不可执行标志。未新增自动人体识别、跨体位配准、VTK 迁移、机械臂或治疗执行功能；Skill 文件保持不变。

## 操作示例

任务 A → 确认“患者左侧 / 大腿 / 背面 / 俯卧” → 查看匹配采集或已保存方案 → 只读核对真实数据。若需另一体位，回到“部位记录”选择新的正背面和体位 → “在此任务下采集该部位” → 重新建立参考位置、采集、检查模型并规划保存。原记录保留，另一体位的记录独立匹配。
