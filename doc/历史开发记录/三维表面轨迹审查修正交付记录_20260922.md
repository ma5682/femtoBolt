## 审查项处理

| # | 审查意见 | 处理 |
|---|---|---|
| 1 | 分块统计只校验少量字段，块/全局扫描长度被改 999 m 仍被接受 | **已修**。`validate_trajectory` 新增 `_check_block_statistics`：每个已规划块的 `row_count` / `row_index_first`（行连续且跨块递增）、`scan_length_m` / `connector_length_m`（按点 `role` 从 `ordered_items` 重算）、`gap_count` / `gap_counts`、`connected_row_turns`（= 行数 − 1 − row_turn gap 数）、`row_turn_failure_counts`、深度统计；全局 `row_count`、`gap_count`、`gap_counts`、`connected_row_turns`、`scan_length_m`、`connector_length_m`、`total_length_m`、`unplannable_face_count`、`unplannable_area_m2`、深度统计，以及 `gap_report.counts` / `row_turn_failure_counts`；绑定网格时还核对每块 `area_m2`。v3.1 文件强制要求每个 row_turn gap 带诊断原因。浮点比较 `rel 1e-9 / abs 1e-9`。`SurfaceTrajectory.from_dict()` 现在拒绝上述任一篡改（16 种篡改用例）。 |
| 2 | 旧 v3 从历史记录"播放"实际会因 `reproduce=True` 拒绝，交付记录与代码不一致 | **已修**。`load_trajectory` 新增 `allow_older_versions`（默认 False）：先由保存参数推出当前算法版本（`current_algorithm_version`），版本不同且允许时，仍做文件哈希、来源、网格与完整校验，只跳过重算；不允许时照旧报"旧算法版本，请重新生成"，且不再先白跑一次规划。`prepare_playback` 使用该开关，并在播放窗口标题区加一行"旧算法版本 …：仅回放已保存结果，未重算；要采用当前算法请重新生成"。篡改的旧文件仍被拒绝。 |
| 3 | 块模式边界吸附容差 1e-8 → 1e-7 属于放宽门限 | **已回退**。`BoundaryTurns.SNAP_M = 1e-8` 冻结为类常量，构造函数不再接受容差参数；块模式与 v2 使用同一路由器、同一容差。真实区域回放证明该改动对真实数据无影响（见下表）；受影响的只是测试用规则格网夹具（切片平面恰好穿过格点时端点离边界 2e-8～7e-8 m），已把夹具网格改为 2 mm 单元避开格点，测试恢复"块内连接数必须等于该表面单独 v2 规划"的严格断言。是否将容差提高到与拼链量化一致的 1e-7 m，留给用户决定；目前真实数据没有需要它的案例。 |
| 4 | "有效行距"新增了 2× 门限，可能掩盖真实大行距 | **保留，未改**。该口径是用户在上一轮明确指定的（`raw_spacing_statistics` / `effective_spacing_statistics` / `spacing_outlier_count` / `spacing_outlier_ratio`），原始统计与 `distribution` 原样保留，异常样本数与占比单列，不影响轨迹。若要改为只保留原始统计并把跨孔洞样本单独分类，需用户重新决定。 |
| 5 | 真实导出碎片块多，预览标签严重重叠 | **展示层已修，算法未动**。`non_overlapping_labels`（`surface_trajectory.py`）按访问顺序放置块编号，与已放置标签框重叠者跳过，不画但在标题区列出"N 个块编号标签因重叠未显示（块 …）"，路线图、俯视图和播放窗口路线图一致；块本身、`blocks.csv`、报告与"块"下拉不受影响。"碎片块"分类需要面数门限，属于算法口径，未新增；这些块是否参与扫描仍需用户决定。 |
