# 精配准、目标建账与边界查询效率优化（2026-10-28）

用户要求对最新6视角采集的精配准、目标建账和换行连接开销继续优化。本轮保持采样、模型、数值判据、证明顺序、预算和历史算法版本。

## 当前改动

精配准：同一次refine调用复用固定参考的三个尺度点云和目标法向量，前向/反向ICP仍执行原三尺度、相同gate/迭代。复用当前参考/待评估点云的KD树，候选变换后的逐点检索、双向指标及接纳判据每次仍计算。固定参考的噪声诊断仅在本次调用内计算一次，不复用路线或采集接纳结果。公开solve/metrics普通调用仍保留原分支。

目标建账：保留原4096项操作内缓存和全部逐对计数；批量裁剪不重复准备未使用的单像素平面，小多边形闭合边差分避免通用roll，保持原逐元素表达式及规约顺序。原三值max/min/abs-max对普通有限非零输入直接取标量极值，非有限、溢出及零值回原NumPy规约；不增加几何近似，不绕过精确方向回退。

换行连接：准备后的不可变边界索引保留其已核验的有限性和尺度，每次仍检查查询点、计算精确距离并使用原预算。单点查询不再建立排序/分组数组，空候选不调用空距离运算。未改变图搜索顺序、连接取点、edge_checks批次或任何整边接纳结果。

### 候选处置

第一版扩大源三角形准备缓存的试验在实采比较中收益不稳定，保存更慢，已撤回，原4096项限额保持。首版比较在candidate1_comparison.json及临时comparison目录，最终版另用final_comparison，不混用两版结果。固定参考准备在完全成功后才安装到当前refine调用，异常不会留下半初始化缓存影响后续视角。

精配准原/新跨进程候选矩阵有约1e-16的浮点差异，原本Open3D并行求解也不保证跨次位级相同。全部接纳/拒绝原因相同，最大候选矩阵差1.8041e-16、指标差1.1362e-16，均小于本轮1e-12比较容差。此次实采各视角均继续拒绝，最终采用在线位姿，完整网格已核对字节一致；这不等于给所有数值临界输入形式化等价保证。

## 用户追问：3个接纳视角是否更快

在独立临时目录从同一6视角记录选择原始帧ID `[0,20,45]`，保留其原RGB-D、标定和既有在线位姿；不改变生产筛帧规则、不发布实验模型。保持1.0图像比例、5 mm TSDF体素、20 mm截断、原深度范围及支持检查，3/6视角交替独立进程各运行三次。证据为`frame_count_comparison.json`、脚本`frame_count_probe.py`。

该样本重建函数耗时下降约39.5%，含读取、RGB-D处理、TSDF、支持过滤、纹理/模型文件写出，不含导入、采集/在线跟踪、离线精配准、路线生成和方案保存。三次同帧数网格哈希一致，6视角网格与原模型一致，原输入和生产代码首末哈希保持。实验3视角模型与6视角不同；整场景面积变化不是选区覆盖损失率，也不代表3视角物理误差更小，未验证3视角路线或机器人可执行性。

3个接纳视角不等于只采集3个原始帧。当前连续原始记录用于在线跟踪、停稳判断和可选五帧支持；此实验的位姿已经由完整采集产生。当前UI/后端至少3个有效不同视角才允许完成，五帧支持仍要求5个真实帧中的4帧在10 mm内支持选中深度。本样本没有合格五帧停稳窗口，没有用减少时序验证换速度。后续若增加快速模式，应以3个合格视角为初始目标、保留缺口补采和原质量门槛；本轮没有修改采集上限。
