# IO 工具收口与实验脚本归位交付记录（2026-09-20）

## 目标

对应代码结构评估中的第 3 项（IO helper 重复约 29 份）和第 7 项（根目录堆积一次性脚本）。本轮不改任何采集、对齐、位姿、融合、TSDF、Mesh 参数或数据格式，只做实现收口与文件归位。

## 变更

### 1. 新增 `io_utils.py`，成为 JSON / JSONL / 图片读写的唯一实现

| 函数 | 语义 |
|---|---|
| `load_json(path)` | `utf-8-sig` 读取，容忍 BOM |
| `load_json_object(path, message=...)` | 同上，顶层非对象抛 `ValueError` |
| `load_jsonl(path)` | 每个非空行一个 JSON |
| `write_json(path, value, indent=2, allow_nan=True)` | 原子写（`.tmp` + `os.replace`），自动建父目录，`ensure_ascii=False` |
| `write_json_strict` | `write_json` 的 `allow_nan=False` 版本 |
| `write_jsonl` / `append_jsonl` | 紧凑分隔符、逐行 |
| `imread_unicode(path, flags)` | `np.fromfile` + `cv2.imdecode`；解码失败抛 `ImageCodecError`，文件不存在抛 `OSError` |
| `imread_unicode_or_none` | 校验器专用：读不到或解不开返回 `None` |
| `imwrite_unicode(path, image, params=None)` | `cv2.imencode` + `write_bytes`，自动建父目录 |

`ImageCodecError` 同时继承 `ValueError` 和 `RuntimeError`。原来的副本一部分抛 `RuntimeError`（`scene_capture` / `top_scan` / `synthetic_scene_demo`），一部分抛 `ValueError`（`scene_to_nerfstudio` / `complete_demo` 等），而 `scene_to_nerfstudio.convert` 的阻断报告只捕获 `ValueError`。双继承让所有现有 `except` 子句行为不变。

`cv2` 只在图片函数内部延迟导入，因此 `.venv-gsplat`（无 OpenCV）里的 `scene_gsplat_viewer`、`scene_gsplat_acceptance`、`scene_single_gs` 等模块可以正常 import `io_utils` 使用 JSON 函数。已在 `C:\FemtoGsplatRuntime` 下实际验证 8 个模块 import 成功。

### 2. 删除 29 处重复定义，改为别名 import

被替换的定义：`_load_json` ×5、`read_json` ×5、`_read` ×3、`write_json` ×3、`imwrite_unicode` ×3、`_write` ×2、`json_dump` ×2、`append_jsonl` ×2、`imread_unicode` ×2、`_read_image`、`read_image`、`load_json`、`load_jsonl`、`_imwrite`、`_write_json`、`_write_jsonl`、`dump`、`read`、`write`、`rows`（`local_geometry_diagnostics`、`scene_quality_report`、`research_validation` 中的同类单行函数一并收口）。

每个模块保留原来的本地名字，例如 `from io_utils import write_json as json_dump`、`from io_utils import imread_unicode as _read_image`，调用点不动，测试里 `mock.patch("scene_temporal_fusion.imwrite_unicode")`、`mock.patch.object(estimator, "_read_image")` 等仍然生效。

同时把 22 个"为了写 JSON 而 `from scene_capture import json_dump`"的 import 改到 `io_utils`。`scene_capture` 顶层 import Orbbec SDK，此前所有局部补采、时域、重建模块都因此传递依赖 SDK；现在只有真正需要相机的 `write_calibration` / `create_session` 还从 `scene_capture` 取。

### 3. 有意的语义统一（不是 bug 修复，但行为有微小差异）

- `scene_dataset_validator.load_json` / `load_jsonl` 原来用 `utf-8`（不容忍 BOM），现在与全仓库一致使用 `utf-8-sig`。这是放宽，符合 CLAUDE.md "JSON 一律 utf-8-sig 读"的约定；`load_jsonl` 对纯空白行由报错改为跳过。
- `scene_single_gs.write_json`、`synthetic_scene_demo._write_json`、`scene_quality_report.dump`、`research_validation.write` 原来是非原子写，现在原子写并自动建父目录。
- `local_*` 系列写 JSON 保持 `allow_nan=False`（走 `write_json_strict`），`scene_*` 系列保持默认允许 NaN，与原实现一致。
- `multiview_texture.read_image` 的错误文案由 "Cannot read texture source" 变为 "Cannot decode image"，无测试或调用方依赖该文案。

### 4. 实现指纹

`local_comparison.py` 与 `local_parameter_study.IMPLEMENTATION_FILES` 记录的实现文件列表新增 `io_utils.py`。旧对照报告的 `implementation_sha256` 键集与新列表不一致，将按既有规则被判为实现已变更、不可复用，这是预期行为。

### 5. 实验脚本移入 `tools/`

`benchmark_depth_quality.py`、`diagnose_local_span.py`、`scene_gsplat_experiments.py`、`validate_temporal_keyframe.py`、`verify_temporal_fusion.py` 通过 `git mv` 移入 `tools/`，各自在文件头把仓库根目录加入 `sys.path`，从根目录以 `python tools\<name>.py` 运行；输出路径仍为根目录 `outputs/`。它们没有 `.cmd` 入口、没有被任何模块 import、没有测试覆盖。`tools/README.md` 记录了每个脚本的用途与对应历史记录。引用它们的三份 doc 与 `技术路线.md` 已加注新位置。

其余 14 个"未被 import"的模块保留在根目录：它们要么是 `.cmd` 入口（`top_scan`、`view_latest`、`depth_debug_viewer`、`scene_3dgs` 等），要么被子进程按路径调用（`export_preview`、`segmented_cloud_viewer`），要么有测试或使用说明（`local_interrupted`、`local_parameter_study`、`research_validation`、`depth_quality_replay`），要么是安装脚本（`download_model`、`download_verified_file`、`patch_gsplat_windows`）。
