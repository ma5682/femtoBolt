## 取消与界面验证

以冻结 large 和 real_30553 样本分别在约 0.1 s、0.5 s 后请求取消构造，四次均抛出取消异常、没有发布输出。记录的是事件实际发出到异常返回的时间，线程调度造成的请求延迟另行保存。

| 样本 | 计划请求时刻 | 实际请求时刻 | 请求到取消响应 |
| --- | ---: | ---: | ---: |
| large | 100 ms | 124.3 ms | 0.8 ms |
| large | 500 ms | 515.1 ms | 0.6 ms |
| real_30553 | 100 ms | 108.1 ms | 9.9 ms |
| real_30553 | 500 ms | 526.1 ms | 4.0 ms |

测量时本机也在运行完整回归，因此不是隔离负载下的最坏响应保证；不覆盖每一种 NumPy 操作、磁盘压缩或驱动调用的抢占延迟。脚本及逐次日志见 [check_cancellation.py](../../outputs/iteration_p0_p1_20261008/check_cancellation.py)。

使用独立 offscreen 合成窗口，验证 1600×940 与 1120×740 逻辑窗口、`QT_SCALE_FACTOR=1/1.5/2`。最终 30 张截图包含路线摘要、目标详情、核对保存、参数过期、恢复完全相同输入、新历史及旧历史状态；检查六步按钮文字、主操作、播放、核对控件位置和完整摘要高度。
