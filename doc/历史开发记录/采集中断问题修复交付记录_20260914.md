# 采集中断问题修复交付记录

日期：2026-09-14。项目：E:/测试3D人体关节坐标。

本轮针对用户反馈“采集中突然结束，只能重新建立原点”核对真实日志、修改代码并回归。所有定位数值仍是研发估计，未完成真实精度验收。

## 已确认的原因

截图的 3 个接纳视角、92,356 个预览点，精确对应 datasets/scene_20260914_174841_local_37552cc6。

- 接纳关键帧 ID 为 0、21、35；52 张原始跟踪帧中，末次可信帧为 ID 46。
- ID 47–50 连续出现 pair_quality，ID 51 仍有同步 RGB-D 输入，但距末次可信帧的主机接收间隔为 2.125 s，进入 tracking_gap。此次原因是跟踪丢失，日志不支持“相机突然断开”的判断。
- 这次会话平均处理 2.23 帧/秒，主机收帧至完成位姿平均约 541.5 ms、P95 625 ms；295 次队列替换针对尚未处理输入。取景刷新率、相机标称帧率和有效位姿帧率不同。
- 原算法每个帧对都从单位矩阵初值求解。只读回放 ID 46→47 复现正反向平移残差约 360.8 mm、旋转残差约 20.38°，并出现超过 0.25 m 的估计单步位移，正确触发拒绝。该残差是算法内部不一致，不能称为实物测量误差。
- 原 UI 的异常提示在大预览图片后排布，可能被挤出窗口；失败后步骤栏仍突出“移动补采”，右侧仅写“采集已结束”，没有明显说明为什么不能继续。

门限保持：fitness≥0.15、RMSE≤0.06 m、单步≤0.25 m/25°、双向一致性≤0.01 m/2°、RGB-D 同步≤5 ms、2 s 时效/连续性、连续 5 帧失败。无效 fitness 增加有限性检查。一次帧内重试不会增加允许失败的帧数，也不会把初值矩阵直接写成测得位姿。

首个有效彩色相机建立的 W0 保持固定；最终模型选点坐标、原点直线距离、两点距离、标记与区域回读不变。局部暂停跟踪、停稳补采、累计预览/高亮、结束融合、固定/时域采集、3DGS 与报告入口保留。没有新增运行时依赖。

## 如何操作

1. 关闭旧程序，再运行 start_femto_app.cmd。已经打开的旧进程不会自动装载新代码。
2. 建立原点后缓慢移动，保留与上一视角重叠，停稳后补采。
3. 黄色“暂不可信”时立即停稳、保持视野；当前帧被拒绝，软件在原连续会话中尝试重新求解。恢复正常后继续补采；手动暂停状态不会被自动解除。
4. 红色“跟踪已中断”时查看主视图上方的具体原因，点击右下“查看本次报告”。已结束的旧会话不能直接续接；下一次“重新建立原点并开始”会创建新会话，保留旧数据。

“暂停补采”仅暂停接纳关键帧，不能当作停止整个相机流后再任意续接的功能。真正失跟后的同原点恢复需要重定位能力，当前产品范围仍未实现；失败会话不会发布成功前缀模型。
