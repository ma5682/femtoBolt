# 三维表面轨迹选择组件分块与块内连续覆盖交付记录

> 日期：2026-09-22 ～ 2026-09-23
>
> 基线：审查修正提交 `70f083b`（v3.1）。本轮保留该基线的统计校验、旧 v3 播放兼容、1e-8 m 吸附容差和行距过滤行为，不做回退。
>
> 起点：Codex 在工作树中留下的三处未完成改动（`fixed_rgb_geometry.region(selection_intent=…)`、`scene_annotations._validate_selection_intent`、`fixed_rgb_viewer.finish_polygon` 里的多边形版 `selection_intent`）由本轮接手重写：多边形无法表示多个分离组件、孔洞和无 Mesh 位置，改为以涂抹像素掩膜为权威记录。

## 一、阶段 0 结论：现有选区数据流能否表达医师意图

| 问题 | 结论（改动前） |
|---|---|
| 是否保留完整选择轮廓或掩膜（含无 Mesh 位置） | 否。全分辨率掩膜只在界面内存中存在；落盘的是 `screen_polygon` / `work_screen_polygon` / `forbidden_screen_polygon`，受 512 角点上限、1 px 简化和整笔拒绝影响，是有损轮廓。 |
| 能否表示多个分离组件和内部未选孔洞 | 三维上由 `triangle_indices` 与边界孔洞隐含表示，二维上是一条带双向桥接边的偶奇多边形；组件和孔洞都没有作为对象枚举。 |
| 能否区分明确未选、无深度、Mesh 缺面 | 否。`FixedProjection.reasons`（supported / no_surface / outside_depth_range / depth_conflict / no_source_pixel）只在内存里，导出只有聚合计数 `geometry_support`。 |
| 原始点云是否有可核验路径、坐标系、哈希与来源绑定 | 否。`region_N.json` 只绑定区域网格 PLY（名称 + SHA-256）、源网格绝对路径与数组摘要、参考 RGB/Depth 内容哈希；融合点云与 `local_geometry.json` 不在清单内。`region_1_vertices_m.ply` 只是区域网格顶点，不是点云。 |

因此仅凭筛选后的 `triangle_indices` 不能反推医师意图，需要向后兼容地补充"选择意图"权威数据。

- 固定 RGB 页 `finish_polygon`：最终掩膜（工作区 − 禁区，或有效范围 − 禁区）连同涂抹禁区掩膜与组合方式一起交给 `FixedRGBModel.region(selection=…)`；三角面改为按"可见面心像素落在掩膜内"选取（`selection_rule=visible_triangle_centroid_pixel_in_selection_mask`），遮挡射线、深度一致性与 `image_valid` 门禁不变；旧多边形规则保留给旧记录。状态栏追加组件数、内部孔洞数和几何待确认像素数。

- `planning_state.region_signature` 未改：新键位于 `region` 内，新区域的签名自动包含意图，旧区域签名不变。

## 三、阶段 B：`mesh-slice-serpentine-v4`（`selection_blocks=true`，已完成）

- 新模块 `femto/planning/selection_blocks.py`；`plan_mesh_slice(..., selection_blocks=True)`；历史"生成 / 重新生成三维扫描轨迹"、`生成三维蛇形扫描轨迹.cmd` 和 CLI 默认采用 v4；`--mesh-blocks-v3` 显式回到 v3.1。`block_planning=True` 不带 `selection_blocks` 仍精确产生 v3.1，其 20 项回归未改语义（仅历史生成相关两项改为 v4 夹具）。
- **工作块 = 医师选择组件**：区域 PLY 的每个三角面按面心像素归属到选择组件（与选取规则一致；面心不在掩膜内的导出判定为不一致并拒绝）。块访问顺序按掩膜包围盒从 `start_corner` 起的阅读顺序，同值按组件编号。没有任何有支持三角面的组件是 `unplannable / no_supported_geometry`（"几何待确认 / 需要补采"），不静默丢弃。
- **Mesh 连通分量只作碎片诊断**：块内三角面按共边连通分成碎片，按阅读顺序逐个用 v3.1 的切片 / 行序 / 折返机制规划；碎片之间的接缝保留为 `disconnected_surface` gap（`link_failure_reason=disconnected_measured_surface`），永不桥接。
- **块内每一对相邻扫描段都尝试贴面连接**（`surface_row_turns.SurfaceLinks` + `connect_links`）：相邻行先用冻结的 v2/v3.1 边界带折返（成功处与 v3.1 输出相同）；其余链接（同行绕孔、非相邻行、边界带失败）改走该碎片自身网格边上的最短路径（A\*，欧氏启发，与 Dijkstra 同解）：每条 connector 边落在同一选中三角面上、不离开参考图像、不触碰涂抹禁区 / 排除多边形（整条边判定，不只端点）。找不到时保留 gap 并记 `link_failure_reason ∈ {disconnected_measured_surface, forbidden_blocked, outside_reference_image, no_surface_path, budget_exceeded}`（`decision_use=none`）。
- **块状态**：`planned` = 恰好一条连续链且块内 `gap_count==0`；`incomplete` = 有链但存在块内 gap（原因逐条记录）；`unplannable` = 没有任何链。块间只放 `selection_break` gap（"选择分离"），播放到块间暂停，继续只定位下一块起点。
- **连续 ≠ 覆盖**：`statistics.continuity_status`（全部块单链才 complete）与 `coverage_status`（存在无法规划块、未覆盖网格碎片或几何待确认像素即 partial）分开；每块 `coverage` 记未覆盖碎片 / 面数 / 面积和几何待确认像素；`treatment_coverage_claim=none_without_effective_head_width`。
- **重复经过**：connector 采样若落在其所连接两行之外的已扫描行采样的名义半行距内，标 `revisit=true`，块与全局统计采样数与长度，预览 / GLB 用洋红显示，报告注明"按名义行距判定，非治疗头宽度，不得据此推定治疗能量持续开启"。
- **校验**（`validate_trajectory(..., region=…)`，`load_trajectory` 传入区域）：块 / 碎片 / 连续 / 覆盖 / 重复经过 / 链接失败计数全部从 `ordered_items` 重算；`planned` 块必须单链无 gap；块间 gap 恰为 `selection_break`；块内 gap 必须带 `link_failure_reason`；绑定网格与导出时重算选择组件与面归属、碎片连通性、面清单哈希、面积、像素计数，核对 `selection_binding` 意图 / 支持哈希，逐点归属块，connector 边不得穿越禁区或离开图像。
- **输出**：JSON 附加 `blocks`（`femto-surface-trajectory-blocks-v2`：碎片、连续、覆盖、选区、重复经过、链接规则、选择绑定）、`selection_semantics`、`gap_report.link_failure_counts / incomplete_blocks / gap_cause_counts / geometry_unconfirmed`；`trajectory.csv` 增 `role` / `revisit` 列，`gaps.csv` 增 `link_failure_reason`，`blocks.csv` 增连续 / 覆盖 / 像素 / 重复经过列；GLB 增 `selection_break` 端点标记、洋红重复经过管线和 `selection_blocks` 元数据；路线图与播放窗口叠加选择组件轮廓（青）、明确未选（红）、有深度缺面（紫）、无可靠几何（橙）；报告逐块逐碎片列出状态、原因与覆盖缺口。既有键、文件名、单位与 v1/v2/v3/v3.1 语义不变。
- **历史与发布策略**：存在 `incomplete` / `unplannable` 块时新结果仍完整生成、校验并可回读，但不删除、不替换旧的有效轨迹（`cleanup=skipped_incomplete_result`），历史列表同时显示最新完整结果与更新的未完成结果并标注"未完成结果，旧轨迹保留"；全部块单链完成后才执行既有清理流程。
- **旧导出 / 旧版本**：无意图记录的导出在 v4 下拒绝（`selection_intent_missing`，提示重新选择并导出），历史重新生成保留旧结果，CLI 写 `trajectory_blocked.json`；旧 v1/v2/v3/v3.1 文件继续可读、可预览、可播放，播放窗口提示当前产品规则为 v4；v4 文件所绑定导出若失去意图记录则拒绝回读。

### 三种"断开"的处理

| 情形 | 处理 |
|---|---|
| 医师明确选择多个分离区域 | 每个 4 连通选中组件一个工作块；块内单链；块间 `selection_break` 停止标记，无跨块点、连线或运动。 |
| 医师明确未选的内部区域 | 记为 `explicit_unselected_holes`（含涂抹禁区像素数）；面心落在其中的三角面不入区域 PLY；路线在已选三角面上沿孔洞边缘或碎片网格边绕行；涂抹禁区按既有像素多边形语义整条边严格避让；绕行无法完成时保留 gap 并报告原因，块记 `incomplete`。 |
| 选中但 Mesh 孔洞 / 缺面 / 碎片 | 覆盖需求保留；逐像素记录 `measured_mesh` / 有参考深度缺面 / 无深度 / 深度冲突 / 无源像素；碎片作为块内诊断逐个规划，接缝不桥接；无任何支持的组件标 `no_supported_geometry`（需要补采）；不生成任何伪实测 XYZ，所有轨迹点仍为 `measured_mesh`。 |

## 四、阶段 C：派生工作表面（未完成，待用户决定）

仓库现有能力核对结果：没有已确认的"从点云在 Mesh 孔洞内重建表面"的方法或门限。已确认的是 TSDF（5 / 20 mm）+ 单视角 10 mm 面支持、单帧像素邻接网格（max(10 mm, 2%)·√2）、五帧 4/5 within 10 mm 像素掩膜和深度图像补洞（≤64 px、置信 0.30，且局部测量链明确不积分修复像素）；`fill_small_mesh_holes` 只在患者分支 CLI 使用、按拓扑封孔、无场景链默认值；区域导出的顶点 PLY 只是区域网格顶点，融合点云与 `local_geometry.json` 均未绑定在清单中。

本轮只做了可独立完成的部分：逐像素标出"参考帧有深度但 Mesh 缺面"的候选（`derived_surface.candidate_pixel_count`，`status=not_generated`，`reason=pending_user_confirmed_method_and_thresholds`），报告中单列，不生成表面、不参与轨迹。需要用户决定的项目见《三维表面轨迹_选择组件分块与派生表面待决项_20260923.md》第 3 节：可采用的点云来源与绑定方式、孔洞最大尺寸、邻域半径 / 最小点密度、与周边网格的深度 / 法线差、拟合误差与置信度门限、多视角支持要求、派生面的 `geometry_support` 标签与 `data_layers` 契约扩展方式。

## 五、验收测试（`tests/test_selection_blocks.py` 12 项 + `tests/test_selection_intent.py` 8 项）

1. 一个选择组件对应两个 Mesh 碎片 → 1 个工作块（`incomplete`，2 碎片，接缝 gap），同一网格在 v3.1 下仍是 2 块。
2. 两个分离选择组件 → 2 个 `planned` 块，块间唯一 `selection_break`，播放到块间暂停、继续进入下一块。
3. 明确未选孔洞：意图记录 1 组件 1 孔洞，孔内三角面不入 PLY，块内单链 `gap_count==0`，同行绕行 + 折返均在选中三角面上，无采样进入孔洞内部。
4. Mesh 缺面但参考帧有深度：候选像素计入报告，`derived_surface=not_generated`，轨迹点全部 `measured_mesh`，覆盖 partial（阶段 C 未实现的显式固化）。
5. 深度歧义（`depth_conflict`）行不产生采样并计入待确认；无支持组件为 `no_supported_geometry` 并提示补采。
6. 投影重叠 / 空间相近但分离的表面：同一块内 2 碎片、`incomplete`，链不跨碎片，每条 connector 边受同一三角面支持。
7. `planned` 块单链；人为插入块内 gap（含配平统计）校验失败。
8. 单链仍可能遗漏：1 面碎片作为未覆盖碎片、无 Mesh 像素作为几何待确认，连续 complete 而覆盖 partial，报告列出。
9. 11 种统计 / 块 / 绑定篡改、导出意图改变后的来源不一致、connector 穿越排除区、扫描点落到其他选择组件均校验失败。
10. JSON / CSV / GLB 节点顺序 / 播放器链顺序一致；路线图、播放窗口含选择叠加；报告与文件一致。
11. 无意图旧导出：v4 拒绝且提示重新选择导出，历史重新生成保留旧结果，CLI 写 blocked 记录，`--mesh-blocks-v3` 显式可用；旧 v3.1 文件可读可播放并提示 v4；导出失去意图后 v4 文件拒绝回读；v3.1 载荷冒充 v4 拒绝。
12. 取消 / 校验失败 / 未完成块：旧结果不删除；未完成结果发布但 `cleanup=skipped_incomplete_result`，历史列表两者并列。
