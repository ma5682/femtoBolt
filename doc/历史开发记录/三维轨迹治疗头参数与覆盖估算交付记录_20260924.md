# 三维轨迹治疗头参数与几何覆盖估算交付记录

> 日期：2026-09-24　基线：`feature/surface-trajectory`（v4.4）。起因：用户反映路线过密，确认"有效治疗宽度 + 重叠率决定行距，外壳直径、治疗深度、安全边界先记录"的方案并要求实施。

## 一、做了什么

- 新模块 `femto/planning/treatment_head.py`：
  - `head_parameters(mode, …)`：`direct_row_spacing`（直接填行距）或 `from_effective_width`（行距 = 宽度 ×（1 − 重叠率/100），四舍五入到 1e-6 mm）。重叠率 0–90%；行距必须落在规划器原有 0.5–100 mm 内，超出拒绝，不夹取。深度 0–200 mm、直径 1–300 mm、安全边界 0–100 mm 只做数值合法性检查。记录 `values_status`（参数框默认 `placeholder_not_device_parameters`，CLI 为 `user_entered_unverified`）、`deferred.usage=recorded_only_not_used_by_planner`、`safety_margin_semantics=housing_clearance_for_future_collision_check_not_region_inset`、`execution_ready=false`、`physical_accuracy_verified=false`。
  - `coverage_estimate`：区域 PLY 每个面的面心到最近扫描采样（`role=scan`，连接段不计）的三维欧氏距离 ≤ 半个有效宽度即计为覆盖，按面积加权；未覆盖面按"是否接触网格边界边"分为边缘或孔洞周边 / 内部。最近邻用 Open3D 0.19 `core.nns`（已有依赖）。注明：用采样而非折线（最多低估半个采样步长）、欧氏非测地、面心决定整面、占位宽度时数值仅示意；`claim=geometric_estimate_on_measured_region_mesh_not_treatment_coverage`、`decision_use=none`。
  - `write_record` / `load_record`：`treatment_head.json` 绑定 `result_sha256`，要求行距等于 `planner.parameters.row_spacing_mm`；回读从记录输入重建参数、重算覆盖并逐字比对。只记录的输入（如直径）由 `trajectory_files.json` 哈希保护。
- 参数框 `femto/planning/treatment_head_dialog.py`：两种模式、六个输入、实时显示计算行距，非法时"生成"不可用；同一历史窗口记住上次输入。
- 接入：历史页"生成 / 重新生成三维扫描轨迹"先弹参数框（取消则不生成）；`trajectory_history.generate(row, control, head=None)` 只把行距传给规划器，并在导出时写记录、在 `trajectory_report.txt` 末尾追加"【治疗头参数】"；"查看规划检查"同样追加；旧轨迹清理白名单加入 `treatment_head.json`；`load_trajectory` 存在记录时校验。CLI 新增 `--head-width-mm`（与 `--row-mm` 互斥）、`--overlap-percent`（需 `--head-width-mm`）、`--treatment-depth-mm`、`--head-diameter-mm`、`--safety-margin-mm`；都不给时行为与以前相同。
- 未改：`trajectory.json` 结构与 `result_sha256`、重算比对、v1–v4.4 规划语义、1 mm 采样冻结、全部门限与预算、`result_complete` 与发布策略、GLB 管线（预览变慢的修复未包含在本轮）。
