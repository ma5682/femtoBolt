# 单机硬件预备迭代优化评估（2026-10-22）

依据[原迭代要求](../技术资料/单机上位机硬件预备开发提示词_20261021.md)、当前技术基线、源码及实际复现进行评估。本次为审查与后续任务建议，未实施下列产品修改。

当前设备配置、模拟协调、坐标与间隙工具、双库记录、故障处理和工作台入口已有实现。已有软件闭环可以继续使用；本次发现一项应优先修正的操作响应问题，以及两项已复现的功能完善点。它们均可在真实硬件未到位时处理。

## 已复现的问题与建议

### P1：导出记录占用控制线程，期间不能从按钮请求停止

**触发方式：** 开始模拟任务，在运行中选择“导出模拟事件”。

**实际行为：** 运行状态允许导出。导出与设备轮询共用 `SimulationOwner` 线程，导出执行期间页面的普通 `busy` 状态同时禁用了“请求停止”。即使直接向业务入口提交停止，也只能排在导出之后处理。

本次用真实 Qt 页面、模拟协调器和临时数据库运行合成任务，只对导出加入可控等待。在约 0.312 秒的观察窗口内，停止按钮不可点击、直接提交的停止尚未处理；释放导出后才完成停止。这证明线程调度与按钮门控存在耦合，不是实际磁盘耗时基准。

**建议修改：**

- 历史读取和事件导出使用独立、可取消的只读 IO 工作任务，不占用处理模拟控制与反馈的所有者线程。
- 普通 IO 忙碌不禁用停止；停止和关闭优先处理，任务状态仍由协调器串行维护。
- 导出明确标注读取时刻与任务状态，保留同一只读事务的任务/事件一致性。

**验收：** 在导出、历史刷新、慢来源核验期间请求停止，设备反馈仍持续被处理；不会重复下发、误报已停止、串用旧结果或破坏导出快照。磁盘异常与关闭取消沿用原缺口/未知规则。

**代码依据：** [qt_execution.py](../../femto/app/qt_execution.py) 第 200–355 行的所有者循环、第 297 行导出分支、第 542–558 行按钮门控；[history.py](../../femto/execution/history.py) 的 `read/export`。

### P2：模拟历史增加分页、查询和按需事件加载

**触发方式：** 累计超过 200 个模拟任务，查找较早记录。

**实际行为：** `ExecutionStore.runs()` 默认只返回最近 200 条，UI 使用没有分页或搜索的下拉框。本次写入 201 条显式合成测试记录后，数据库仍有 201 条，页面只有 200 条，最早记录无法从页面选到。该记录没有丢失，按已知 ID 调用仓储仍可读取。

此外，回看虽然只显示最近 400 条事件，但后台先读取全部事件，再把完整 JSON 传到 UI，最后才截取显示范围；大量事件场景仍会产生不必要的读取与内存开销。后者属于代码确认的优化点，本次未做大规模性能测量。

**建议修改：**

- 任务按时间及任务 ID 游标分页，支持日期、状态、方案修订/任务 ID 查询。
- 保持刷新前的选择，列表显示任务时间、方案名称与结果，避免只能辨认截断 ID。
- 事件按序号分页，并支持请求 ID、设备、事件类型过滤；完整导出继续保留全部事件。

**验收：** 超过 200 条记录后仍能从界面找到首条；新增记录或刷新不造成漏项/重复；旧记录只读、来源变化提示和完整导出保持。分页后只加载当前所需事件，不以截断记录代替性能优化。

**代码依据：** [history.py](../../femto/execution/history.py) 第 110–127 行；[qt_execution.py](../../femto/app/qt_execution.py) 第 287–299、435–440、562–598 行。

### P2：支持保存和恢复整套设备组合

**触发方式：** 保存机械臂、治疗头配置，再依次通过“读取设备配置”恢复。

**实际行为：** 单设备读取把配置集合替换为只有一台设备的元组。本次保存默认两设备配置后，读机械臂并连接仅得到机械臂，再读治疗头并连接仅得到治疗头。默认场景本身仍可建立两设备模拟；缺口是缺少自定义设备组合的完整恢复入口。

**建议修改：**

- 增加版本化“设备组合配置”，引用各设备 ID、配置修订、摘要、参与角色、资源标识及场景版本。
- 支持整体选择、校验、保存和恢复，明确显示哪些设备参与、哪些不适用。
- 加载配置仍不自动连接，不给真实设备赋予模拟能力；替换组合继续遵循结束旧任务与隔离旧实例的规则。

**验收：** 两台以上设备和固定底座组合保存后可一次完整恢复；配置缺失、重复身份、修订变化或真实适配器未实现时给出明确结果；旧单设备配置继续可读。

**代码依据：** [qt_execution.py](../../femto/app/qt_execution.py) 第 241–260 行，特别是第 249、253 行；[configuration.py](../../femto/hardware/configuration.py) 的版本化单设备保存/读取。

## 可以随后安排的功能

| 优先级 | 建议 | 已有基础与边界 | 验收重点 |
| --- | --- | --- | --- |
| P3 | 常见故障场景选择器与场景编辑 | 已有版本化 Scenario、故障注入及 JSON 读取；当前界面主要依赖选文件。可以直接提供正常、拒绝、无响应、断连、停止未知、不支持暂停等预设 | 使用同一适配器与协调器；展示场景版本、软件时间预算及预期结果；非法组合在加载时拒绝 |
| P3 | 任务诊断摘要与时间线 | 当前实时事件文本和回看 JSON 已包含证据，可增加“首个失败原因→关联请求→各设备停止确认→持久化缺口”展示 | 能从摘要回到原事件；未知不显示为完成；不改变保存快照或裁掉异常记录 |
| 维护 | 收敛当前状态文档 | 技术基线的 SQLite 历史条目仍写“完整资产联合备份未实现”，与同页后续五项迭代和现有维护入口不一致；厂家交接清单末尾仍保留待最终回归的阶段措辞 | 依据实际交付证据更新当前状态，将阶段过程留在归档；不把其他在途迭代或实机验收一并宣称完成 |

这几项属于后续完善建议，不是用新入口替代已有模拟状态机、数据库或来源核验。建议下一轮先完成 P1，再做历史与设备组合两个 P2；故障预设和诊断时间线可以复用相同业务链逐步补充。
