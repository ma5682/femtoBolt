# 补充规划与覆盖复核 P3 交付记录

工作区：`E:\测试3D人体关节坐标-ui`，分支 `ui/workstation-redesign`。承接 P0／P1 和 P2／B2，按用户“继续”实现可选补充规划、恢复补充前路线、完整保存和历史回读。默认新路线仍使用 `quality-constrained-surface-v3`；补充版本为 `coverage-refined-surface-v1`。

## 可用行为

在路线页先核验模型覆盖，再点击“补充规划”。后台按未确认原因选择可用表面上的候选，检查每条新增扫描边和连接边，重新核验覆盖；只有原确认集合无损失且新增扫描点见证的增益达到门槛，才接纳本轮路线。未接纳、取消或失败时保留原路线和证据，结果仍需重新核对保存。

补充版本提供“恢复补充前路线”，同时恢复原计算修订、目标台账和覆盖证据。纯导航返回保留结果；实际修改区域、宽度或源输入使旧结果失效。已补充版本不能嵌套启动新一轮预算，需先显式恢复原路线。历史只读展示，原生包和便携工程都保存原路线及补充过程，独立打开时完整重放。

操作例子：打开已采集的右肩记录 → 确认工作区域并生成路线 → 核验模型覆盖 → 定位未确认原因 → 补充规划 → 检查剩余范围 → 核对保存。缺失、质量不足和预算未完成的范围仍保留；接纳补充不代表完整目标覆盖。详见 [使用说明](../使用说明/补充规划与恢复原路线.md) 和 [P3 契约](../技术资料/P3_补充规划与覆盖增益契约.md)。

## 算法与证据约束

仅 `outside_inner_seed_balls` 且原有效域允许的面可成为候选；质量、定位、构造、连通和预算未知不当作行距问题。按同工作块共边分组和未确认面积排序，在未确认叶中心沿该面最长边生成面内短切片，端点内缩 2%，最短 2 mm，沿用 1 mm 采样。没有扩展、插补或替换源 Mesh。

新增边复用原 v3 的整边、有效宽度、参考深度及边界判定。连接复用原共享面图，只带两端邻近扫描点参与搜索；共享面节点与谓词不变，可能保守地留下更多断点。连接输出再次逐边验收，记录通过状态、原因和残差余量。分离工作块没有规划转场，搜索失败也不证明不存在可行路线。原扫描边和连接边的坐标、角色及相对顺序保持，全局访问索引可重排。

旧、新覆盖分区以原目标根单元和深度 8 的四叉前缀整数区间求交，独立累计保留、新增、丢失集合，不能直接用两个汇总面积相减判定无回退。接纳还要求新增确认范围的 leaf → proof → seed 见证来自本轮新增扫描点；仅多算了旧扫描种子的证明不能使一轮补线获准。原目标数组逐项保持，只把台账清单绑定到新计算修订。

| 工程预算 | 默认值／上限 |
| --- | --- |
| 轮数、每轮候选 | 2 轮、每轮 4 个 |
| 连续低增益停止 | 2 轮 |
| 累计新增边验收和图检查 | 200,000 |
| 最终输出点 | 200,000 |
| 总路径长度增量 | 0.1 m，包含扫描及连接 |
| 新扫描见证增益门槛 | 0.1 mm²，研发计算参数 |
| 每轮覆盖时间 | 4 秒 |
| 各轮累计覆盖比较、邻接、证明 | 各 1,000,000 |

P2 的叶、深度、种子、数组和文件预算及原 120 秒操作期限不放宽。达到预算保留未确认范围，失败尝试仍保留记录；未执行覆盖的轮次没有伪造试验证书。最终证书及最多三组原始／轮次证书独立保存。完整版本、参数、绑定及重放约定见 P3 契约。

## 保存性能问题及修复

首次实际 Qt 合并保存耗时 **129.916 秒**，超过原 120 秒要求，见 [首次失败日志](../../outputs/iteration_p3_20261009/product_real_1.log)。第二次尝试原生包保存成功，但便携包被原 120 秒限制终止，页面保留当前方案并提示可重新保存，见 [第二次失败日志](../../outputs/iteration_p3_20261009/product_real_2.log)。两次失败和当时产物均保留。

[阶段计时](../../outputs/iteration_p3_20261009/profile_save/timings.json) 显示原生保存约 66.469 秒，其中原覆盖重放约 39 秒、目标验证约 15 秒；便携包重复同一计算导致合并超时。最终在同一 Qt 保存任务内使用不可序列化的验证凭据：原生目标／证明完整读回、重放和发布成功后签发；便携包只有在完整轨迹语义（含补充报告）、目标、最终及全部历史证据完全一致时复用此次计算。

凭据复用仍重新 hash 实际目标和证明数组，对每份新文件执行受界读回。更改语义、数组或 issuer 的凭据拒绝；文件无法携带凭据，独立打开和独立保存仍完整重放，旧 v3 保存流程保持不变。最终同一真实输入合并保存降至 66.364 秒，没有提高期限或放宽几何验收。

`probe/` 与 `probe.log` 是图搜索和记录格式收口前的探索结果，不作为最终格式回读证据；`product_real_1/`、`product_real_2/` 与 `profile_save/` 是性能诊断。正式产品验证以 `product_real_final/`、`positive/` 和最终六项检查为准。早期 unittest 的 PowerShell 重定向日志虽有 `OK`，仍包含 stderr 渲染的 NativeCommandError，不作为最终门禁；最终命令通过子进程合并原始 stdout/stderr 保存日志。
