## 当前产品范围

第一阶段优先支持人体主要体表区域：肩部、胸部、腹部、腰部、背部、臀部 / 髋部、上臂、肘部、前臂、腕部、手背、手掌、大腿、膝部、小腿。这里的“支持”定义产品范围，不代表相关采集、配准和规划能力已经实现或完成验证。

当前暂不支持头部、面部、颅颈精细区域、足部和脚趾。头部和足部可以在人形导航示意图中保留轮廓，但第一阶段应显示为“暂未支持”或不可选择，新建时不进入局部精细扫描、区域标记和路线规划。“暂未支持”只是当前产品阶段的范围约束，不表示算法永久不支持。下文“人体体表概览”不扩大此支持范围。旧记录中的暂不支持部位保留原值并允许只读回放，标记“当前版本暂不支持新建”，不得据此删除或静默修改历史数据。

### 手部支持边界

手部当前支持腕部、手背、手掌整体体表，允许这些区域进入局部精细扫描、工作区域涂抹与擦除和三维表面路线规划；仍需满足现有数据质量与几何约束。

第一阶段暂不重点支持单根手指、指尖、指缝、单个指关节的精细规划及多根手指之间的复杂表面路线，不将这些能力纳入第一阶段稳定产品范围，也不声称手指已完成验证。

原因应表述为：手指区域尺寸小、遮挡多、容易运动、相邻表面间距小，其深度质量、配准稳定性和路线可用性需要单独验证。不要归因为“Femto Bolt 无法采集手指”。

如果实际采集中的手指区域存在无效深度、遮挡、跟踪失败、配准质量不足或表面不连续，必须显示缺失或需补扫，不得使用通用手模型、姿态模型或插值结果伪装成可靠患者几何。

### 人体导航交互

第一阶段人体导航可选择：肩、胸/腹、腰/背、上肢、腕/手、髋/臀、大腿、膝、小腿。头部和足部体现为暂不支持，不能通过导航进入后续局部规划流程。

手部点击后优先进入腕部、手背、手掌，不展开为拇指、食指、中指、无名指、小指的逐指治疗规划。

人体导航示意图只用于部位选择，不属于患者真实几何。手部、腕部等区域仍必须来自当前患者的真实 RGB-D / 点云 / Mesh 数据。MediaPipe、Pose 或其他人体/手部关键点只能用于辅助导航或候选定位，不能直接作为工作区域边界、治疗目标或机器人坐标；继续遵循下文定位与几何约束。

## 产品流程

以“人体体表概览 → 选择支持部位 → 局部精细扫描 → 涂抹与擦除工作区域 → 检查路线并保存”为推荐起点，根据用户当前产品定义调整。

- 人体体表概览用于支持范围内的部位导航，覆盖信息以实际采集证据为准，不默认要求每个部位达到局部规划的精度。
- 明确体位，以及扫描的是当前可见体表还是多体位覆盖；仅在影响当前方案时询问仰卧、俯卧、站立等尚未确定的信息。
- 人体示意图用于导航。点击部位应打开对应患者的真实影像或提示采集，不能用通用人体模型代替已测量的患者几何。
- 候选部位允许自动提示和手动修正；患者左右、正背面需明确展示和确认。
- 医师可在与当前采集记录绑定的真实参考影像上涂抹工作区域。二维区域映射到三维表面时，只接受同时具有有效深度、有效标定、有效帧位姿且满足当前几何质量要求的数据点。选区可保留缺失位置的医师意图，但不得将其计作可靠患者几何。是否提供自由三维视角取决于产品需求，不强制引入 VTK。
- 当前新建区域的正式交互为“涂抹工作区域 / 擦除”，允许多个分离工作区域，允许通过擦除形成内部留空；不提供独立绘制禁止区域入口。
- 历史记录中已有的 forbidden region 继续保留、显示并从工作区域中扣除，不因新 UI 取消禁区工具而删除旧禁区或扩大旧规划范围。
- 每步展示当前部位、数据来源、质量状态和一个明确的主操作。使用“未采集、需补扫、待确认”等可行动状态，避免只有空白视窗。

### 两阶段采集与医师页面

推荐将医师操作组织为五个主要页面：患者与体位 → 定位与选部位 → 局部扫描与质量检查 → 工作区域标记 → 路线检查与保存。内部状态不必各占一页，坐标、标定等工程信息放入详情；主界面使用“概览扫描、建议扫描范围、需要补扫”等可理解的用语。

- 患者身份、当前空间状态和本次工作意图分别管理。身份来自病例选择、扫码或人工确认，视觉模块不自行推断身份。会话保存必要关联标识、体位、患者左右、设备配置和标定版本。
- 概览扫描（Overview Scan）用于人体/床体候选定位、可见面和部位导航；根据安装方式与实测质量采用单帧或多视角，不把完整高精度人体建模作为前提，也不因完成概览就宣称已获得可靠患者空间参考。
- 局部精细扫描（Treatment Scan）针对确认的扫描范围，输出真实数据、覆盖与缺失信息、模型及其参考坐标和版本。明确保存采集模式，粗定位数据不能自动取得局部规划质量资格。
- 部位选择只是意图。系统根据真实观测、有效位姿和目标部位提出 Scan ROI，由医师确认或调整；自动定位失败时可在真实画面中手动指定候选范围，但仍须经过有效深度和位姿校验，不能靠手动点击虚构三维位置。
- 区分目标候选范围、含周边上下文的 Scan ROI 和未来机器人检查的空间范围。上下文余量可配置，依据视野、定位误差和设备要求验证，不写死临床标准；不把机器人检查空间简化为一个必然包含扫描框的包围盒。
- 上层向采集模块传递会话、目标部位、ROI、参考坐标、采集模式和质量要求，字段以实际架构为准。Scan ROI 约束采集引导和派生计算，原始完整场景 RGB-D 保留，不用 ROI 裁剪结果覆盖采集证据。

默认新建顺序为先取得当前患者的概览和有效空间参考，再确定局部扫描范围。允许提前记录医师选择的部位意图，但仅凭示意图不能生成可靠三维范围或路线；概览完成也不自动证明 W0 已通过验证。

扫描范围与采集结果应区分以下语义，具体字段名称不强制：

- **Target Intent**：医师选择的部位、患者左右及可见面，仅表示任务意图。
- **Candidate ROI**：由当前患者真实观测定位的候选三维范围，能够追溯至有效深度、标定和位姿。
- **Scan ROI**：候选范围加上所需上下文的局部扫描范围；其存在不代表采集已经成功。
- **Coverage / Missing Mask**：记录范围内合格几何、未观察、遮挡、无效深度和质量不足的位置；不能用扫描框面积代替已测得的覆盖。
- **Robot Check Space**：未来检查治疗头、机械臂连杆、床体和可达性所需的空间，不能由 Scan ROI 直接替代。

上下文余量还应考虑局部曲率、边缘、法向估计与路线所需邻域、定位和配准不确定性，以及患者可能运动。参数应注明单位与来源，不自行编造固定阈值。Scan ROI 超出当前可靠观测时，显示缺失范围并引导补充概览或移动相机采集，不得静默截断后继续规划；若医师调整范围，应显式确认并记录版本变化。

采集请求同时明确质量配置及其版本、参考变换版本和源标定信息，使采集结果可追溯到当时的要求与空间关系；实际接口按现有架构实现，不要求新建固定类名。

### 页面状态与返回交互

流程步骤与运行状态分开管理。页面状态至少涵盖：未开始、加载中、可操作、质量不足、需补扫、数据缺失、处理中、已完成、已过期、失败。禁止用空白视窗代表业务状态；阻塞状态必须显示原因、影响和下一步操作。处理中说明正在处理什么，并在实现允许时提供取消；失败后允许重试或返回可用步骤，不假装任务已完成。

上一步保留会话、部位、数据和编辑上下文。切换记录或退出有未保存编辑的页面时，提供保存、放弃或取消离开；不得静默丢失编辑。仅导航返回不自动使数据过期；真正修改上游输入时按生命周期规则使下游结果失效。

### 区域编辑与路线语义

提供涂抹、擦除、撤销和重做；明确区分未选择、主动擦除的留空与几何缺失。擦除表示从工作区域排除，不等同于机器人碰撞避让体积。多个分离区域分别形成路线段，不用直线跨越留空、旧禁区或无效表面拼接为连续工作路线；未来转场运动单独规划和验证。

质量不足时允许保留明确标注为草稿的区域意图，不赋予其正式几何有效性。正式路线仅能基于通过质量检查的目标表面及必要邻域；缺失影响目标范围或必要邻域时，阻塞相应路线生成并提示补扫，不能静默排除问题区域后宣称原目标已完成。

路线预览显示覆盖、留空、缺失和路线顺序；不足以验证覆盖时显示未知，不把视觉上有线条当作覆盖合格。

### 治疗头参数语义

外壳尺寸用于未来碰撞、边缘和机械避让；有效作用宽度用于表面覆盖和行距，两者不得混用。行距可按 `有效作用宽度 × (1 - 重叠率)` 计算，输入需有来源、单位和有效范围；有效作用宽度应大于零，重叠率应满足 `0 ≤ 重叠率 < 1`。该公式只代表表面覆盖规划，不代表焦域深度、剂量或机械臂可执行性；不能单凭公式推断曲面覆盖已合格。

## 定位与几何约束

区分三个层次：人体检测、解剖部位候选、实际工作区域的空间定位。姿态关键点只辅助选部位，不能直接作为治疗边界或工具目标。

空间定位链应可追溯：有效图像像素与深度 → 标定后的相机坐标 C → 该帧位姿对应的固定参考坐标 W0。W0 可由初始采集位姿建立；相机移动后不随之重置。明确变换方向、单位、坐标轴和有效性。姿态模型推断的髋部中心坐标不能直接当作相机或机器人坐标。

- 手持多视角扫描依赖可靠跟踪和配准。评估运动限制时，区分相邻帧运动、相对初始位置运动、累计路程和采集视野；不要仅放宽阈值就宣称支持全身扫描。
- 跟踪丢失时暂停可信融合并引导重新定位；具体质量阈值需要当前数据验证，不编造通用临床精度或运动范围。
- 人体移动、呼吸和变形可能破坏刚性配准假设。翻身或显著姿态变化后，旧区域和路线应标记需重新验证，必要时重新采集。
- 衣物、床面、遮挡及未观察表面不可伪装成可靠体表。无效深度、遮挡、跟踪失败、配准失败、质量不足或未观察区域，必须标记为缺失、待检查或需补扫；不得通过通用人体模型、姿态模型或无依据插值伪造成可靠患者几何。显示覆盖缺口，规划不得无提示地跨越无效表面。
- 区域与路线至少关联病例或采集标识、体位、参考坐标、源模型版本及质量状态；避免跨会话静默复用。
- 几何表面路线不等于机械臂可执行轨迹。后续需额外处理手眼标定、机器人基座变换、工具标定、姿态、可达性和接触条件。不要把表面法向直接宣称为合格工具姿态。

### 区域与路线生命周期

源模型重建、体位改变、参考坐标重新建立、标定或几何版本变化后，旧区域和旧路线不得静默继续有效：必须重新映射、重新验证或标记已过期。工作区域修改后旧路线失效；覆盖宽度、重叠率等规划参数改变后旧路线需重新生成或验证。恢复有效必须有对应数据和验证依据，不能只靠点选“确认”覆盖几何失效。

记录会话/病例关联、部位、患者左右、体位、采集标识与模式、参考坐标、标定版本、源模型版本、Scan ROI 版本、工作区域版本、规划参数、质量状态和时间。区分当前有效、待复核、需重扫和已失效；旧结果保留用于追溯，不作为当前有效路线。

患者移动不等于 W0 必须重建。优先重新定位患者、验证配准或重扫局部；只有参考机制本身失效时才重新建立 W0，并按上述规则使依赖它的数据失效。轻微变化能否继续使用也必须有当前项目的质量验证依据，不能只凭肉眼或通用阈值判断。

未来机器人执行前，需再次验证患者当前空间状态与保存路线所依赖的参考坐标、标定和源模型一致；保存时有效不代表执行时仍有效。具体方法由机器人集成与风险分析确定，本 Skill 不据此声明执行能力已经实现。

如未来引入患者坐标 P 或机器人基座坐标 B，必须另行定义原点、轴向、变换方向和有效期；不能替换现有 W0 定义，也不能假定患者坐标已经实现。

## 视图与历史回放

明确区分实时点云、初始点云、累计点云和最终模型：实时点云通常属于当前相机坐标，累计点云来自多帧统一坐标下的融合，最终模型属于重建输出。实际语义应从实现和产物核实。

历史打开应恢复选中记录的数据与上下文，包括会话、部位、体位、采集模式、Scan ROI、标定与参考坐标、模型/区域/路线版本和质量状态；成功后关闭选择弹窗。旧记录缺少字段时明确标为未知，不依据当前设备状态补造历史值。返回上一步应保持当前历史记录和可查看数据，不落入无数据的新采集状态。历史回放与实时设备状态分开，不能混入当前相机画面并误称为历史数据。

历史文件缺失时明确指出缺失的是哪类数据，并提供可行操作。如果从原始数据重建派生点云，应说明来源并保持原始文件不变。异步加载必须避免旧任务结果覆盖新选中的记录。

## 技术选择与实施验证
