# 三维采集与轨迹规划工作台 · PySide6 原型

本目录是独立桌面产品原型，不导入 `femto/`，不连接相机或机械臂。默认启动 **Mock 交互演示**；只有显式传入 `--replay` 才尝试只读加载历史项目。

## 启动本轮原型

在仓库根目录运行：

```powershell
python -m pip install -r prototype/requirements.txt
python prototype/main.py
```

Windows 上也可以双击本目录的 `start_prototype.cmd`。

需要 Python 3.10 或更新版本及 PySide6。最低窗口尺寸为 **1280 × 760**，建议 **1600 × 900** 或更高。

`start_femto_app.cmd` 是现有业务程序的入口，**查看本轮 PySide6 原型请运行 `prototype/main.py`**。两者的界面和启动方式不同。

### 只读查看已有项目

```powershell
python prototype/main.py --replay
```

该选项尝试加载仓库内已保存的 RGB、深度、点云/网格、选区和轨迹，并保留原有校验提示与缺口。源文件不写回，不能在回放中重新采集、编辑标记或生成规划；未能载入可用项目时使用 Mock 演示。

### 可选单文件版本

模块是可编辑源码，单文件版本由构建脚本生成。更新模块后先重新生成：

```powershell
python prototype/build_standalone.py
python prototype/standalone.py
```

生成版本使用相同的默认 Mock / 显式 `--replay` 启动方式。

## 演示路径

1. 默认进入等待状态。设备栏显示未连接/未获取；中央显示取景框、空间网格和连接提示，不显示虚构实时遥测。
2. 点击“建立参考位置并开始采集”进入模拟采集；至少 3 个模拟视角后，点击“完成采集并检查质量”。
3. 在区域标记页画规划区与禁入区，点击“确认标记并检查三维几何”。
4. 核对路线，按需修改直接行距或有效作用宽度与重叠率；非法参数和路线断开会阻止继续。
5. 进入“规划确认”，核对当前参数和检查结果，保存规划方案（预览）。记录写入 `prototype/demo_records/`。

左侧显示六个里程碑：建立参考位置、移动补采、检查模型、区域标记、轨迹规划、规划确认。前三项属于同一个采集状态页，后面三项分别对应原来的标记、规划、确认页；沿用原有四阶段状态机，不增加后台业务步骤。

顶部研发场景菜单可切换正常流程、数据缺失需补采、三维几何缺失、禁区干涉/轨迹断开、参数超限。切换会重置 Mock 任务。补采流程保留已画区域和规划参数；“重新采集”是清除草稿的操作，会先确认。

## 固定视觉规范

颜色、尺寸和字号定义在 `styles/tokens.py`；Qt 控件样式在 `styles/medical.qss`，两者保持同步。采用深蓝黑分层、4–6 px 圆角、单一蓝色主按钮和纵向流程轴，避免大面积纯黑、霓虹效果和大圆角卡片。

- 主背景 `#08131F`，左右面板 `#0D1B29`，视口 `#06101A`。
- 主按钮 `#087DDE`，正常/完成 `#22D3A6`，注意 `#F2B84B`，错误 `#F06464`，待处理 `#F29B45`。
- 普通按钮/视图切换高 42 px，视口工具 40 × 40 px，步骤高 80 px，状态项高 36 px，主按钮 290 × 52 px。

详细色表、状态语义和页面分工见 [DESIGN.md](DESIGN.md)。

## 数据与范围

Mock 模式中的 Qt QPainter 躯干、点云、缺失区和扫描路线均为交互示意，**不是真实患者解剖数据**。回放模式显示已有项目数据，同时明确相机未连接。任何模式都不提供治疗执行，不将示意覆盖、位置或法线解释为临床验证结果。
